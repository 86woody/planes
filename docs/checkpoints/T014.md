# T014 checkpoint: paths and config store

## What works
- `resolvePaths` in `packages/daemon/src/paths.ts`: pure, `path.win32` for win32 and
  `path.posix` otherwise. MC_HOME wins on every platform; then APPDATA/LOCALAPPDATA
  (win32), `~/Library/Application Support` (darwin), XDG (linux).
- `fixtures/paths.json` has 9 cases (MC_HOME on linux/win32/darwin, win32 with and
  without APPDATA, darwin, linux with no XDG, both XDG vars, and one XDG var).
- `loadConfig` in `packages/daemon/src/config.ts`: missing file gives defaults; parse and
  schema errors give `config invalid: <instancePath> <message>`; `MC_PORT` overrides port
  after validation (so 0 works); `fs.watch` on configDir, 300 ms debounce, listeners,
  keep-old-config with `error()` on a bad edit, `close()` stops the watcher.
- Acceptance: `pnpm task:check T014` prints `TASK T014 PASS 10/10`, exit 0.
  `pnpm -w run typecheck` and `pnpm -w run lint` exit 0.

## What does not work / not done
- Hot-reload tests use real timers and poll (fs.watch is real I/O). They take about
  2.4 s in total. The task allowed this, but it is not the fake-timer approach the
  AGENTS.md test rules prefer.
- The debounce and the fs.watch callback were not tested against a real port change
  log line; the caller logs that warning (per the task), so the store logs nothing.

## Decisions the contract did not spell out
- Win32 without APPDATA/LOCALAPPDATA falls back to `<home>\AppData\Roaming` and
  `<home>\AppData\Local`. Case 5 of the fixture covers it.
- Parse errors use instancePath `/`: `config invalid: / invalid JSON: <msg>`.
- Invalid `MC_PORT` (not an integer 0-65535) is a load error:
  `config invalid: MC_PORT must be an integer 0-65535`. The task did not say; this is
  the safer choice to a silent ignore.
- Read errors other than ENOENT on the config file are reported as
  `config invalid: / cannot read: <msg>`.
- On reload, the new config always carries the port the store started with, so the
  port-change case needs no separate branch.
- `watcher.on("error")` is a no-op so an fs.watch failure cannot crash the daemon; the
  last good config stays in force.

## Surprises
- `validateConfig` already returns a structuredClone with defaults applied, so
  `loadConfig` can mutate the result (port override) without touching the input.
- Ajv errors come back as strings `"<instancePath> <message>"`, so the prefix
  `config invalid: ` is added in one place.
