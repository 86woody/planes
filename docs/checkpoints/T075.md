# T075 checkpoint: Copilot fixes from the real run (T074)

## What works

- `mc uninstall copilot` leaves the hooks directory as it found it. `mc install copilot` records in the manifest
  (`copilot-cli`) the `mission-control.json.mc-backup-*` files it created (`backups`) and whether it created the
  hooks directory (`createdHooksDir`). Uninstall deletes only recorded names matching
  `mission-control.json.mc-backup-<14 digits>[-n]`, and removes the hooks directory only when the installer created
  it and it is now empty. A user's own backup or file in the same directory is never deleted.
- Root cause of the leftover: uninstall rewrote the file through `writeWithBackup`, which made a new unrecorded
  backup. Uninstall now writes atomically (`writeAtomic`); the install-time backup keeps the user's original.
- SessionEnd reasons map onto the frozen `endReason` enum in the reducer (`COPILOT_END_REASONS`, copilot-cli only):
  `user_exit` -> `prompt_input_exit`; `complete`, `error`, `abort`, `timeout` and unknown -> `other`. The raw reason
  stays in `lastEvent.summary`. Recorded in ingest.md 6.3 and D-36.
- `process.alive = false` on SessionEnd for every adapter (D-38, orchestrator decision on the CR). SM-20 in
  attention.md amended; reducer implements it. Asserted in the existing SM-20 test (attention.test.ts) and in CP-08
  (copilot.test.ts).
- Tests: CP-08 (reason mapping and alive), CP-12 (our backup deleted, user's backup and file kept), CP-13 (hooks dir
  removed when we created it), CP-13 (a hooks dir we did not create stays, even empty). No new test IDs.
- Suites: `pnpm vitest run` (full): 42 files passed, 3 skipped; core and daemon projects 15/15 files, 160 tests.
  Typecheck and lint exit 0.

## What does not, and why

- SM-25 does not revive a session that ended by SessionEnd. SM-25 applies only when `endReason` is `process_exit`
  or `lost`. A session ended by SessionEnd stays ended under SM-26 when later events arrive, with `alive` false. That
  matches the contract as written. D-38 says events "revive" the session; that holds only for process_exit or lost.
  Flagged for the orchestrator; not changed here.
- `complete` maps to `other`, not a dedicated value. The enum has no `complete`; a dedicated value means changing the
  frozen `session.schema.json`. Recorded as the closest value.
