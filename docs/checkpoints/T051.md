# T051 checkpoint: installers

Status: PASS. `pnpm task:check T051` = TASK T051 PASS 16/16. Typecheck and lint green.

## What works

- `commands/install.ts` and `commands/uninstall.ts`: `mc install <target>` with `--dry-run` (claude-code only), `--direct` (uri-handler), `--pwsh|--bash|--zsh` (shell); `mc uninstall <target>` reverses from the manifest.
- `installers/json-edit.ts`: JSON read (invalid JSON leaves the file untouched), atomic write, backup `<file>.mc-backup-<yyyyMMddHHmmss>` before the first write per run, line diff for dry-run.
- `installers/manifest.ts`: config.md directory rules; all external inputs injectable; `realRun` wraps .cmd shims in cmd.exe on Windows.
- `installers/claude.ts`: claude-hooks.md 1-3 (nine events, exec form, async/timeout table, idempotent, backup, dry-run diff, manifest). Uninstall removes only the recorded hook objects and the groups and arrays it emptied.
- `installers/uri.ts`: Windows shim or direct mode through `@mc/platform` (D-30); Linux desktop file and xdg-mime; macOS prints "not needed on macOS".
- `installers/codex.ts`: notify goes before the first top-level table header, found by a light TOML scan (bracket and brace depth, basic, literal and multi-line strings). An existing notify exits 1 and changes nothing.
- `installers/shell.ts` (D-30): writes the T053 snippet with `__MC_STATE_DIR__` replaced by stateDir to `<stateDir>/shell/mc.<ext>`; the marked block sources that copy; writes shell.env; sets adapters.shell.enabled and records the previous value.
- `installers/autostart.ts`: Windows Run key plus autostart.vbs; macOS LaunchAgent via `launchctl bootstrap gui/<uid>`; Linux systemd user unit, or an XDG autostart desktop file without systemd.
- `installers/vscode.ts` (D-30): build, `vsce package` to `<stateDir>/mission-control-bridge.vsix`, then `--install-extension` for each of code, code-insiders, cursor on PATH. Each editor is recorded in the manifest as soon as its install succeeds. Extension id `woody.vscode-bridge`.
- Tests: `test/install-claude.test.ts` (IC-01..08) and `test/install-other.test.ts` (IX-01..08) with `test/fixtures/install-sandbox.ts`. Every test uses temp HOME, MC_HOME, CLAUDE_CONFIG_DIR and a recording runner.

## Review fixes (this pass)

1. codex: a `[` on a continuation line of a multi-line array was taken for a table header and the notify line was spliced into the array. The insert point now comes from `firstTableIndex`. Regression: IX-01.
2. shell uninstall: a malformed config.json threw before the manifest entry was removed, so every rerun threw. Each cleanup step is now tolerant: a problem is a warning, and the manifest entry is always removed. Regression: IX-04.
3. vscode: the manifest said `installedWith: []` until the end, so a cursor failure after a code success left code unrecorded. Each editor is now persisted on success, and a failure returns 1 only after the successes are saved. Regression: IX-08.
4. uri-handler: the manifest entry was written before the platform calls, so a failure left a stale entry that stopped `install claude-code` from retrying. The entry is now written only after the platform calls succeed, and a failed xdg-mime removes the half-written desktop file. In `install claude-code`, a failed uri step is a warning: hooks stay, exit 0, and the message says how to retry. claude-hooks.md and the task file set no failure rule for the uri step, so this follows the orchestrator's instruction. Regressions: IC-03 and IX-06.

## What does not work or is unverified

- Nothing ran against the real machine, by design. The registry, pnpm/vsce and editor CLIs are exercised only through the recording runner.
- A Windows registry write that fails partway can leave keys with no manifest entry, because the entry is now written after success. A retry overwrites them. `mc uninstall uri-handler` will not remove them if no retry happens. Accepted per the review, flagged here.
- `--dry-run` exists for claude-code only; other targets exit 2 on it.
- The shell copy is a snapshot until `mc install shell` runs again.
- zsh is not exercised by any test (the same gap T053 recorded).
- `mc uninstall vscode` calls `--uninstall-extension woody.vscode-bridge`; no test checks it against a real editor.
