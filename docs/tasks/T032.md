# T032: UI data layer, board, poll strip, counts

Milestone M2 · Wave 1 · Depends on: M0 · Runs on: any OS

## Goal

Connect the page to the daemon: pairing, `GET /api/state`, the WebSocket with gap
detection, the restore/ack/dismiss actions, sorting, the poll strip, the counts and the
board grid.

## Codes against

`docs/contracts/api.md` sections 2, 3, 5 (normative), `api.schema.json`,
`docs/DESIGN.md` section 2 (poll strip, counts, grid, sort order, SPLASHDOWN), D-05,
`internal.md` section 3 (`useBoard`, `api`, `sort.ts`, `Board`, `PollStrip`, `Counts`),
`session.schema.json` (the `Session` shape; the acknowledgement flag is
`attention.acknowledged`, the attention start is `attention.since`) (D-24).

## Steps

1. `api.ts`: `fetch` with `credentials: "same-origin"`. CSRF: kept in memory and in
   `sessionStorage["mc.csrf"]` (survives reloads within the tab); sent as `X-MC-CSRF` on
   POST/DELETE. When `state()` succeeds and no CSRF is known (new tab, browser restart),
   fetch it with `GET /api/csrf`; on a `403` from a POST/DELETE, refetch it once and
   retry the request once. `state()` returns `"unpaired"` on 401. `pair(code)` POSTs `/api/pair`,
   stores the CSRF. `restore` returns `RestoreResponse.result` or null on 429/404.
2. Pairing (D-05: no code ever appears in a URL): on first load call `api.state()`;
   `"unpaired"` sets `needsPairing: true` (the banner of T030 shows the code form).
   `actions.pair(code)` calls `api.pair(code)`; on true, clear `needsPairing`, load state
   and open the WebSocket; return the boolean. The store never reads `location.hash`.
3. WebSocket: `new WebSocket(\`ws://${location.host}/api/ws\`)`; on `hello` replace state
   and remember `seq`; every later message must have `seq === last + 1`, else close and
   reconnect; reconnect every 2000 ms while closed; `link` = connecting/open/closed.
   `session.upsert` replaces or inserts by id; `session.remove` deletes;
   `daemon.update` replaces daemon and capabilities; `notify`: if
   `Notification.permission === "granted"` and `document.visibilityState === "hidden"`,
   show a Web Notification whose `onclick` calls `actions.restore(sessionId)` and
   `window.focus()`; `highlight` sets `board.highlight` for 3000 ms. Send `{"type":"ping"}`
   every 20 s.
4. Actions: `restore(id)` sets `pending[id]`, awaits `api.restore`, stores
   `results[id] = {result, until: Date.now() + 5000}`, clears pending; expired results
   are dropped on the next tick. `ack`, `dismiss` call the API (state updates arrive over
   WS). `copyCwd(id)` writes the session's cwd with `navigator.clipboard.writeText` and
   stores a synthetic result `{status: "partial", code: "focused_window_only", detail: "FOCUS MANUALLY", at}`
   which the card shows as `FOCUS MANUALLY` (T031 renders `detail` when it equals
   `FOCUS MANUALLY`).
5. `sort.ts`: DESIGN.md 2 sort order and groups exactly; `pollItems`: active and
   unacknowledged attention, ordered permission/error, input, done, then `since`
   ascending; `counts`: GO/HOLD/NO-GO/LOS definitions of DESIGN.md 2.
6. Components: `PollStrip` (testid `poll`, chips `poll-chip` with `data-session`,
   click -> `actions.restore`), `Counts` (testid `counts`, children `count-go`,
   `count-hold`, `count-nogo`, `count-los`), `Board` (testid `board`; grid of `Card`;
   when no sessions at all, `Empty`; SPLASHDOWN section testid `splashdown`, collapsed by
   default with a toggle button `splashdown-toggle`).
7. Keyboard shortcut `R` (DESIGN.md 9): in `store.ts`, a `keydown` listener on
   `document` restoring the first poll item when `event.target === document.body`.
8. Tests (jsdom; a fake `WebSocket` class and `fetch` mock), titles exactly:
   - `US-01 actions.pair posts the code, stores the csrf, clears needsPairing and loads state`
   - `US-02 401 on state sets needsPairing`
   - `US-03 hello replaces state; upsert and remove apply by id`
   - `US-04 a seq gap closes the socket and reconnects`
   - `US-05 link goes closed and retries every 2 s` (fake timers)
   - `US-06 restore sets pending, stores the result for 5 s, then drops it`
   - `US-07 sortSessions orders permission, error, input, done, working, starting, idle and puts ended and lost in splashdown`
   - `US-08 pollItems excludes acknowledged attention and orders by reason then since`
   - `US-09 counts groups states into GO HOLD NO-GO LOS`
   - `US-10 a notify message shows a Web Notification only when the page is hidden and permission is granted`
   - `US-11 with a valid cookie but no stored csrf, the store fetches /api/csrf and a restore succeeds; a 403 triggers one refetch and one retry`
