## What does not
- Nothing known to fail. Not checked: macOS and Linux hosts (the darwin case is covered only by IN-07 through the sandbox).

## Surprises
- readline on a stream that never ends waits forever, so the prompt tests always end their streams. IN-03 keeps a bare never-ended PassThrough on purpose: it proves init never reads stdin when `--agents` is given.
- In non-terminal mode the `> ` prompt and the `not a choice: <input>` text share a line (no echo). IN-09 counts with `split("not a choice:")`.
- Task file says a prompt that never becomes valid (EOF or three bad answers) prints the same "(no terminal to ask on)" usage line as the no-TTY case. Followed as written; the wording is misleading there. Possible follow-up: a separate message. Not changed, because the spec says "same usage line".
- The vscode skipped line pads to 12 columns, so it has 7 spaces before `skipped`, not 8 as the example in the task file shows. The test uses `padEnd(12)`.
- `installClaude` runs its own uri-handler step, so on Windows and Linux (no MC_HOME) init's explicit `uri-handler` line reports `repaired` after claude-code ran it. Left as the task file says.
