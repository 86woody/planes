# T054: System e2e through real processes

Milestone M4 · Wave 6 · Depends on: T050-T053 · Runs on: any OS

## Goal

One end-to-end path through every real process the product has: `mc start`, the
installer against a temp Claude settings file, real `mc-hook` processes fed raw Claude
Code hook JSON exactly as Claude Code would, the browser page, `mc restore` as the
notification click would run it, and `mc stop`.

## Codes against

`docs/contracts/claude-hooks.md` (the installed command is what the test executes),
`ingest.md`, `api.md`, `ARCHITECTURE.md` section 3 (the sequence this test walks).
Added by D-32: `platform-adapter.md` section 5 (`FakeCall`, served by
`GET /api/test/fake-platform`); `config.md` section 1 (paths under `MC_HOME`);
`DESIGN.md` sections 2-3 and 7 for selectors (`fd-bar`, `poll`, `counts`, `card` with
`data-state`, `restore`, `ack`, `dismiss`, `result`, `pair-input`, `pair-submit`, `banner`).
`mc status` prints a header line `daemon pid=<pid> port=<port> sessions=<n>` then one line
per session such as `MC-07  HOLD        schmux      VS CODE      2m`, and exits 1 when the
daemon is not running; `mc start` exits 0 once healthz answers. The installed hook is
exec form (claude-hooks.md 1): run `command` with `args` as an argv array, do not join it
into a shell string. Test titles must start with the ID exactly (`SYS-01 ...`), as in
every other spec; `task:check` greps titles by ID. Per D-29, sessions need a live agent
pid (the real hook's parent) or no agent.

`e2e/system.spec.ts`, `e2e/system-support/**`, `docs/checkpoints/T054.md`.

## Steps

1. Environment: temp `MC_HOME`, temp `CLAUDE_CONFIG_DIR`, `MC_PLATFORM=fake`, `MC_TEST=1`.
   Do not set `MC_PORT` (the installed hook commands must find the port the normal way):
   find a free port by listening on port 0 and closing, and write it to
   `<MC_HOME>/config/config.json` as `{"port": <n>}`.
2. `node packages/cli/dist/mc.js install claude-code` into the temp settings.
3. Read the installed `command` strings from the temp settings; for each event in the
   scenario, run that exact command through the shell Claude Code would use
   (`powershell -NoProfile -Command <command>` on Windows, `sh -c <command>` elsewhere)
   with the raw fixture on stdin, so the test proves the installed string works.
4. Scenario and titles exactly:
   - `SYS-01 mc start then mc status reports the daemon`
   - `SYS-02 installed SessionStart command creates a card visible in the page`
   - `SYS-03 installed PermissionRequest command turns the card GO/NO-GO and records a fake notify`
   - `SYS-04 mc restore mission-control://restore/<id> --from-notification records a fake focus and acknowledges`
   - `SYS-05 installed SessionEnd command moves the card to SPLASHDOWN`
   - `SYS-06 mc uninstall claude-code restores the settings file byte for byte, and mc stop stops the daemon`
