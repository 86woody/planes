# T020 checkpoint: mc-hook

## Status


The console lookup is live on Windows (D-26).

## What works

- `paths.ts`: config.md section 1 rules; HK-11 passes against
  `packages/daemon/test/fixtures/paths.json` (all 8 cases).
- `main.ts`: 1500 ms unref'd deadline as the first statement, every path ends in
  `process.exit(0)`, stdout is never written, unknown adapters exit 0.
- `claude.ts`: stdin read capped at 1 MiB, payload allowlist per ingest.md 4,
  truncation by code points, `capturePromptText` from config.json (missing or invalid = true).
- `send.ts`: port from daemon.json, config.json, then 47800; token from `stateDir/token`
  (absent means spool without POST); 202 done, 400 logged and dropped, 401/403/5xx/network
  or timeout spooled; spool capped at 1000 files by name; `hook-errors.log` one line per error.
- `codex.ts` and `shell.ts`: ingest.md 6.1 and 6.2.
- `envelope.ts`: ancestry via `@mc/platform` root, agent rule table, tty via `ttyOf` on POSIX,
  env allowlist with `SSH_CONNECTION` -> `present`, `sentAt = Math.floor(performance.timeOrigin)`.
- Tests: `test/hook.test.ts` (HK-01..HK-11), `test/codex.test.ts` (CX-01..CX-03),
  `test/support/harness.ts` (spawns the built `dist/mc-hook.js` with a temp `MC_HOME`,
  fake daemon on port 0). Tests never touch real config or state.

## What does not work

- Nothing blocking. Windows console fields were verified on dev-pc (D-26 landed): a manual
  run of the built hook spooled `origin.console` = consoleHwnd `0x0000000000040AC4`, ownerHwnd
  `0x0000000000010C68`. The run did not record which path produced the handle
  (GetConsoleWindow directly or the AttachConsole fallback).
- HK-01 asserts console shape on win32 (hex-or-null, owner null when console null), not that the handle is non-null.

## D-26

koffi is declared in packages/hook/package.json (D-26, 85ad4d2). The CR from the first stop is closed.
The import is now a literal `import("koffi")` in envelope.ts; it still never throws (failure -> null fields).

## Surprises

- `ancestry` in `@mc/platform` returns `ProcessInfo[]`, but the generated envelope type types
  `origin.ancestry` as a 0..16 tuple union, so one cast is needed in `envelope.ts`.
- ingest.md 4 says an over-1 MiB stdin is sent with payload `{}`, but a `{}` payload has no
  session id. The hook takes `session_id` and `hook_event_name` from the head of the input by regex.
- The raw fixture set has no `cc-stop` or `cc-session-end` input; HK-09 builds its Stop input inline.
