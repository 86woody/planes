# T060: Release: user guide, validation templates, final audit

Milestone M5 · Wave 6 · Depends on: T050-T053 · Runs on: any OS

## Goal

The user-facing guide, the manual validation templates for each OS, and the first full
`pnpm gate` run.

## Codes against

`README.md`, `docs/PRD.md` (ACs), `docs/TEST-PLAN.md` sections 2 and 6, the three
platform docs (manual rows), `docs/DESIGN.md` section 6 (fix-it texts to mirror in the
troubleshooting table).

## Files

`docs/USER-GUIDE.md`, `docs/validation/TEMPLATE-windows.md`,
`docs/validation/TEMPLATE-macos.md`, `docs/validation/TEMPLATE-linux.md`,
`docs/checkpoints/T060.md`.

## Do not touch

Every other file, including the other docs (report errors you find in them in your
checkpoint for the orchestrator).

## Steps

1. `USER-GUIDE.md`: install (`pnpm install`, `pnpm build`, `pnpm mc install claude-code`,
   `pnpm mc install vscode`, `pnpm mc start`, `pnpm mc open`), what each card state means
   (DESIGN.md 4 table in plain words), RESTORE and what each result chip means, the
   per-OS permissions (from the doctor tables), troubleshooting (every `restore.reason`
   with its fix), uninstall, and where files live (config.md 1-2).
2. Templates: one table per OS with every manual row (ID, steps, pass condition copied
   verbatim from the platform doc) and empty `Result | Note` columns; a header for date,
   machine, OS build, commit.
3. Run `pnpm gate` and paste the output into the checkpoint.

## Acceptance command

```
pnpm gate
```

## Expected output (last line)

`GATE m5 PASS <n>/<n>`. The orchestrator reviews the guide by reading it. If the gate
fails because of another task's code, record the failing stage in your checkpoint and stop.
