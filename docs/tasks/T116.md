# T116: shell integration points Copilot's OTel file exporter at one file per shell (D-56)

Milestone M5 · Wave 9a · Depends on: T053 · Runs on: any OS

## Goal

In a shell that has mission-control's shell integration, every `copilot` started there writes OTel
to `<stateDir>/otel/shell-<pid>.jsonl`, where the daemon reads it (D-56 item 6).

## Codes against

`docs/DECISIONS.md` D-56 (items 1 and 6).

## Files

`packages/cli/src/installers/shell.ts` (the `shell.env` text only),
`packages/cli/assets/shell/mc.ps1`, `packages/cli/assets/shell/mc.bash`,
`packages/cli/assets/shell/mc.zsh`, `packages/cli/test/shell-integration.test.ts` (new tests SH-06,
SH-07 only), `docs/checkpoints/T116.md`.

## Steps

1. The installer writes a third line to `shell.env`: `MC_OTEL_DIR=<stateDir>/otel` (forward slashes,
   like the other two).
2. Each snippet, after it has read `shell.env` and before it reports `ShellStart`: when `MC_OTEL_DIR`
   is set in the file AND `COPILOT_OTEL_FILE_EXPORTER_PATH` is not already set in the environment,
   create the folder if missing and set (export) `COPILOT_OTEL_FILE_EXPORTER_PATH=<MC_OTEL_DIR>/shell-<pid>.jsonl`
   for this shell only (`$PID` in pwsh, `$$` in bash and zsh). Set nothing else: no content-capture
   variable, no `COPILOT_OTEL_ENABLED`, no endpoint.
3. A `shell.env` without `MC_OTEL_DIR` (older installs) changes nothing. A user-set
   `COPILOT_OTEL_FILE_EXPORTER_PATH` is never overwritten.

## Tests

- `SH-06` bash, zsh and pwsh (each skipped when the shell is not installed, as SH-01..SH-05 do): with
  `MC_OTEL_DIR` in the test `shell.env`, a child command `env`/`Get-ChildItem env:` run inside the
  sourced shell shows `COPILOT_OTEL_FILE_EXPORTER_PATH` ending in `shell-<that shell's pid>.jsonl`
  under the test dir, and the folder exists.
- `SH-07` with `COPILOT_OTEL_FILE_EXPORTER_PATH` already set, it is unchanged; without `MC_OTEL_DIR`,
  it stays unset.
