# Checkpoint T117: Copilot traces and spans per session (D-57)

Branch `task/T117-traces`, builder run on dev-pc.

## What works

- `packages/daemon/src/traces.ts`: `createTraceStore` groups the Copilot OTel span records routed by
  `telemetry.ts` into `TraceRun` values. Copies only the attributes in the task's copy list. Dedupes by
  spanId, caps at 500 spans per run (`droppedSpans` counts the rest), keeps the newest 50 runs per session,
  debounces writes 2 s, and writes `<stateDir>/traces/<encoded id>.json` atomically (tmp + rename).
  Writes are serialized, so an explicit flush waits for a debounced write in flight. Files load lazily; a
  file that fails `validateTracesResponse` is ignored with a warning. Removing a session deletes its file
  and its in-memory runs.
- `telemetry.ts`: a routed span record is also handed to `traces.addSpan`. `traces` is an optional dependency,
  so the existing D-56 telemetry tests needed no change.
- `GET /api/sessions/:id/traces` (realm browser-or-bearer): 404 for an unknown id, else `200 {sessionId, runs}`.
- `internal.ts` (`DaemonDeps.traces`), `main.ts` (creates the store, passes it to telemetry and deps, and
  calls `traces.flush()` in the stop path before `persistence.flush()`), `test/support/deps.ts` (no-op
  `traces` stub).
- Tests: `packages/daemon/test/traces.test.ts`, TT-01..TT-06, all passing. Temp `MC_HOME` only; no fixed port;
  the debounce is checked with fake timers. TT-04 asserts the secret is absent from the stored file and from
  the route body. TT-05 asserts the same on the route.

## What does not

- The `kind` is read from the first word of the span name (`invoke_agent`, `chat`, `execute_tool`), not from
  `gen_ai.operation.name`. The task's wording names the span, so I followed it. Compaction is detected from
  `github.copilot.request.type`, the same key core's fold reads. These two keys are read for classification
  only and never stored.
- Span records without `traceId`, `spanId`, or a readable `startTime` are dropped. Events without a readable
  time are dropped.

## Surprises

- Core's `addOtelRecord` treats a span as an agent root by `rec.name === "invoke_agent"`. The store uses the
  first word of the name instead, so `invoke_agent <agent>` also counts as a root.
- The `otlp` and `readAttrs` helpers are copied from `packages/core/src/telemetry.ts` (not exported there),
  as the task asked.
- `api.schema.json` says runs are "newest last", so `runs()` returns oldest first, the newest 50.
