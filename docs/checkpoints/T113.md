# T113 checkpoint: the daemon reads Copilot session logs and OTel files into Session.telemetry (D-56)

Branch `task/T113-daemon-telemetry`, host dev-pc. No push, merge or rebase.

## What works

- `SessionService.setTelemetry(id, t)` (sessions.ts): no-op for an unknown id; stores `{...session, telemetry}`; emits an upsert only when the value changed (the file's `same` deep compare); `save()`.
- `createTelemetry(deps, {copilotHome, tickMs = 2000})` (telemetry.ts):
  - `events.jsonl` per live or recently ended (under 60 s) `copilot-cli` session, read from a byte offset, at most 8 MiB per tick, partial last line held, `\r` stripped, shrunk file restarts the fold at offset 0, missing file is silent.
  - `<stateDir>/otel/*.jsonl`: span records routed to `copilot-cli:<gen_ai.conversation.id>` when that session exists (object and OTLP list attribute forms).
  - `setTelemetry` for each session that has data; state forgotten for removed sessions; OTel files older than 7 days and fully read are deleted; read errors logged once per file via `log.warn`.
  - `start()` and `tickNow()` use `setInterval(...).unref()`. `stop()` clears the timer.
- `main.ts`: `copilotHome = env.COPILOT_HOME ?? os.homedir()/.copilot`; the service is created after the session service, started after notifier and liveness start unless `adapters["copilot-cli"].enabled === false`, and stopped in shutdown before the final flush.
- Tests `TD-01`..`TD-05` (packages/daemon/test/telemetry.test.ts) pass with temp `MC_HOME` and `COPILOT_HOME`, `tickNow()` only, no sleeps. TD-02 checks a SHA-256 over the whole temp `COPILOT_HOME` before and after ticks.

## What does not

- Nothing in the spec left undone.
- The OTel deletion path is written but not covered by a test; no TD-id in the registry asks for it.

## Deviations and notes

- `packages/daemon/src/internal.ts` had no `setTelemetry` line in the source, only in the contract doc. Added the line (plus the `Telemetry` type import) to match `docs/contracts/internal.md` section 2. Without it, typecheck fails in sessions.ts and telemetry.ts.
- The spec says `save()` after every `setTelemetry`, like `setGit`. Because the tick calls `setTelemetry` for every session with data, `save()` is scheduled every tick even when nothing changed. The persistence layer debounces it (500 ms), but sessions.json will be rewritten about every 2 s while a Copilot session is live. Followed the spec as written; if that write churn matters, a follow-up can save only on change.
- A shrunk events file resets the fold to the new file's contents, so OTel-fed data for that session is dropped at the same moment. Not a case the spec covers.
- Partial lines are held as bytes, not strings, so a multi-byte UTF-8 character split by the 8 MiB read boundary cannot corrupt a line.

## Surprises

- `setTelemetry` was declared in `docs/contracts/internal.md` but absent from the daemon's `src/internal.ts`. The typecheck error pointed at it immediately.
- Core's fold (T112) already accepts the `session.usage_record` shape used by the fixtures, so the tests needed no fold changes.
