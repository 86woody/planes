# T093: Bundle dbus-next so the tarball installs without building usocket

Milestone M5 · Wave 8g · Depends on: T087 · Runs on: any OS

## Goal

`npm i -g ./mission-control-desktop-<v>.tgz` finishes without running any `node-gyp`
build. Today the generated `package.json` lists `dbus-next`. npm installs its optional
`usocket`, whose install script runs `node-gyp rebuild` and hung for more than 4 minutes in
T089's smoke run. After this task, `dbus-next` is inlined into the bundles, and `usocket`
stays external and is not a dependency.

## Codes against

`docs/DECISIONS.md` D-47 and D-39, `docs/PACKAGING.md` 2.

## Files

`scripts/package.mjs`, `packaging-test/package.test.mjs`, `docs/checkpoints/T093.md`.

## Do not touch

Every other file. Do not change any other test's title or ID.

## Steps

1. In `scripts/package.mjs`, change how the externals are collected so that `dbus-next` is
   left out of the externals map. It is then bundled by esbuild, and the generated
   `package.json` `dependencies` no longer list it. Add `usocket` and `x11` to esbuild's
   `external` array only: not to the externals map, and not to `dependencies`. Leave every other
   external unchanged.
2. Run `pnpm -r build && pnpm package` and confirm it still prints
   `PACKAGE mission-control-desktop-<v>.tgz <bytes>`.
3. In `packaging-test/package.test.mjs`, add one test titled exactly
   `PK-09 dbus-next is bundled and usocket is neither bundled nor a dependency`. It reads
   the generated `release/pkg/package.json` and expects that `dependencies` has no
   `dbus-next` key and no `usocket` key. It reads `release/pkg/dist/daemon.js` and expects
   the text `require("usocket")` (or `require('usocket')`) to be present, because the call
   stays external. It also expects no `node_modules/usocket` path in the tarball listing.
   Use the same tarball-listing helper the file already uses.
4. Write `docs/checkpoints/T093.md`.

```
pnpm -r build && pnpm package && pnpm -w run lint && pnpm task:check T093 && pnpm task:check T087
```
