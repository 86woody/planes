# T116 checkpoint

## What works
- The installer writes a third `shell.env` line, `MC_OTEL_DIR=<stateDir>/otel` (forward slashes), in `packages/cli/src/installers/shell.ts`.
- Each snippet (`mc.ps1`, `mc.bash`, `mc.zsh`) reads `MC_OTEL_DIR`. When it is set and `COPILOT_OTEL_FILE_EXPORTER_PATH` is not already set, it creates the folder and exports `COPILOT_OTEL_FILE_EXPORTER_PATH=<MC_OTEL_DIR>/shell-<pid>.jsonl` (`$PID` in pwsh, `$$` in bash and zsh). Nothing else is set.
- A preset exporter path is kept. A `shell.env` without `MC_OTEL_DIR` changes nothing.
- Tests SH-06 (per-shell pid path and folder creation) and SH-07 (preset kept, unset without `MC_OTEL_DIR`) added to `packages/cli/test/shell-integration.test.ts`. Both use temp dirs only; no real profile or installer run.
- Acceptance `pnpm -r build && pnpm task:check T116 && pnpm task:check T053` exits 0. `pnpm -w run typecheck` and `pnpm -w run lint` exit 0.

## What does not / was not verified
- zsh is not installed on this machine (`where zsh` finds nothing), so the zsh branches of SH-06 and SH-07 were skipped by their own guards. The zsh snippet change is untested here. SH-03 also skipped zsh.
- bash was Git for Windows bash; pwsh was the WindowsApps pwsh 7.

## Surprises
- Nothing blocking. The pwsh snippet's early `return` (no hook / no env) happens after the exporter block, so the exporter is set even when the hook is missing. That matches "after it has read shell.env", but it is a choice: the exporter does not depend on the hook.
