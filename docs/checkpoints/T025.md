# T025 checkpoint: Liveness and git info

## What works
- `createLiveness` (`packages/daemon/src/liveness.ts`): interval start/stop; a pass checks each
  non-ended, non-lost session. A session with `agentPid` goes through
  `platform.processAlive(pid, origin.agent.startTime ?? null)` and gets `process_exited` when
  false. A session without a pid and idle longer than `sessions.lostAfterHours` gets
  `lost_timeout`. Each check is wrapped so one rejection does not stop the pass. Overlapping
  `checkNow()` calls share the running pass.
- `readGit` (`packages/daemon/src/git.ts`): one `rev-parse --show-toplevel --abbrev-ref HEAD`
  call with a 2 s timeout. Exit 128 triggers the retry (`rev-parse --show-toplevel` plus
  `symbolic-ref --short HEAD`). Any other failure returns `{project: basename(cwd), branch: null}`.
  Results are cached per cwd for 30 s using `Date.now()`.
- Tests: `packages/daemon/test/liveness.test.ts` (LV-01..LV-04) and
  `packages/daemon/test/git.test.ts` (GI-01..GI-03). All 7 pass.

## Surprises
- `createLiveness` deps are `Pick<DaemonDeps, "clock" | "config" | "sessions" | "platform">`,
  which has no `log`. The step says "logged, not fatal", so the failure path uses
  `console.warn`. Lint allows it. If the orchestrator wants a structured logger, the frozen
  signature would need a `log` entry (a contract change, not made here).
- Tests use a hand-written `FakeSessions` cast to `DaemonDeps["sessions"]`. This avoids
  depending on T021 (`sessions.ts`), which is still a stub on this branch.
- GI-03 advances time by replacing `Date.now` with a spy, not with fake timers. execFile
  timeouts are internal timers and do not mix well with faked globals.
