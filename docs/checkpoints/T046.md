## What works

- `notifyArgs` is a pure builder for the eight Notify arguments (linux.md 5). Urgency byte is 0/1/2, expire is -1, actions are `default`/`restore`, and body is escaped only with body-markup.
- `createNotify` connects at creation and reports `linux_no_notification_server` through `probe()` when there is no bus or no server. `notify` then returns null.
- Tag to id replacement, `ActionInvoked` (`default`/`restore`) to `onClick(sessionId)`, `NotificationClosed` cleanup, `withdraw` via `CloseNotification`, and `dispose` disconnecting the bus.
- `getDaemonService()` requests `org.missioncontrol.Daemon` and exports `Report(s)` at `/`. Without a session bus it is a no-op.
- dbus-next is loaded only inside the real connectors, so Windows never loads it.

## Deviations and choices (review these)

- The module exports `createNotifyWithConnector` and `createDaemonService`, which take an injected connector. `createNotify` and `getDaemonService` keep their frozen signatures and call them with the real connectors. Adding exports does not change the frozen signatures.
- `notifyArgs` returns hints as plain `{signature, value}` records, not dbus-next `Variant` instances. The real connector converts them with `new Variant(...)` at send time. This keeps dbus-next out of the module's load path.
- `sound` is `urgency !== "low"`. The contract does not define how sound is chosen, so this is my assumption.
- `notify` and `withdraw` have a 1800 ms deadline (PA-07). If the server answers after that, `notify` returns null and the id is not tracked, so a later click on that toast is ignored.
- The D-Bus RequestName reply codes are literal (1 primary owner, 4 already owner) because dbus-next's `constants` export is not typed here.
- `dbus-run-session` is not available on Windows. The acceptance command was run as `pwsh -NoProfile -Command "pnpm task:check T046"`.
- The LO-05 test starts its own `org.freedesktop.Notifications` on the session bus, exports `GetCapabilities`, `Notify` and `CloseNotification`, emits `ActionInvoked(id, "default")`, and checks that `onClick` gets `sess-os-1`. Unverified until it runs on Linux.
