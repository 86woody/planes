# T115 checkpoint: `mc doctor copilot [--live]`

Branch `task/T115-doctor-copilot`, built on `integration`. Commits: `9de5932` (SDK dependency), `cf4a867` (command and check module), `e6fa7b3` (tests). No CR lines: no stop rule applied and no frozen file needed changing.

## What works

- `@github/copilot-sdk` 1.0.34 (exact) is a dependency of `@mc/cli`. `pnpm-lock.yaml` updated.
- `mc doctor copilot` runs D1-D9 and prints one `PASS|FAIL|WARN|SKIP D<n> <label>  [<detail>]` line per check, then `DOCTOR COPILOT PASS|FAIL <passed>/<run>`. Exit 1 on any FAIL, else 0.
- `mc doctor copilot --live` adds D10. Without `--live`, D10 does not appear.
- Any other argument form prints `usage: mc doctor [copilot [--live]]` to stderr and exits 2.
- The SDK is loaded only by a dynamic `import()` inside `doctor-copilot.ts`. The client is stopped in a `finally`. `gitHubToken` is never passed. No token, config value or events line is printed; bad event lines are counted, never echoed.
- `runCopilotDoctor(io, deps)` takes injectable deps, so tests use fakes.
- Tests DC-01 to DC-05 pass (5 tests). The existing `doctor.test.ts` (7 tests) still passes, which covers the no-argument `mc doctor` path.

## What does not work or is not proven

- The real SDK path (`start`, `getStatus`, `getAuthStatus`, `resumeSession` against a live runtime) has not been run. Types are checked against the real SDK, but no runtime was started, by design.
- D10 has never run. Its OTel record shape is an assumption (see below).

## Decisions and surprises

- **koffi (D2):** the CLI cannot resolve `koffi` under pnpm isolation (typecheck failed on `import("koffi")`). D2 instead resolves the `koffi` that the SDK brings (3.3.6) from the SDK's own folder. The platform's koffi 2.x is not checked by this command.
- **Runtime package (D2):** found by reading the SDK's `optionalDependencies` for `@github/copilot-sdk-<process.platform>-<process.arch>`, then checking the sibling folder exists. `linuxmusl` variants are not distinguished.
- **D8 strictness:** any unparseable line makes D8 FAIL. A torn last line in a live session would therefore FAIL. Flagged for Woody to decide whether that should be WARN.
- **D9 gating:** runs whenever the runtime started, and is not gated on sign-in. Only the session-ended check is a SKIP condition, per the task.
- **D7:** uses `listModels()` only. The `rpc.models.list` alternative was not used.
- **D10 OTel shape (unverified):** span and metric records are matched by `type === "span"` / `"metric"`. The conversation id is read from `attributes["gen_ai.conversation.id"]` or the top level. Needs a check against a real `--live` file before relying on it. Do not run `--live` in a builder.
- **`packages/cli/package.json`:** pnpm reordered the `dependencies` keys alphabetically when adding the SDK. No other change to that file.
