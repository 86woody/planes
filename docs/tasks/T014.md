# T014: Paths and config store

Milestone M1 · Wave 1 · Depends on: M0 · Runs on: any OS

## Goal

Resolve every directory and file path, load and validate `config.json` with defaults,
and hot-reload it.

## Codes against

`docs/contracts/config.md` (normative), `config.schema.json` via `validateConfig` from
`@mc/contracts`, `internal.md` sections 1-2 (`Paths`, `ConfigStore`, `resolvePaths`,
`loadConfig`).

## Files

`packages/daemon/src/paths.ts`, `packages/daemon/src/config.ts`,
`packages/daemon/test/config.test.ts`, `packages/daemon/test/fixtures/paths.json`,
`docs/checkpoints/T014.md`.

## Do not touch

Every other file. (`packages/hook/src/paths.ts` and the bridge's copy are written by
T020 and T052; your `fixtures/paths.json` is what they test against.)

## Steps

1. `resolvePaths(env, platform, home)`: the table of config.md section 1; file names of
   section 2 (`configFile = configDir/config.json`, `tokenFile = stateDir/token`, ...,
   `spoolDir = stateDir/spool`). Pure: no fs calls. Use `path.win32` for `win32` and
   `path.posix` otherwise (so tests can resolve Windows paths on Linux).
2. `fixtures/paths.json`: an array of `{env, platform, home, expected: Paths}` cases:
   MC_HOME set (each platform), Windows with APPDATA/LOCALAPPDATA, macOS, Linux with and
   without XDG vars. At least 7 cases.
3. `loadConfig(paths, env)`: missing file -> defaults; parse error or schema error ->
   `{ok: false, errors}` with lines `config invalid: <instancePath> <message>`;
   `MC_PORT` overrides `port` (integer, 0 allowed only via env). The store watches
   `configDir` with `fs.watch` (create the dir if missing), debounce 300 ms, re-validates,
   on success replaces the config and calls listeners (if `port` changed, keep the old
   port value in the new config object and log nothing: the caller logs), on failure
   keeps the old config and sets `error()`. `close()` stops the watcher.
4. Tests (use `MC_HOME` temp dirs, fake timers for the debounce where possible; for
   `fs.watch` use real timers and poll up to 2 s), titles exactly:
   - `CF-01 resolvePaths matches every case in fixtures/paths.json`
   - `CF-02 missing config file yields defaults`
   - `CF-03 invalid JSON yields ok:false with a config invalid line`
   - `CF-04 schema violation reports the instancePath`
   - `CF-05 MC_PORT=0 overrides port`
   - `CF-06 hot reload applies a valid edit and notifies listeners`
   - `CF-07 hot reload of an invalid edit keeps the old config and sets error()`
   - `CF-08 a later valid edit clears error()`
   - `CF-09 a port change on reload keeps the old port`
   - `CF-10 close() stops reloading`
