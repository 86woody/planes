# T124 checkpoint: `mc uninstall --all [--purge]`

## What works

- `mc uninstall --all` stops the daemon (`daemon: stopped` / `daemon: not running`), then runs the
  target handlers in the D-59 order: vscode, autostart, uri-handler, shell, codex, copilot, claude-code.
  Targets with a manifest entry always run, and claude-code, copilot, codex and shell always run.
  Each target prints `<target>: removed` or `<target>: failed: <message | exit N>` and the run continues.
- Without `--purge`: `left in place:` for each existing dir, then the `--purge` hint.
- With `--purge` and every target succeeded: the purge guard runs first (basename `mission-control`, or
  exactly `MC_HOME/state` or `MC_HOME/config`), then both dirs are removed. Any failure deletes nothing
  and prints `purge skipped`.
- Exit 0 only when the daemon step and every target succeeded (and the purge, when asked). The last line
  on success is `mission-control removed. Now run: npm rm -g mission-control-desktop`.
- Usage: `--purge` alone, `--all` with a target, and extra words exit 2 with the new usage line.
  `mc uninstall <target>` is unchanged.
- The `main.ts` usage line is updated.
- Tests: `packages/cli/test/uninstall-all.test.ts` has UA-01..UA-07, all passing. They use the sandbox
  fixture, the fake `run`, temp `MC_HOME`, and a daemon started in temp `MC_HOME` (UA-06).
- `packaging-test/install.test.mjs` has SK-08 (added last, own prefix). It passes through
  `pnpm task:check T124` (8/8) with a release tarball built by `pnpm package`.
- Acceptance: `pnpm -r build && pnpm task:check T124 && pnpm vitest run packages/cli/test` exits 0.
  Typecheck and lint exit 0.

## What does not / caveats

- **macOS purge refuses by default.** On darwin without `MC_HOME`, the state dir is
  `.../mission-control/state`, so its basename is `state`, not `mission-control`. The guard as written
  in D-59 refuses it, and `--purge` on macOS exits 1 with `purge: refusing to delete`. No test covers
  this (the tests run with `MC_HOME`). This follows D-59 literally; the guard probably needs the parent
  name too. Not changed here (see Surprises).
- **`uninstallVscode` ignores the exit code** of `code --uninstall-extension` (`vscode.ts` is not a file
  this task owns). A non-zero exit is reported as `vscode: removed`, and the manifest entry is deleted, so
  a retry cannot find it. UA-04 therefore makes the fake `run` throw for that command, which reaches the
  `--all` catch and gives `vscode: failed: boom`.
- SK-08 needs a release tarball. `pnpm package` produced `release/mission-control-desktop-1.0.1.tgz`
  (gitignored). `task:check` fails SK-01..08 without it ("run pnpm package first").

## Surprises

- The copilot manifest key is `copilot-cli`, not `copilot`. It does not matter for `--all`, because
  copilot always runs, but the "has a manifest entry" check uses target names, so the mapping is
  noted here.
- A failing `code --uninstall-extension` is only a failure through a thrown error (see above).
- `DECISIONS.md` D-59 has one very long line, which the Read tool omits when it is in a large window.
  The text was read with a narrow offset.
