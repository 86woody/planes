# T085: CLI lib in package mode: paths, koffi, --version, hook-paths, launcher self-heal

Milestone M5 · Wave 8e · Depends on: T083, T084 · Runs on: any OS

## Goal

The `mc` CLI finds its own files through `layout()` instead of "four levels up", loads koffi
in a packaged install, answers `mc --version`, warns in `mc doctor` when a hook path is
stale, and `mc start` rewrites the launchers when their target moved.

## Codes against

`docs/PACKAGING.md` 3 (`Layout`), 4 (launchers) and 5 (upgrade and node switch),
`docs/DECISIONS.md` D-40, D-41 item 3, D-42 and D-44 item 3, `docs/contracts/claude-hooks.md` 2,
`docs/contracts/config.md` 1-2. T083 provides `installers/launcher.ts`, T084 makes the claude-code and codex installers write the launchers (PC-06, PC-09 and PC-10 rely on it); `installers/codex.ts`
already exports `parseNotify`.

## Steps

1. `lib/paths.ts`: `import { layout } from "@mc/platform/layout";` Replace line 6 with
   `export const REPO_ROOT = layout().root;` (comment: "the install root: the clone in clone mode, the package directory in package mode;
   the name stays for existing imports") and line 51 with `export const DAEMON_BIN = layout().daemonJs;`. Drop the `fileURLToPath` import
   and, if unused, `path`'s import stays (it is used by `resolveCliPaths`).
2. `lib/system.ts`: remove the `REPO_ROOT` import (line 4). Add and export
   `export function koffiRequireBase(lay: Layout): string` returning `path.join(lay.root, "package.json")` in package mode and
   `path.join(lay.root, "packages", "platform", "package.json")` in clone mode, and
   `export function koffiRequire(lay: Layout = layout()): NodeRequire` returning `createRequire(koffiRequireBase(lay))`
   (a packaged install resolves `koffi` from `<package>/node_modules`, where npm puts the dependency). `allowSetForeground` (line 60) uses
   `koffiRequire()`.
3. `lib/doctor-checks.ts`: remove `REPO_ROOT` from the import at line 6; the `koffi` check (line 131) uses `koffiRequire()("koffi")` (import from `./system.js`)
   and the `createRequire` import goes if unused. `checksFor` gets a fourth parameter `lay: Layout = layout()` (after `home`), used by the new check below.
4. `main.ts`: before the `help` branch in `main`, add: if `name === "--version" || name === "-v"`: `io.out(layout().version)` and return `0`
   (extra arguments are ignored). Add the line `  --version, -v         print the version` to `USAGE` after the `uninstall` line.
5. New check in `doctor-checks.ts`, appended to the `common` array (so it appears on every OS), exactly:
   `{ id: "hook-paths", label: "Hook paths current", required: false, fix: "mc install <target>", run }`.
   `run` reads `<paths.stateDir>/install-manifest.json` (`paths` is already in scope):
   - file missing, or the manifest has no keys: return `{ status: "ok", detail: "nothing installed" }`; unparsable JSON: `{ status: "warn", detail: "install-manifest.json is not valid JSON" }`.
   - Otherwise collect `problems: string[]` and return `"ok"` when empty, else `{ status: "warn", detail: problems.join("; ") }`. Helpers
     (`launcherProblems(label, file, expected)`: `!existsSync(file)` -> `<label>: launcher missing <file>`; `readLauncherTarget(file) === null` -> `<label>: <file> is not a launcher`;
     target `!== expected` -> `<label>: launcher targets <target>, this install is <expected>`; else `!existsSync(target)` -> `<label>: launcher target missing <target>`).
   - `claude-code` entry (`entry.settingsPath`) and `copilot-cli` entry (`entry.hooksPath`): if the file exists parse it (invalid -> `<label>: <file> is not valid JSON`). For every event key of `hooks`,
     collect the mc objects (claude: `args` length 2, `args[0]` ends in `mc-hook.js` after `\`->`/`, `args[1]==="claude-code"`, objects found inside each group's `hooks` array; copilot: objects of the flat array with `args` length 3,
     `args[0]` ends in `mc-hook.js`, `args[1]==="copilot-cli"`). More than one -> `<label>: N mc hooks for <Event>`. For every mc object: its `command` (copilot: `exec`) not an existing file ->
     `<label>: command missing <command>`; then `launcherProblems(label, args[0], lay.hookJs)`.
   - `codex` entry (`entry.path`): find the first line matching `/^\s*notify\s*=/`, `parseNotify(lines, index)` from `../installers/codex.js`; if `argv[1]` ends in `mc-hook.js` and `argv[2]==="codex"`:
     `argv[0]` missing file -> `codex: command missing <argv[0]>`, then `launcherProblems("codex", argv[1], lay.hookJs)`.
   - `shell` entry (`entry.envFile`): read lines `MC_NODE=` and `MC_HOOK_JS=`; node missing -> `shell: command missing <node>`; `launcherProblems("shell", hookJs, lay.hookJs)`.
   - `uri-handler` (win32 shim, `entry.restoreVbs`): text matched by `/Run """(.+?)"" ""(.+?)"" restore/`; (linux, `entry.desktopFile`) by `/^Exec="(.+?)" "(.+?)" restore/m`; groups are node and mc.js: node missing -> `uri-handler: command missing <node>`,
     `launcherProblems("uri-handler", mcJs, lay.mcJs)`. The `direct` Windows mode (`restoreVbs` is null) is skipped.
   - `autostart`: win32 `entry.vbs` by `/Run """(.+?)"" ""(.+?)"" start/`; linux systemd `entry.unit` by `/^ExecStart="(.+?)" "(.+?)" daemon/m`; linux xdg `entry.desktopFile` by `/^Exec="(.+?)" "(.+?)" start/m`;
     darwin `entry.plist` by `/<string>([^<]+)<\/string>\s*<string>([^<]+)<\/string>\s*<string>daemon<\/string>/`. Same two checks with label `autostart`.
   - Any listed file that does not exist is skipped silently (uninstalled by hand); a regex that does not match is skipped. Nothing is ever written. The existing `claude-hooks` check is unchanged.
6. `commands/start.ts`: add and export
   `export function healLaunchers(paths: CliPaths, io: { out(s: string): void }, lay: Layout = layout()): boolean`:
   read `paths.stateDir/install-manifest.json` (missing or invalid JSON or not an object -> return `false` and write nothing); if it has no keys, return `false`; otherwise
   `const { changed } = writeLaunchers(paths.stateDir, lay)`; when `changed`, `io.out(\`launchers updated -> ${lay.root}\`)`; return `changed`.
   In `run`, call `healLaunchers(paths, io)` after `resolveCliPaths` and before `ensureRunning` (so a failed daemon start still heals). The output line is exactly
   `launchers updated -> <layout().root>`, once, only when changed (`io.out` adds the newline).

   Bodies:
   - PC-01: `main(["--version"], io)` and `main(["-v"], io)` return 0, `out` is `[layout().version]` and `layout().version` equals the `version` of the root `package.json` read from `REPO_ROOT`; `main([], io)` `err` text contains `--version, -v`.

     `koffiRequire(layoutFor("package", tmp, "1"))("koffi").marker === 1`.
   - PC-05: empty `MC_HOME`: `run()` of the check returns `{ status: "ok", detail: "nothing installed" }`; `check.id === "hook-paths"`, `label === "Hook paths current"`, `fix === "mc install <target>"`, `required === false`; it is present in `checksFor("win32"|"darwin"|"linux", ...)`.
