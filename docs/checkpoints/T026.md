## Choices the contract left open (for review)

- POST /api/pair: a request with no Origin header is refused with 403 as well as a foreign
  Origin. api.md 3 says "Origin must be the daemon's own"; a browser always sends Origin on
  POST, so this is the strict reading.
- Restore body: `{}` or `{"source": "notification"}`; any other body is 400 invalid_request.
- Unknown routes go through the security hook first, so an unauthenticated 404 is a 401.
- `wsHub` is process-global (as the task specifies), so two apps alive at once would both
  receive broadcasts. Tests close each app before the next starts.
- Broadcast `daemon.update` builds its daemon info and capabilities at send time (async),
  so seq is still assigned at the moment of the send.

## Surprises

- Setting `route.config` in an `onRoute` hook inside a scoped plugin is enough to give
  @fastify/static routes `realm: none`. No wrapper was needed.
- `sessions.apply({kind: "ack"})` only acknowledges an active attention, so API-08 starts from
  a Notification fixture.
- Fixture `sentAt` values are older than the retention window of a 2026-11-12 test clock,
  so an ended session is pruned at once. The tests stamp `sentAt` with the test clock.
- Git reports CRLF warnings for the new TypeScript files. Content is LF; nothing was
  reformatted.
