# T088: `scripts/release.mjs` and the 1.0.0 release notes

Milestone M5 · Wave 8g · Depends on: T087, T092 · Runs on: any OS

## Goal

`pnpm release` runs the project gate, builds the package with `scripts/package.mjs`, and
copies `RELEASE-NOTES.md` next to the artifacts, so `release/` holds the three files that
go on the forge release. The notes carry install, upgrade, uninstall and an honest
"Unverified" section.

## Codes against

`docs/PACKAGING.md` 1, 5 and 6, `docs/DECISIONS.md` D-44 (items 4 and 5), PRD section 8 Q4,
AC-07 and AC-09, `docs/TEST-PLAN.md` 6.

## Files

`scripts/release.mjs`, `RELEASE-NOTES.md`, `packaging-test/release.test.mjs`,
`docs/checkpoints/T088.md`. The root `package.json` script `"release": "node scripts/release.mjs"`
is added by T080, not by you. If it is absent, write `CR:` in your checkpoint (do not edit
`package.json`); `node scripts/release.mjs` still works.

## Do not touch

Every other file, including `scripts/package.mjs` (T087), the root `package.json` and
`scripts/gates.json`.

## Steps

1. `scripts/release.mjs`, plain ESM Node. Arguments: `--skip-gate` (flag), `--out <dir>`
   (default `<ROOT>/release`, resolved absolute). Anything else, or `--out` without a value:
   print `usage: node scripts/release.mjs [--skip-gate] [--out <dir>]` to stderr, exit 2.
   `ROOT` is the repo root (`scripts/..`); `VERSION` is `version` of the root `package.json`.
2. Order of work:
   1. Unless `--skip-gate`: run the gate with stdio inherited, in `ROOT`. The command is
      `pnpm gate`, except that when the environment variable `MC_RELEASE_GATE_CMD` is set its
      value is run through the shell instead (tests use it). A non-zero status prints
      `RELEASE FAIL gate` to stderr and exits 1 before anything is packaged.
   2. Run `node scripts/package.mjs --out <out>` (inherit stdio). Non-zero: print
      `RELEASE FAIL package` and exit 1.
   3. Copy `<ROOT>/RELEASE-NOTES.md` to `<out>/RELEASE-NOTES.md`. If the notes' first line is
      not `# mission-control-desktop <VERSION>`, print `RELEASE FAIL notes version` and exit 1.
   4. Check that `<out>/mission-control-desktop-<VERSION>.tgz`, `<out>/vscode-bridge-<VERSION>.vsix`
      and `<out>/RELEASE-NOTES.md` exist, else `RELEASE FAIL missing <name>`, exit 1.
   5. Print as the last line (stdout) `RELEASE <VERSION> <out>` and exit 0.
3. Create `RELEASE-NOTES.md` in the repo root. First line exactly
   `# mission-control-desktop 1.0.0`. Then these sections, in this order, with these headings:
   - `## What this is`: two or three sentences: Mission Control watches local coding-agent
     sessions and lets you jump to the one that needs you; this release is the first
     packaged one (an npm tarball plus a VS Code extension file; nothing on a registry).
   - `## Install`: a fenced block with exactly these three lines, then one sentence that
     Node >= 22 is required, that `mc init` asks which agents to connect (GitHub Copilot CLI
     is pre-selected; Claude Code and Codex are the others) and installs the VS Code
     extension when `code`, `code-insiders` or `cursor` is on PATH, and that `mc launch`
     starts Mission Control and opens the page.
     ```
     npm i -g ./mission-control-desktop-1.0.0.tgz
     mc init
     mc launch
     ```
     After the block add a `### Reference` paragraph (one sentence each) naming `mc start`,
     `mc open` and `mc install <target>` as the individual commands, including
     `mc install shell` and `mc install autostart`, which `mc init` does not run.
   - `## Upgrade`: `mc stop`, then `npm i -g ./mission-control-desktop-<new>.tgz`, then `mc launch`
     (as a fenced block, three lines); one sentence each: `mc launch` (through `mc start`) rewrites the launchers
     when their target moved and hooks are not rewritten; after a Node version switch run
     `mc doctor`, which warns `hook-paths`, then `mc init` again (or `mc install <target>`).
   - `## Uninstall`: a fenced block `mc stop`, `mc uninstall <each installed target>`,
     `npm rm -g mission-control-desktop`; one sentence that config and state directories stay.
   - `## Unverified`: the sentence `This release has not been proven on a Mac, and the
     fresh-machine install was proven on one OS only.` followed by this bullet list, verbatim:
     - `AC-07: RESTORE on Terminal.app and iTerm2 (no Mac available, PRD Q4).`
     - `The macOS rows of AC-09: notification click restore on macOS.`
     - `MO-01..MO-06: the macOS OS-level tests, which only run on a Mac.`
     - `The macOS manual checklist rows M-01..M-07.`
     - `fresh-machine proof: Windows Sandbox only. No fresh-machine run on Linux or macOS.`
   - `## Contents`: one line each for `mission-control-desktop-1.0.0.tgz`,
     `vscode-bridge-1.0.0.vsix` and `RELEASE-NOTES.md`.
4. Tests in `packaging-test/release.test.mjs` (vitest, `import { test, expect, afterAll } from
   "vitest"`). Setup: `ROOT`, `VERSION` (from the root `package.json`), `NOTES = readFileSync(ROOT +
   "/RELEASE-NOTES.md", "utf8")`, temp dirs removed in `afterAll`. Titles exactly:
   - `RN-01 the notes have an Unverified section naming AC-07, the macOS rows of AC-09, MO-01..MO-06 and the Windows Sandbox proof`
   - `RN-02 the notes title carries the version of the root package.json`
   - `RN-03 the notes give the install (npm i -g, mc init, mc launch), upgrade and uninstall commands of PACKAGING.md 5`
   - `RN-04 release --skip-gate leaves the tgz, the vsix and the notes in the out dir and prints RELEASE <v> <out>`
   - `RN-05 a failing gate stops the release before anything is packaged`

   Assertions:
   - RN-01: the text after the line `## Unverified` (up to the next `## ` heading or the end)
     contains each of: `AC-07`, `macOS rows of AC-09`, `MO-01..MO-06`,
     `fresh-machine proof: Windows Sandbox only`.
   - RN-02: the first line equals `# mission-control-desktop ${VERSION}`.
   - RN-03: `NOTES` contains `npm i -g ./mission-control-desktop-${VERSION}.tgz` (this needs the
     notes' version equal to the package version; if you bump the version, update the notes),
     `mc init`, `mc launch`, `mc install vscode`, `mc start`, `mc open`, `mc stop`,
     `mc uninstall <each installed target>`, `npm rm -g mission-control-desktop` and `mc doctor`.
   - RN-04: the tree is already built (the `package` gate stage and the acceptance command run
     `pnpm -r build` first; do not build in the test). Run `spawnSync(process.execPath, ["scripts/release.mjs", "--skip-gate", "--out", OUT],
     { cwd: ROOT, encoding: "utf8" })`; status 0; last stdout line equals `RELEASE ${VERSION} ${OUT}`;
     `mission-control-desktop-${VERSION}.tgz`, `vscode-bridge-${VERSION}.vsix` and
     `RELEASE-NOTES.md` exist in `OUT`; `RELEASE-NOTES.md` equals the root file byte for byte.
     Timeout argument of this test: `600_000` (it runs the packager).
   - RN-05: run `release.mjs --out OUT2` (no `--skip-gate`) with env `MC_RELEASE_GATE_CMD` set to
     `node -e "process.exit(3)"`; status 1, stderr contains `RELEASE FAIL gate`, and `OUT2` has no
     `.tgz` file (the directory may not exist at all). Timeout `30_000`.
