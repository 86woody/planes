# T117: the daemon keeps Copilot traces and spans per session (D-57)

Milestone M5 · Wave 9d · Depends on: T113, T114 · Runs on: any OS

## Goal

Keep each Copilot agent run as a trace: the `invoke_agent` root with its `chat`, compaction,
`execute_tool` and skill spans, their timing, tokens and status, and span event names. Serve them
at `GET /api/sessions/:id/traces`. Names and numbers only, never content.

## Codes against

`docs/DECISIONS.md` D-57; `docs/contracts/api.schema.json` (`TraceSpan`, `TraceRun`,
`TracesResponse`); `docs/contracts/api.md` (the `GET /api/sessions/:id/traces` row).

## Files

`packages/daemon/src/traces.ts`, `packages/daemon/src/telemetry.ts` (hand each routed span record to
the trace store too, only), `packages/daemon/src/routes/api.ts` (the traces route only),

`packages/daemon/test/traces.test.ts`, `docs/checkpoints/T117.md`.

## Steps

1. `createTraceStore(deps: Pick<DaemonDeps, "clock" | "log" | "paths" | "sessions">)` returns
   `{ addSpan(sessionId, rec): void; runs(sessionId): TraceRun[]; flush(): Promise<void> }`.
2. `addSpan` takes a Copilot OTel `span` record (T112 reads its attributes in object or OTLP list form;
   reuse that reading: copy the small helper into `traces.ts`). Group by `traceId`. Map:
   `spanId`, `parentSpanId` (empty or missing -> null), `name` (cut to 96), `startedAt` from
   `startTime`, `durationMs` from `endTime - startTime` (null when missing; both may be ISO strings,
   numbers in ms, or `[seconds, nanos]` pairs; read all three), `status` from `status.code`
   (`2`/`ERROR` -> error, `1`/`OK` -> ok, else unset), `kind` per the schema description, `model`
   = `gen_ai.response.model` ?? `gen_ai.request.model`, `tool` = `gen_ai.skill.name` ?? `gen_ai.tool.name`,
   `inputTokens`/`outputTokens` = `gen_ai.usage.input_tokens`/`output_tokens`, `ttftMs` =
   `gen_ai.response.time_to_first_chunk` (seconds in OTel: multiply by 1000), `serverMs` =
   `github.copilot.server_duration` (as written, ms), `events` = the span's event names and times,
   newest 20. Copy no other attribute, never an attribute value that is not one of these.
3. A run: `traceId`; `startedAt` = earliest span start; root = the span with kind `agent` and no
   parent in the trace; `complete` = root present; `durationMs`, `status`, `agent`
   (`github.copilot.agent.type` ?? null), `nanoAiu` (`github.copilot.nano_aiu`), `turnCount`
   (`github.copilot.turn_count`) from the root; `spans` sorted by `startedAt`, root first, at most 500
   (count the rest in `droppedSpans`). Keep the newest 50 runs per session. A duplicate `spanId` in
   one trace replaces the earlier one (research note C1).
4. Persist each session's runs to `<stateDir>/traces/<url-safe session id>.json` (atomic write,
   debounced 2 s, `flush()` writes now); load lazily on the first `runs()` call. Delete the file when
   the session is removed (subscribe to `sessions.onChange` remove events).
5. `telemetry.ts`: where a span record is routed to a session's fold, also call
   `traces.addSpan(sessionId, rec)`.
6. Route `GET /api/sessions/:id/traces`, realm browser-or-bearer: unknown id -> 404 as the other
   session routes; else `200 {sessionId, runs}`.

## Tests (`packages/daemon/test/traces.test.ts`; temp `MC_HOME`; no sleeps over 2 s, fake timers for the debounce)

- `TT-01` spans of one trace (root, two chat, one tool, one compaction chat) build one complete run:
  kinds, parent links, tokens, ttft in ms, root first; `validateTracesResponse` passes.
- `TT-02` spans that arrive before their root give `complete: false`, then `true` after the root.
- `TT-03` a duplicate spanId replaces, does not add; more than 500 spans count `droppedSpans`; more than
  50 runs keep the newest 50.
- `TT-04` an attribute not on the copy list (e.g. `gen_ai.input.messages` with `SECRET-ARGS-7731`) is not
  in the stored JSON file or the route body.
- `TT-05` the route: 404 for an unknown id; 200 with runs for a known one (use the daemon test harness).
- `TT-06` `flush()` writes the file; a new store reads it back; removing the session deletes it.
