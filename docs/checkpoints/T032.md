## What works

- `api.ts`: `state`, `pair`, `restore`, `ack`, `dismiss`. CSRF kept in memory and in
  `sessionStorage["mc.csrf"]`, sent as `X-MC-CSRF` on POST/DELETE. `state()` fetches
  `/api/csrf` when no token is known; a 403 on a mutation refetches once and retries once.
  `state()` returns `"unpaired"` on 401; `restore` returns `null` on 429/404.
  `forgetCsrf()` is an extra named export (not on the `api` object) for tests.
- `store.ts`: `useBoard()` backed by an external store (`useSyncExternalStore`), so the
  WebSocket and timers keep one identity. Pairing (no code in any URL), `hello` / upsert
  / remove / daemon.update / notify / highlight, seq-gap close and reconnect every 2 s,
  ping every 20 s, restore results kept 5 s (1 s tick prunes them), `copyCwd` synthetic
  `FOCUS MANUALLY` result, the `R` shortcut on `document.body`.
- `sort.ts`: `sortSessions` (DESIGN.md 2 group order, then `attention.since` oldest
  first, then `startedAt` newest first; ended and lost go to splashdown, most recently
  updated first), `pollItems` (active, unacknowledged attention; permission/error, input,
  done; `since` ascending), `counts` (GO/HOLD/NO-GO/LOS).
- Components: `PollStrip` (testid `poll`, chips `poll-chip` with `data-session`, click
  restores), `Counts` (testid `counts`, children `count-go`, `count-hold`, `count-nogo`,
  `count-los`, text such as `GO 4`), `Board` (testid `board`, `Card` grid, `Empty` when
  there are no sessions, `splashdown` section with `splashdown-toggle`, collapsed by
  default and rendered only when it has sessions).
- `board.css`: grid, poll strip, counts and splashdown styles on the `--mc-*` tokens.
  `Board.tsx` imports it.
- `packages/ui/test/store.test.tsx`: the 11 US titles, jsdom, fake WebSocket, fetch
  routing mock, Notification stub. Card and Empty are not imported by the store test.

## What does not

- Board and PollStrip have no rendering tests (not in the task's list). They are checked
  only by typecheck and by T033's e2e later.
- `Card` and `Empty` are still T031/T030 stubs that throw. The Board renders them, so
  the page will not render until those merge. The store tests do not render Board.
- Choices the task left open: the poll chip labels (permission and error show `NO-GO`
  and `ANOMALY`, input `HOLD`, done `MECO`, from DESIGN.md 4 and 2); `Counts` puts the
  label and number in one element; `pollItems` does not exclude ended or lost sessions,
  since the task's wording did not say to.
