## Decisions the contract left open

1. **SM-24 (stale) and SM-25 (revive) are guards before the row table.** The table lists them after the live rows, but a stale PostToolUse on a live session would match SM-10 first, which contradicts attention.md section 3. So the stale check runs first (SessionEnd exempt), then the revive, then the table.
2. **SM-28 is the creation default, not a row.** A created session starts `working`, so SM-16 (live catch-all) handles any event with no earlier match. SM-01, SM-02 and SM-07 are checked first and use a `created` flag, because a created session is live and would otherwise match SM-04/SM-05/SM-06.
3. **Catch-alls at the end of the table.** SM-16 (any live event) and SM-26 (any non-live event) are last, so they cannot shadow the specific rows.
4. **Shell and codex are normalized to a Claude row name.** ShellCommandStart becomes UserPromptSubmit (no prompt text, so the title is not set). ShellCommandEnd shorter than the threshold becomes an internal ShellIdle row (SM-34). A long ShellCommandEnd with exit 0 becomes Stop with message `<command> exited <code>`. A nonzero long one becomes StopFailure with message "Turn failed", since shell has no `error` payload. A missing `exit_code` is treated as 0.
5. **process.alive** is set to true on an applied ingest when the agent pid is present and the session is live. SM-03 and the revive path also set it true. SM-21 sets it false.
6. **Title** follows the project while `title === project`, and a captured first prompt overrides it. This means a cwd change updates the title only when no prompt has set it.
7. **Attention messages** are truncated to 200 code points, and `lastEvent.summary` to 120.
8. **Generic event names** are matched exactly as attention.md table 3 gives them (Start, Working, NeedsInput, NeedsPermission, Done, Error, End).
9. **Helper clock.** `envelope()` steps `sentAt` by 1000 ms per call. Tests that need a stale event override `sentAt` explicitly.

## What does not work / not covered

- Nothing known broken. The reducer is pure: no clock, no I/O, no `node:` imports (lint passes).
- `changed` uses a recursive deep-equal of the whole session. For ingest it is true almost always, because `stats.events` moves on every applied event. That matches section 1.
- Not exercised here: the daemon wiring, the real `classifyHost` (T012), and notify policy (T011).

## Surprises

- Table order and the guard rules are ambiguous for SM-24 and SM-25 (decision 1). If the orchestrator reads the table literally, the stale and revive rules would need to move.
- SM-18 in a waiting state has no row. It falls to the SM-16 catch-all, which gives the specified "unchanged".
