# T004: Gate runner, task check, test-ID audit, CI workflow

Milestone M0 · Wave 0b · Depends on: T001 · Runs on: any OS

## Goal

Build the three scripts every later task and milestone is judged by: `gate.mjs`
(milestone gates), `task-check.mjs` (per-task acceptance), `check-test-ids.mjs` (the
audit), plus the test-ID registry and the forge CI workflow.

## Codes against

`docs/TEST-PLAN.md` sections 2, 3, 4, 5 (all normative), `docs/TASKS.md` (milestone of
each task).

## Files (create)

`scripts/gate.mjs`, `scripts/gates.json`, `scripts/task-check.mjs`,
`scripts/check-test-ids.mjs`, `scripts/test-ids.json`, `scripts/lib/report.mjs`,
`scripts/lib/run.mjs`, `scripts/test/gate.test.mjs`, `scripts/test/fixtures/**`,
`.gitea/workflows/gate.yml`, `docs/checkpoints/T004.md`.

## Do not touch

Everything else. Plain Node ESM only (no TypeScript, no dependencies beyond Node built-ins).

## Steps

1. `scripts/gates.json`: `{"stages": [{"name", "kind": "cmd"|"vitest"|"playwright", "pre": [cmd...]?, "cmd": "...", "first": "m0".."m5"}]}`
   with exactly the rows of TEST-PLAN 2.1, in order, `audit` last.
2. `scripts/lib/run.mjs`: `runStage(stage, gate) -> {pass, ms, tail}`. For `vitest`
   stages append `--reporter=default --reporter=json --outputFile=.gate/reports/<name>.json`;
   for `playwright`, set env `PLAYWRIGHT_JSON_OUTPUT_NAME=.gate/reports/<name>.json` and
   pass `--reporter=line,json`. Commands run through `pnpm exec` with `shell: true` and
   inherit env; environment assignments at the start of a command (`MC_OS_TESTS=1 ...`)
   are parsed and moved into `env` (Windows has no inline env syntax). Capture combined
   output; `tail` = last 30 lines.
3. `scripts/gate.mjs <mN>`: select stages with `first <= mN`; clear `.gate/reports`;
   run in order; print the lines of TEST-PLAN 2.2 exactly (`STAGE <name> PASS|FAIL <ms>ms`
   plus optional summary text, failing tails indented with `  | `); stop early only if
   `toolchain` fails; final line `GATE <mN> PASS n/n` or `GATE <mN> FAIL k/n` (k passed);
   exit 0 iff all passed. `audit` is called with `--gate <mN>`.
4. `scripts/test-ids.json`: expand every row of TEST-PLAN section 4 into
   `{"ids": {"<ID>": {"task", "milestone", "os", "file", "runner"}}}` where milestone
   comes from TASKS.md's task table and runner is `playwright` for files under `e2e/`,
   else `vitest`. Write it by hand from the doc (no doc parsing at runtime).
5. `scripts/lib/report.mjs`: read vitest JSON (`testResults[].assertionResults[]` with
   `title`/`fullName` and `status`) and Playwright JSON (`suites[].specs[].title`,
   `tests[].results[].status`, nested suites) into `{title, status}` lists. Normalise
   statuses to `passed|failed|skipped`.
6. `scripts/check-test-ids.mjs --gate <mN> [--reports <dir>]`: TEST-PLAN 2.3 exactly.
   The test title is matched with `/^([A-Z]+-\d{2})\s/` against the **leaf** title
   (`title`, not the full describe path). Current OS: `win32`->windows, `darwin`->macos,
   else linux. Output `ids <found>/<required> (os=<os>), skipped <k>`; on failure also
   `missing: <ids comma-separated>` and/or `unknown: <ids>`.
7. `scripts/task-check.mjs <T0xx>`: TEST-PLAN 2.4 exactly. Group the task's IDs (for
   the current OS and `any`) by file and runner; run `pnpm exec vitest run <files...>
   --reporter=default --reporter=json --outputFile=.gate/task-<T>.vitest.json` and/or
   `pnpm exec playwright test <files...>` with the JSON env; then check. Unknown task:
   `TASK <T> UNKNOWN` exit 2. A task with zero IDs for this OS prints
   `TASK <T> PASS 0/0 (os=<os>, <m> ids for other OSes not checked)` exit 0.
8. `scripts/test/gate.test.mjs` (Vitest, project `scripts`), titles exactly:
   - `GT-01 audit passes when every required id passed` (fixture reports in `scripts/test/fixtures/`)
   - `GT-02 audit fails and lists a missing id`
   - `GT-03 audit fails on a skipped test`
   - `GT-04 audit fails on an unknown id-shaped title`
   - `GT-05 gate output ends with GATE <name> PASS n/n and exits 0 for a gates.json of two passing cmd stages` (run `gate.mjs` against a temp `gates.json` passed with `--gates <file>`, an option you add for tests)
   - `GT-06 gate continues after a failing stage and exits 1 with FAIL 1/2`
9. `.gitea/workflows/gate.yml`: TEST-PLAN section 5 row 1: `runs-on: ubuntu-latest`,
   Node 24 via `actions/setup-node@v4`, `corepack enable`, `pnpm install --frozen-lockfile`,
   `sudo apt-get install -y wmctrl x11-utils xdotool xterm openbox tmux xvfb dbus-x11`,
   `pnpm exec playwright install --with-deps chromium`, then
   `xvfb-run -a dbus-run-session -- bash -c 'openbox & sleep 1; pnpm gate'`.

## Acceptance command

```
pnpm vitest run --project scripts && node scripts/task-check.mjs T004
```

## Expected output (last lines)

```
 Tests  6 passed (6)
...
TASK T004 PASS 6/6
```

Exit 0. Then also run `node scripts/gate.mjs m0` once and paste its output into your
checkpoint. It must fail at this point, exactly like this (the contracts and fake
platform tests do not exist until T002/T003): `STAGE contracts FAIL`,
`STAGE platform-fake FAIL`, an audit line containing `missing: CT-01`, and last line
`GATE m0 FAIL 5/8`. Any other result means a bug in the runner.
