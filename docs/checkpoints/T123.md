# T123 checkpoint

## What works

- `App.tsx`: `useRoute()` drives the page. A session route renders `SessionView` and a run route renders
  `RunTrace` inside `main` in place of the side column and Board; the telemetry row is hidden on a page.
  The deck renders as before.
- Run route: `api.traces(id)` on entering, then every 5 s while the run is not complete and the session is
  live. A failed refresh keeps the last good answer. `loading` is true until the first answer.
- A session or run route whose session is missing (after state arrived) goes to the deck. Entering a page
  selects its session and closes the sheet.
- Keys on a page: Esc goes up one level (run -> session -> deck), j/k open the next/previous session page
  along `walk`, Enter restores, `?` and `t` work; every other deck key is ignored there.
  On the deck, `o` opens the selected session's page.
- `Details.tsx`: `sheet-open` link after Copy cwd. `Help.tsx`: the `O` row after `I`.
- `routes.test.tsx`: RO-01 to RO-05 pass. Existing `shell.test.tsx` still passes.

## What does not

- The 5 s trace poll is not covered by a test (no fake-timer test of the interval).
- No change to `route.ts`, `api.ts`, the session or run components.

## Surprised me

- Enter on a waterfall row (`role="row"`, own Enter handler in `RunTrace.tsx`) also reaches the window key
  handler, which restores the page session because the `onControl` check does not include `[role=row]`.
  Left as written (the task says Enter restores); worth a follow-up.
- RO-01 needs the `t` preview on to make the "no telemetry row" check meaningful, since the row is off by default.
