# T024 checkpoint: FocusService and target resolution

## What works
- `createFocusService` in `packages/daemon/src/focus.ts` implements `resolve(id)` and `restore(id, source)` with the frozen signatures.
- `resolve`: no record or no origin does nothing. Ended or lost sessions write `none/process_ended` with no target. VS Code sessions go through the bridge registry (bound window, unbound with title fallback, or no bridge with title fallback as `window/vscode_bridge_missing`). Everything else goes through `platform.resolveTarget`. The `{windowId, terminalId}` link is kept in a private map.
- `restore`: unknown id gives `failed/not_found` with no apply. Missing target triggers `resolve` first. Capability `none` gives `failed/unsupported` with the reason and no `platform.focus` call. Otherwise `platform.focus` runs with the config options. For VS Code targets the bridge request follows (`focusTerminal` or `focusAgentPanel`) and the results combine as in vscode-bridge.md 5. `not_found` unbinds (VS Code only), re-resolves and retries once. The result is always applied as `restore_result` with `ackOnRestore` from config. The function never throws.
- Concurrent restores of one session share one in-flight promise.
- Tests FO-01 to FO-10 in `packages/daemon/test/focus.test.ts`, titled exactly as the task file. They use `FakePlatform` (subclassed for `listWindows`), and in-memory session and bridge doubles. No real windows are touched.

## Decisions
- A restore for a session whose target is still missing after `resolve` (no origin) is treated as `none/no_window_found`. The task file does not cover this case.
- Capability `none` restores are still applied as `restore_result` (the spec's "finally" step), so the page sees the failure.
- The `not_found` retry for a non-VS Code target re-resolves without unbinding anything. The task file only names unbind for OS `not_found` on VS Code targets.
- `FocusResult.detail` is cut to 200 characters to match the schema.
- The title match is case-sensitive, as the spec's contains/ends-with wording reads.

## What does not work / open
- Nothing known to be broken. The bridge registry (`bridge.ts`, T022) is still a stub on this branch. T024 tests use a double, so this does not block them, but the real restore path is untested end-to-end until T022 merges.

## Surprises
- `FakePlatform.focus` reads its script after recording the call, so a log hook that changes `focusResult` on the first call affects that same call. The FO-08 test switches the script on the second call.
