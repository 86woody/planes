# T016 checkpoint: persistence

## What works
- `createPersistence` in `packages/daemon/src/persistence.ts` implements the frozen `Persistence` interface.
- `load()`: missing file gives empty state; invalid JSON or `version !== 1` (or non-array `records`) renames the file to `sessions.json.corrupt-<ms>` and returns empty. Each record's `session` is checked with `validateSession`; invalid records are dropped and counted in one warn line.
- `scheduleSave()`: 500 ms debounce; writes `sessions.json.tmp` via `fs.promises.open`/`write`/`sync`/`close`, then `rename` over the target. Saves are chained so they never overlap. `flush()` cancels the timer, runs a pending save now and awaits in-flight work.
- `appendEvent()`: if `events.jsonl` is >= 10 MiB it is renamed to `events.jsonl.1` (replacing any old `.1`), then the line is appended with `appendFileSync`.
- `readSpool()`: lists `spoolDir` (missing gives []), keeps `*.json`, sorted by name; unparseable files come back with `envelope: null`. `file` is the full path. `deleteSpool(file)` ignores ENOENT.
- Tests PS-01, PS-02, PS-03 in `packages/daemon/test/persistence.test.ts`; `Paths` is built by hand in the test, and all state goes under a `mkdtemp` directory (no `paths.ts` import).

## Decisions
- The test reads its session and envelope fixtures from `packages/contracts/fixtures/` (read-only). No contract file was changed.
- `deleteSpool` takes the full path that `readSpool` returns, so the two calls compose without re-joining.
- Spool sorting uses plain string sort on file names, which is what the spec says. `sentAt` is not zero-padded, so numeric order is not guaranteed; the caller should not rely on it.

## What does not work / open
- Nothing known to be broken. The sessions write does not create a `.tmp` cleanup if the process dies between write and rename; the stale `.tmp` is overwritten on the next save.

## Surprises
- `validateSession` is exported from `@mc/contracts` and needed no change.
