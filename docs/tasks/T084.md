# T084: Repair in place: claude-code, copilot, codex

Milestone M5 · Wave 8d · Depends on: T083 · Runs on: any OS

## Goal

`mc install claude-code|copilot|codex` repairs what is already there instead of appending:
it finds mc's own entries by the identification rule, updates them in place, removes
duplicates and writes the launchers. `mc uninstall` removes every entry that matches the
rule, even when the manifest records other values.

## Steps

1. Identification rules (write each as a small exported function in its own installer file;
   `endsMc(s) = typeof s === "string" && s.replace(/\\/g, "/").endsWith("mc-hook.js")`):
   - claude-code (`isMcClaude(h)`): `h` is an object, `h.args` is an array of length 2, `endsMc(h.args[0])`, `h.args[1] === "claude-code"`.
   - copilot (`isMcCopilot(h, event)`): `h.args` is an array of length 3, `endsMc(h.args[0])`, `h.args[1] === "copilot-cli"`, `h.args[2] === event`.
   - codex (`isMcNotify(argv)`): `argv.length >= 3`, `endsMc(argv[1])`, `argv[2] === "codex"`.
2. `claude.ts` `installClaude` (replace the `present`/`push` logic at lines 91-96; keep `hookCommand`, `hookArgs`, `hookObject`):
   for each spec in `CLAUDE_EVENTS`, walk the event's groups in order and collect every hook object for which `isMcClaude` holds.
   - None found: push `{ matcher: "", hooks: [hookObject] }` as today (`added++`).
   - Found: the first one is repaired in place: set `type: "command"`, `command`, `args`, `async`, `timeout` to the wanted values
     (other keys it carries are kept; key order of the object is kept). It counts as `repaired++` only if any of the five values changed.
     Every later one is removed from its group (`removed++`); a group whose `hooks` array becomes empty through that removal is removed from the
     event array; groups that were already empty are left alone. The first object keeps its group and its position.
   - `changed = added + repaired + removed > 0`. Write once with `writeWithBackup` when `changed`. Output when not changed: `claude-code: hooks already in <file>\n`
     (as today); when changed: `claude-code: added A hook group(s), repaired R, removed D duplicate(s) in <file>\n`.
   - `--dry-run` uses the same walk and prints `lineDiff` as today; it calls nothing else and writes nothing (no launchers).
   - Registry safety (D-41 item 6): the automatic uri-handler step (line 121) runs only when `ctx.env.MC_HOME` is unset. When the platform is `win32` or `linux`, the manifest has no
     `uri-handler` entry and `ctx.env.MC_HOME` is set, print exactly the line `uri-handler skipped (MC_HOME set)` (followed by a newline) with `ctx.out` instead and call nothing. The `--dry-run` line
     `would also run: mc install uri-handler` is unchanged; an explicit `mc install uri-handler` is unchanged.
   - Call `prepareLaunchers(ctx)` (import it from `./manifest.js`) after the three validation `return 1` blocks and before the first write
     (just above `const before = read.raw;`, line 98), and not on `--dry-run` (the helper already skips it). Manifest entry as today
     (`command` and `args` are the new values).
3. `claude.ts` `uninstallClaude`: still requires the manifest entry ("not installed by mc", exit 0, file untouched, when absent), but
   now scans every key of `settings.hooks` (not only `entry.events`) and removes every object with `isMcClaude(h)` (not the recorded
   `command`/`args`). Empty groups, empty event arrays and an empty `hooks` are removed exactly as today. Message unchanged
   (`claude-code: removed N hook object(s) from <file>`). The unused `command`/`args`/`events` locals are deleted.
4. `copilot.ts` `installCopilot` (lines 76-86): same walk per event over the flat list `hooks[event]`: none found -> push the object;
   first found -> repair in place (`type`, `exec`, `args` = `argsFor(ctx, event)`, `timeoutSec`); later ones removed. Same change count,
   one backup, message `copilot-cli: added A hook(s), repaired R, removed D duplicate(s) in <file>\n` when changed and the existing
   `hooks already in` line otherwise. `prepareLaunchers(ctx)` before the first write (just above `const dir = path.dirname(file);`, line 93;
   skipped on dry-run by the helper). `uninstallCopilot` (lines 144-153): for every key `ev` of `root.hooks` (not only `entry.events`), drop objects
   with `isMcCopilot(h, ev)`; the rest of the function (delete file when only `version` is left, recorded backups, created dir) is unchanged.
5. `codex.ts` `installCodex`: before the existing wrap logic, when a top-level `notify` was found and parsed and `isMcNotify(found.argv)`:
   build the new line from `[fwd(ctx.nodePath), fwd(hookJsPath(ctx)), "codex", ...found.argv.slice(3)]` as a TOML string array on one line
   (`notify = ["a", "b", "codex", "--chain", "<same base64url>"]`; strings are written the way `codexNotifyLine` writes them). Never wrap it, never
   touch `original`. If the new line text equals the existing single line, print `codex: notify already installed in <file>` and return 0. Otherwise replace
   lines `existingAt..found.end` with the new line, `writeWithBackup`, and save the manifest as `{ path, line: <new line>, original: <previous manifest original>, eol: <previous manifest eol> }`
   (keep `original` and `eol` only if the previous manifest entry has them, as today's shape for the plain case has neither). The old check at line 141
   (`found.argv.includes(...)`) is deleted. A `notify` that is not an mc line and not a plain string array behaves exactly as today (exit 1 or wrap).
   Call `prepareLaunchers(ctx)` once validation has passed and before `writeWithBackup` (skipped on dry-run by the helper).
6. `codex.ts` `uninstallCodex` (line 177): instead of matching `l.trim() === entry.line`, find the first line matching `/^\s*notify\s*=/`, parse it with `parseNotify`,
   and if `isMcNotify(argv)` replace lines `at..end` with `entry.original` (or nothing when there is none). Same manifest and message handling as today.
7. Tests, `install-repair.test.ts`. Use `sandbox()`; a helper `second(sb, nodePath, mcHomeName)` returns `{ ...sb.input, nodePath, env: { ...sb.input.env!, MC_HOME: path.join(<root>, mcHomeName) } }`
