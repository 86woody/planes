# T015: Auth and security middleware

Milestone M1 · Wave 1 · Depends on: M0 · Runs on: any OS

## Goal

The token file, pairing codes, browser sessions with CSRF, and the Fastify plugin that
enforces Host, Origin, auth realms, OPTIONS, body size, rate limits and security
headers. This is what stops a web page from driving windows (ARCHITECTURE.md 7).

## Codes against

`docs/contracts/api.md` sections 1, 2, 4 (normative), `ARCHITECTURE.md` section 7,
`api.schema.json` `$defs.Error`, `internal.md` (`Auth`, `createAuth`, `registerSecurity`, `Realm`).

## Files

`packages/daemon/src/auth.ts`, `packages/daemon/src/security.ts`,
`packages/daemon/test/security.test.ts`, `docs/checkpoints/T015.md`.

## Do not touch

`app.ts`, `routes/**` (T026 registers your plugin and sets `config.realm` on routes).

## Steps

1. `createAuth(paths, clock)`: read `tokenFile`; if missing, create 32 random bytes
   (`crypto.randomBytes`) as base64url without padding (43 chars), write with mode
   `0o600`; on Windows then run `icacls "<file>" /inheritance:r /grant:r "%USERNAME%":F`
   via `child_process.execFile` (ignore failure, log it in your checkpoint if it happens).
   Pair codes (api.md 3, `api.schema.json` `PairCodeResponse`): 8 random Crockford
   base32 characters shown as `XXXX-XXXX` (alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ`,
   from `crypto.randomInt`); only one live code at a time (issuing a new one drops the
   old), expiry `clock.now() + 60000`, single use, invalidated after 5 wrong `pair()`
   attempts. `pair()` normalises input (upper-case, remove `-`), returns a new session
   cookie value (43-char base64url random) and its CSRF token, or null. The CSRF is
   derived, never random or stored: `base64url(HMAC-SHA256(token, cookie))` (api.md 2);
   `csrfFor(cookie)` returns it for a live session, else null.
   Browser sessions survive restarts (api.md 2): keep `{cookieSha256, lastSeen}`
   in memory, load `paths.stateDir/browser-sessions.json` in `createAuth` (missing or
   corrupt -> empty), write it atomically (temp + rename, same permissions as `token`)
   on `pair()`, on expiry removal, at most once per 60 s for `lastSeen` updates, and in
   `flush()`. Sessions expire after 30 days idle. Never store the raw cookie or CSRF.
   Comparisons with `crypto.timingSafeEqual` on the digests and on the recomputed HMAC.
2. `security.ts`: `registerSecurity(app, opts)` adds an `onRequest` hook implementing
   api.md section 1 in order, reading the route's realm from `request.routeOptions.config.realm`
   (default `browser-or-bearer` if unset; `none` routes still get the Host check and
   headers). Realm rules exactly as api.md 2, including: bearer requests carrying an
   `Origin` are refused unless the route lists that origin
   (`config.allowedOrigins: string[]`, used by `/bridge/v1` for `vscode-file://vscode-app`).
   WebSocket upgrade requests go through the same hook (Fastify runs `onRequest` for
   them). Rate limits per api.md 4 with an in-memory sliding window keyed by route id
   (`config.rateLimit: {perSession?: number; total: number}` read from route config; the
   session key is `request.params.id`). `onSend` adds the headers of api.md 1 and the
   CSP for `text/html` responses. Errors use the `Error` body shape.
3. Tests build a bare Fastify app with your plugin and a few dummy routes per realm.
   Titles exactly:
   - `SEC-01 Host evil.example:47800 gets 421 bad_host`
   - `SEC-02 Host localhost:<port> and 127.0.0.1:<port> are accepted`
   - `SEC-03 OPTIONS gets 405 and no Access-Control headers`
   - `SEC-04 bearer route without Authorization gets 401`
   - `SEC-05 bearer route with Origin header gets 403 even with the right token`
   - `SEC-06 browser POST without X-MC-CSRF gets 403`
   - `SEC-07 browser POST with a foreign Origin gets 403`
   - `SEC-08 browser POST with cookie, CSRF and own Origin passes`
   - `SEC-09 pair code is single use and expires after 60 s` (fake clock)
   - `SEC-10 token file is created with 43 chars and mode 0600 on POSIX` (on Windows, instead of the mode, run `icacls <file>` in the test and assert its output has no `BUILTIN\Users` or `Everyone` entry, which proves `/inheritance:r` applied; no `it.skip`; `createAuth` takes no injectable runner, so do not try to spy on it)
   - `SEC-11 restore rate limit returns 429 on the third call within a second for one session`
   - `SEC-12 every response has no-store, nosniff and no-referrer; HTML has the CSP`
   - `SEC-13 a paired browser session still passes checkBrowser after a new createAuth on the same stateDir, and browser-sessions.json contains no raw cookie or csrf`
   - `SEC-14 pair codes look like XXXX-XXXX, accept lower case and no dash, and die after 5 wrong attempts`
   - `SEC-15 csrfFor returns the same csrf pair() returned, also after a new createAuth; null for an unknown cookie; a csrf from another cookie fails checkBrowser`
