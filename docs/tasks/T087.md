# T087: `scripts/package.mjs`: build the npm package and the .vsix

Milestone M5 · Wave 8f · Depends on: T082-T086 · Runs on: any OS

## Goal

`node scripts/package.mjs` turns an already built tree (`pnpm -r build` ran) into
`release/mission-control-desktop-<v>.tgz` and `release/vscode-bridge-<v>.vsix`, laid out
exactly as `docs/PACKAGING.md` 2 says, and prints one summary line.

## Codes against

`docs/PACKAGING.md` 1, 2 (layout, esbuild options) and 5 (README text), `docs/DECISIONS.md`
D-39, D-40, D-43, D-44, PRD AC-15.

## Files

`scripts/package.mjs`, `packaging-test/package.test.mjs`, `.gitignore`, `eslint.config.js`, `.prettierignore`,
`docs/checkpoints/T087.md`.

## Do not touch

Every other file. In `eslint.config.js` touch only the global `ignores` list (add one entry), in
`.prettierignore` add one line. (The root `package.json`, `packages/*/package.json`, `vitest.workspace.ts`,
`scripts/gates.json` and `scripts/test-ids.json` have other owners). The script only reads
the repo and writes under its output directory and, through `vsce`, one `.vsix` in
`packages/vscode-bridge/dist/`.

## Steps

1. `.gitignore`: append one line, `release/`. `eslint.config.js`: add `"release/**"` to the
   global `ignores` array (the block that holds `"**/dist/**"`), nothing else. `.prettierignore`:
   append the line `release`. (Without these, `release/pkg/ui/assets/*.js` and
   `release/pkg/macos-scripts/*.js` fail lint and format after `pnpm package`.)
2. `scripts/package.mjs` is plain ESM Node (`node:` builtins only, no new dependency).
   Constants: `ROOT` = repo root (`scripts/..`), `VERSION` = `version` of the root
   `package.json`. Arguments: `--out <dir>` (default `<ROOT>/release`, resolved to absolute);
   anything else, or `--out` without a value, prints
   `usage: node scripts/package.mjs [--out <dir>]` to stderr and exits 2. Failures print
   `PACKAGE FAIL <reason>` to stderr and exit 1. Helper `sh(cmd, args, cwd)` is
   `spawnSync(cmd, args, { cwd, encoding: "utf8", shell: process.platform === "win32" })`
   and fails the script on a non-zero status, showing the child's stderr.
3. Preconditions (fail with `PACKAGE FAIL missing <path>: run pnpm -r build`): these exist:
   `packages/cli/src/mc.ts`, `packages/daemon/src/bin.ts`, `packages/hook/src/mc-hook.ts`,
   `packages/ui/dist/index.html`, `packages/vscode-bridge/dist/extension.cjs`, and the
   built `dist/index.js` of `contracts`, `core`, `platform` (esbuild resolves `@mc/*`
   through them).
4. Work area: `<out>/pkg` is deleted and recreated; stale `<out>/mission-control-desktop-*.tgz`
   and `<out>/vscode-bridge-*.vsix` are deleted. `<out>` is created if absent.
5. Externals, derived and never hand-written: start from the packages `cli`, `daemon`,
   `hook` (directory `packages/<name>`). Read each `package.json` `dependencies`; for every
   key that starts with `@mc/`, follow it to `packages/<name after @mc/>` and read that one
   too (visit each once). Every key not starting with `@mc/` is an external, recorded with
   the directory of the package that declares it. `ui` is not visited (it is copied, not
   bundled). For each external read `<declaring package dir>/node_modules/<name>/package.json`
   (this is the installed copy; do not resolve from the root, `ajv` differs there) and take
   its `version`; a missing file is `PACKAGE FAIL not installed: <name>`. Result today:
   `@fastify/cookie`, `@fastify/static`, `@fastify/websocket`, `ajv`, `ajv-formats`,
   `dbus-next`, `fastify`, `koffi`, `ws`.
6. esbuild through its JS API: `import * as esbuild from "esbuild";` (esbuild is a root devDependency, added by T080). For each entry run
   `await esbuild.build({ entryPoints: [<entry>], outfile: <out>/pkg/dist/<name>.js,
   bundle: true, platform: "node", format: "esm", target: "node22", external: <externals>
   (the names plus each name + "/*"), define: { __MC_PACKAGE__: JSON.stringify({ version:
   VERSION }) }, banner: { js: <the banner line of PACKAGING.md 2, written as one line> },
   logLevel: "error" })`. Entries: `packages/cli/src/mc.ts` -> `mc.js`,
   `packages/daemon/src/bin.ts` -> `daemon.js`, `packages/hook/src/mc-hook.ts` -> `mc-hook.js`.
   The banner line is exactly
   `import { createRequire as __mcCreateRequire } from "node:module"; const require = __mcCreateRequire(import.meta.url);`
   (esbuild keeps an entry's `#!` line first, above the banner).
7. Copy (use `cpSync` with `recursive: true`):
   `packages/ui/dist` -> `pkg/ui`; `packages/platform/src/windows/ps` (the `*.ps1` files) -> `pkg/ps`;
   `packages/platform/src/macos/scripts` (every file) -> `pkg/macos-scripts`;
   `packages/platform/assets/icon-256.png` -> `pkg/assets/icon-256.png`;
   `packages/cli/assets/shell/mc.ps1`, `mc.bash`, `mc.zsh` -> `pkg/shell/`;
   `packages/contracts/schemas/*.json` -> `pkg/schemas/`.
8. The `.vsix`: delete any `packages/vscode-bridge/dist/*.vsix`, run `pnpm --dir <ROOT> --filter
   vscode-bridge run package` (the script T080 put in the bridge manifest; it runs
   `vsce package --no-dependencies --allow-missing-repository --skip-license` and writes
   `packages/vscode-bridge/dist/vscode-bridge-<bridge version>.vsix`). Expect exactly
   `packages/vscode-bridge/dist/vscode-bridge-<VERSION>.vsix`; if absent fail with
   `PACKAGE FAIL vsix not found`. Copy it to `<out>/pkg/vscode-bridge.vsix` and to
   `<out>/vscode-bridge-<VERSION>.vsix`.
9. `pkg/package.json`, written with `JSON.stringify(obj, null, 2) + "\n"`, keys in this order:
   `name` `"mission-control-desktop"`, `version` VERSION, `description`
   `"Mission Control: local daemon, mc CLI and agent hooks"`, `type` `"module"`, `bin`
   `{ "mc": "dist/mc.js", "mc-hook": "dist/mc-hook.js" }`, `engines` `{ "node": ">=22" }`,
   `dependencies` (the externals with their exact installed versions, no `^`, keys sorted),
   `files` `["dist", "ui", "ps", "macos-scripts", "assets", "shell", "schemas", "vscode-bridge.vsix"]`.
10. `pkg/README.md`: a title `# mission-control-desktop <VERSION>` and the text of
    PACKAGING.md 5 (install block, upgrade, node switch, uninstall) with `<v>` replaced by
    VERSION, so it contains the literal lines `npm i -g ./mission-control-desktop-<VERSION>.tgz`,
    `mc install claude-code`, `mc stop` and `npm rm -g mission-control-desktop`.
11. Pack: `npm pack --pack-destination <out>` run with `cwd` `<out>/pkg`. The tarball must
    be `<out>/mission-control-desktop-<VERSION>.tgz` (else `PACKAGE FAIL tarball not found`).
12. Last output line (stdout), exactly `PACKAGE mission-control-desktop-<VERSION>.tgz <bytes>`
    where `<bytes>` is `statSync(tarball).size`. Print nothing after it, exit 0.
13. Tests in `packaging-test/package.test.mjs` (vitest, `import { test, expect, beforeAll,
    afterAll } from "vitest"`, same style as `scripts/test/gate.test.mjs`). Shared setup:
    - `ROOT`, `VERSION` as above; `OUT = mkdtempSync(join(tmpdir(), "mc-pack-"))`, removed in `afterAll`.
    - the tree is already built: the `package` gate stage and the acceptance command run
      `pnpm -r build` first. Do not build inside the test.
    - then run `node scripts/package.mjs --out OUT` once with `spawnSync`, keep status, stdout, stderr.
    - the `packaging` Vitest project has `testTimeout` 600000; still pass `600_000` as the
      `beforeAll` timeout (second argument) and nothing else per test.
    - the tarball listing: `spawnSync("tar", ["-tzf", "mission-control-desktop-<VERSION>.tgz"], { cwd: OUT })`
      with a relative file name (an absolute `C:\` path breaks GNU tar), lines trimmed, `\` to `/`.
    Titles exactly:
    - `PK-01 package.mjs exits 0 and its last line is PACKAGE <tgz name> <bytes> with the real file size`
    - `PK-02 the tarball contains exactly the PACKAGING.md 2 layout and nothing else`
    - `PK-03 the generated package.json has the pinned name, version, bin, engines, files and exact-version dependencies`
    - `PK-04 no bundle still imports an @mc/ package`
    - `PK-05 __MC_PACKAGE__ is defined away in the bundles and the version is inlined`
    - `PK-06 the externals stay imports in the bundles and the hook keeps its shebang`
    - `PK-07 the vsix is a zip, identical in release/ and in the package, and README names the install commands`
    - `PK-08 a bad flag exits 2 with usage and an --out without a value exits 2`

    Assertions:
    - PK-01: status 0; last non-empty stdout line matches
      `^PACKAGE mission-control-desktop-<VERSION>\.tgz (\d+)$` and the number equals
      `statSync(join(OUT, tgz)).size`.
    - PK-02: every entry starts with `package/`. After stripping it, the set contains
      `package.json`, `README.md`, `dist/mc.js`, `dist/daemon.js`, `dist/mc-hook.js`,
      `ui/index.html`, `assets/icon-256.png`, `shell/mc.ps1`, `shell/mc.bash`, `shell/mc.zsh`,
      `vscode-bridge.vsix`, every `*.ps1` found in `packages/platform/src/windows/ps` as
      `ps/<name>`, every file of `packages/platform/src/macos/scripts` as `macos-scripts/<name>`,
      every `*.json` of `packages/contracts/schemas` as `schemas/<name>`, and at least one entry
      starting with `ui/assets/`. Every entry starts with one of `package.json`, `README.md`,
      `dist/`, `ui/`, `ps/`, `macos-scripts/`, `assets/`, `shell/`, `schemas/`, `vscode-bridge.vsix`;
      none contains `node_modules/`, `/src/` or ends in `.map`.
    - PK-03: parse `OUT/pkg/package.json`: `name` `mission-control-desktop`; `version` VERSION;
      `type` `module`; `bin` deep-equals `{ mc: "dist/mc.js", "mc-hook": "dist/mc-hook.js" }`;
      `engines` `{ node: ">=22" }`; `files` deep-equals the array of step 9;
      `Object.keys(dependencies)` equals `["@fastify/cookie", "@fastify/static",
      "@fastify/websocket", "ajv", "ajv-formats", "dbus-next", "fastify", "koffi", "ws"]`;
      every value matches `^\d+\.\d+\.\d+` and has no `^` or `~`.
    - PK-04: for `mc.js`, `daemon.js`, `mc-hook.js` in `OUT/pkg/dist`, no match of
      `/(from\s*|import\s*\(\s*|require\s*\(\s*)["']@mc\//`.
    - PK-05: the three bundles do not contain the text `__MC_PACKAGE__`; `mc.js` and `daemon.js`
      each match `new RegExp('version:\\s*"' + VERSION.replace(/\./g, "\\.") + '"')`
      (esbuild prints the inlined define as an object literal; if the printed form differs,
      adapt the regex to the real output and note it in the checkpoint).
    - PK-06: `daemon.js` contains `from "fastify"` and `from "ws"` and does not contain
      `node_modules/fastify`; `mc-hook.js` starts with `#!/usr/bin/env node`; all three contain
      the string `__mcCreateRequire`.
    - PK-07: `OUT/vscode-bridge-<VERSION>.vsix` and `OUT/pkg/vscode-bridge.vsix` both exist,
      start with bytes `50 4b 03 04`, and are byte-identical (`Buffer.equals`); the text of
      `OUT/pkg/README.md` contains `npm i -g ./mission-control-desktop-<VERSION>.tgz`,
      `mc install claude-code` and `npm rm -g mission-control-desktop`.
    - PK-08: `node scripts/package.mjs --bogus` and `node scripts/package.mjs --out` each exit 2
      and print `usage:` on stderr, and neither creates anything (use a fresh temp `--out`
      for the second and check the directory is not created).
