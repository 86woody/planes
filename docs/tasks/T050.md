# T050: `mc` CLI: start, stop, status, daemon, open, restore, token, doctor

Milestone M4 · Wave 5 · Depends on: T027 · Runs on: any OS

## Goal

The command Woody types: run the daemon in the background or foreground, open the
paired page, restore from a notification click, rotate the token, and diagnose
permissions and dependencies per OS.

## Steps

1. `main.ts`: `run(argv, io)` dispatch; `mc --help` lists commands; unknown -> exit 2.
2. `start`: if `daemon.json` pid is alive and healthz matches, print
   `already running pid=<pid> port=<port>`, exit 0. Else spawn
   `process.execPath <repoRoot>/packages/daemon/dist/bin.js` with `detached: true,
   windowsHide: true, stdio: "ignore"`, `unref()`, poll `daemon.json` + healthz up to
   5 s, print `started pid=<pid> port=<port>`; timeout -> exit 1 with the last 20 lines
   of `daemon.log`.
3. `stop`: POSTs nothing; sends `SIGTERM` (POSIX) to the daemon.json pid and waits up
   to 5 s for the file to disappear. Windows: the daemon is windowless, so a plain
   `taskkill /pid <pid>` (WM_CLOSE) cannot end it and Node has no SIGTERM there; run
   `taskkill /pid <pid> /F`, wait for the process to exit, then delete `daemon.json`
   yourself (the forced kill skips `stop()`; at most the last 500 ms of the debounced
   snapshot is lost, which `events.jsonl` does not replay in v1). Prints `stopped`.
4. `status`: healthz + `/api/state` with the bearer token; prints one line per session
   `MC-07  HOLD        schmux      VS CODE      2m` and a header line
   `daemon pid=<pid> port=<port> sessions=<n>`; exit 1 if not running.
5. `daemon`: foreground (`startDaemon({foreground: true})`), for systemd/launchd.
6. `open`: start if needed, `POST /api/pair-code`, copy the code to the clipboard
   (`clip.exe` via stdin on Windows, `pbcopy`, `wl-copy` or `xclip -selection clipboard`
   on Linux; skip silently if none), print `PAIR CODE  XXXX-XXXX  (copied; valid 60 s)`,
   then open `http://127.0.0.1:<port>/` (no code in the URL, D-05) with the OS opener
   (`cmd /c start "" <url>`, `open <url>`, `xdg-open <url>`). `--print` prints the URL
   and the code line and opens nothing (for tests). `--no-pair` opens the page only (an
   already-paired browser needs no code; sessions persist 30 days).
7. `restore <id|mission-control://restore/<id>|mission-control://open> [--from-notification]`:
   parse; on Windows with `--from-notification` call koffi
   `AllowSetForegroundWindow(0xFFFFFFFF)` first; POST restore with
   `{"source": "notification"}`; result `failed` or `open` -> run `open --no-pair` behaviour
   (page with highlight comes from the daemon). Exit 0 unless the daemon is down (1).
8. `token rotate`: if the daemon is running, run `stop` first (otherwise its `stop()`
   would `auth.flush()` the old sessions back to disk after the delete); then rewrite
   the token file (same rules as T015), delete `browser-sessions.json`, print
   `token rotated; daemon stopped. run mc start, then mc open to pair browsers again`.
   (Old CSRFs die with the token anyway: they are HMACs under it, api.md 2.)
9. `doctor`: run the checks for the current OS from the platform docs' doctor tables
   (plus: daemon reachable, hook installed in Claude settings, config valid) and print
   `OK|MISSING|WARN <check>  <fix>`; exit 1 if any required check is MISSING.
   Checks are data: `lib/doctor-checks.ts` exports `checksFor(os)` returning
   `{id, required, run(): Promise<"ok"|"missing"|"warn">, fix}` so tests can inject.
10. Tests (temp `MC_HOME`, `MC_PORT=0`, `MC_PLATFORM=fake`, built daemon), titles exactly:
    - `CLI-01 start launches the daemon and prints started pid= port=`
    - `CLI-02 start when running prints already running and exits 0`
    - `CLI-03 status prints the daemon line and one line per session`
    - `CLI-04 stop removes daemon.json within 5 s`
    - `CLI-05 open --print prints a URL with no code in it and a PAIR CODE line whose code /api/pair accepts once`
    - `CLI-06 restore with a mission-control:// URI calls the fake focus with source notification`
    - `CLI-07 restore of an unknown id exits 0 and falls back to open`
    - `CLI-08 token rotate changes the token file and old bearer requests get 403 after restart`
    - `CLI-09 unknown command exits 2 with usage`
    - `CLI-10 status with the daemon down exits 1`
    - `DR-01 doctor exits 0 when every required check is ok`
    - `DR-02 doctor exits 1 and prints MISSING with the fix text when a required check fails`
    - `DR-03 windows checks include PowerShell 5.1, AUMID, protocol, notifications enabled`
    - `DR-04 macos checks include Automation, Accessibility and the responsible process`
    - `DR-05 linux checks follow the selected backend's tools`
    - `DR-06 doctor reports whether the Claude Code hooks are installed`
