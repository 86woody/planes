# T012 checkpoint

## What works

- `classifyHost(origin)` in `packages/core/src/classify.ts`: rules 1-11 in order, with
  `VSCODE_NAMES`, `SHELL_NAMES`, `LINUX_TERMINALS` exported. Names are normalised
  (lower-case, `.exe` stripped). `multiplexer` and `display` follow the spec.
- `CallsignAllocator` in `packages/core/src/callsign.ts`: MC-01..MC-99 with wrap, skips
  in-use values, returns the next value when all 99 are in use, `counter()` returns the
  last issued number.
- `packages/core/test/classify.test.ts`: 16 tests with the exact CL-01..CL-16 titles.
  CL-16 validates each host by building a full Session and calling `validateSession`.

## What does not

- Nothing known to fail.

## Choices made where the spec was silent

- `app` for rules 2, 3 and 10 is the raw ProcessInfo name (e.g. `Code.exe`), not the
  normalised list entry. The schema example suggests the raw form.
- Rule 2's "no shell between" check uses the nearest VS Code entry above the agent.
- `electron` counts as a VS Code name only when its parent entry is another VS Code name.
- Env presence means `!== undefined`; an empty string counts as set.
- Multiplexer is set whenever TMUX and TMUX_PANE are present, even if the pane does not
  match the schema pattern (spec says so; the schema would then reject the host).

## Surprises

- The shell heredoc used to write the test file failed with an unmatched-quote error.
  The file was written with the Write tool instead.
- `validateSession` is the only exported validator; there is no Host-only validator, so
  CL-16 wraps the host in a full session fixture.
- To find the `IngestOrigin` shape I looked up its type in
  `packages/contracts/src/generated/ingest.ts`. That file is not in the task's reading list.
