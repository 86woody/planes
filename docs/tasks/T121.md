# T121: the session page: key values, model calls, runs, tools, permissions, subagents (D-58)

Milestone M5 · Wave 10b · Depends on: T119 · Runs on: any OS

## Goal

One page that explains one session's spending, tools, permissions and subagents, and lists its
agent runs so one can be opened as a trace.

## Steps

1. Export
   ```ts
   export function SessionView(p: {
     session: Session; board: BoardState; now: number; actions: BoardActions;
     onCopy(id: string): void;
     loadTraces?: (id: string) => Promise<TracesResponse | number>; // default api.traces
   }): JSX.Element
   ```
   Root: `<section className="pagev" data-testid="session-view" data-session={id} aria-labelledby="sv-h">`.
   Import `../session-view.css`.
2. The head, the no-telemetry block, the six key values, the model-call strip, runs, tools,
   permissions and input, subagents and footer facts exactly as DESIGN.md 3a says, with those testids.
   `sv-back` is `<a href="#/">← Fleet</a>`. Each key value is `<article className="kpi" data-testid="sv-kpi"
   data-k="<k>">` with `<h3>` label, `<b className="num">` value, `<small>` second line; an orange one gets
   class `over` and `data-over="true"` and keeps its word (`Over 85%`, `Error rate N%`, `waiting MM:SS`).
3. Runs: on mount and when `session.id` changes call `loadTraces(id)`; while `session.state` is not
   `ended` or `lost`, again every 5,000 ms (clear the interval on unmount). Keep the last good response
   when a later call fails, and show the failure line only when there was never a good one. Rows newest
   first (`runs` arrive newest last). Each row: `<tr data-testid="sv-run" data-trace={traceId}>`, the
   Started cell holds `<a href={routeHref({ page: "run", id, traceId })}>HH:MM:SS</a>` (local time),
   then the columns in DESIGN.md. Duration from `durationText(run.durationMs)`; Running runs show
   `durationText(now - Date.parse(run.startedAt))`.
4. Model calls: a `<div data-testid="sv-calls">` with one `<i className="bar" data-model="<index>"
   title="...">` per call (`data-failed="true"` on failed ones, `data-sub="true"` on subagent calls), the
   height as an inline `style={{ height: "<n>%" }}` (min 4%). The colour per model index comes from CSS:
   `[data-model="0"]` `--ink`, `1` `--ink2`, `2` `--ink3`, `3` `--go`, `4` and above set inline as
   `data-model="4"` -> `--ink4`; `[data-failed]` `--look`; `[data-sub]` `opacity: .5`. Legend
   `data-testid="sv-legend"`. No calls: "No model calls yet."
5. Layout in `session-view.css`: `.pagev { grid-column: 1 / -1; min-height: 0; overflow: auto;
   background: var(--card); border: 1px solid var(--hair); border-radius: var(--r-hero);
   padding: 22px 26px; }`; key values a 6-column grid (3 under 1180px, 2 under 760px); sections
   separated by 1px `--hair` rules with Geist 300 15px `--ink2` headings; tables like `.listv` (13px,
   `--hair` row lines, numbers right-aligned and tabular). No new colours: tokens only.

## Tests (`packages/ui/test/session-view.test.tsx`; `loadTraces` stubbed; fake timers for the 5 s refresh)

- `SD-01` a copilot-cli session with telemetry: six `sv-kpi` with `data-k` credits, tokens, rate, ctx,
  calls, waited, values from the telemetry (`12.35`, `3,000`, `1,234`, `≈42%`, `40`, `01:12`); `sv-age`
  says `12s ago` for an `updatedAt` 12 s before now.
- `SD-02` without telemetry: copilot-cli shows `No data yet`, shell `n/a`, claude-code `No data`, inside
  `sv-nodata`, and no `sv-kpi`.
- `SD-03` context 90 and 3 failed of 40 calls mark `ctx` and `calls` with `data-over="true"`; a pending
  permission with `pendingSince` 75 s ago makes `waited` read `waiting 01:15`.
- `SD-04` `sv-calls` draws one bar per recent call, the largest at 100%, a failed call with `data-failed`,
  two models with `data-model` 0 and 1, and the legend names both.
- `SD-05` runs: three runs arrive newest last and render newest first, a link to `#/s/<id>/run/<traceId>`,
  counts of chat spans and tool+skill spans, `Running` for an incomplete run, `Error` for an errored one;
  the loader is called again after 5,000 ms for a live session and not for an ended one; a 500 before any
  good answer shows `Could not load runs (500)`; an empty `runs` shows the "No traces yet" text.
- `SD-06` tools sorted by runs, a failed count above 0 marked; subagents hidden when empty, `≠ parent`
  shown when `modelMatches` is false.
