# T023 checkpoint: Notifier

## What works

- `packages/daemon/src/notifier.ts`: `createNotifier` implements `Notifier` (start, test, stop).
  - `start()` subscribes to `sessions.onChange`; each upsert is checked for foreground
    (`foregroundWindow()` vs the record's `target.window.handle`), local minutes, then
    `decide(prev, next, ctx)`. A send goes through the `Coalescer`; each released
    notification is shown via `platform.notify`, remembered per session, broadcast as
    `notify`, and (when handle and sessionId are set) applied as `notified`.
  - Attention cleared: `platform.withdraw(handle)` and forget the handle.
  - Renotify tick every 30 s via `decideRenotify`, not through the coalescer.
  - Coalescer flush tick every 1 s.
  - `onClick(sessionId)`: null does nothing; otherwise `focus.restore(id, "notification")`,
    and a `failed` result broadcasts `highlight`.
  - `test()` sends the COMMS CHECK notification directly and reports `{sent, backend}`.
  - `stop()` clears both intervals and unsubscribes.
- `packages/daemon/test/notifier.test.ts`: NT-01 to NT-08, fake timers, `FakePlatform`,
  in-memory SessionService double, fake FocusService. No real notifications are raised.

## What does not

- Nothing in the task scope is left open. Acceptance, typecheck and lint pass.

## Surprises

- The task says the SessionService double has only `onChange`, `get`, `list`, but step 1
  calls `sessions.apply({kind: "notified", ...})`. The double also implements `apply`
  (a recorder), and the test cast is `as unknown as` for the deps object.
- `FakePlatform` records `notify` args without the onClick callback (platform-adapter.md 5),
  so NT-07 and NT-08 assert `args` without a function matcher.
- The upsert handler takes `prev` from the `SessionChange` event; `decide` needs it for NP-04.
- Withdrawal happens before the `decide` call and returns early when attention is inactive.
  NP-03 would return `no_change` anyway, so this only adds the withdraw.
