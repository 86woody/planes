# T114 checkpoint: the daemon's Copilot account service over the SDK (D-56)

Branch `task/T114-copilot-account`, host dev-pc. No push, merge or rebase.

## What works

- `@github/copilot-sdk` 1.0.34 added to `packages/daemon/package.json` with `--save-exact` (committed separately; pnpm also re-sorted the dependency list).
- `copilot-sdk-client.ts`: `CopilotAccountClient` interface and `createSdkClient()`. The SDK is loaded with a dynamic `import()` on first use. `status()` maps `getStatus().version` to `runtimeVersion`. `quota()` calls `rpc.account.getQuota({})` and never passes `gitHubToken`. No session calls.
- `copilot-account.ts`: `createCopilotAccount(deps, {client, refreshMs = 300000, onChange})`.
  - `start()` starts the client once, refreshes now, then on an unref'd interval. A refresh that is still running is skipped.
  - Quota comes from the snapshot with a numeric `entitlementRequests`, preferring a key matching `premium` or `credit`.
  - `nanoAiuToday` sums `telemetry.credits.nanoAiu` for sessions whose `updatedAt` is on today's local date. `aiCreditsToday` is always null.
  - Forecast uses a 7-day window of `(time, used)` samples. It needs two samples at least 1 h apart plus a `resetDate` and an entitlement above 0.
  - `error` is the first failure of the refresh, redacted for `gh[opsu]_` and `github_pat_` tokens, then cut to 200 characters. Other fields keep their last values.
  - `onChange` fires when the content changes, ignoring `updatedAt`. Without that, every 5-minute refresh would broadcast.
  - `stop()` clears the timer and calls `client.stop()` if `start()` was ever called. `current()` returns the last result.
- `internal.ts`: `copilot: { current(): CopilotAccount | null }` added to `DaemonDeps` only.
- `routes/api.ts`: `daemonInfo()` sets `copilot: deps.copilot.current()`.
- `main.ts`: when `MC_TEST=1` or `MC_COPILOT_SDK=0`, the service is a no-op that returns null, and no client is made. Otherwise it is created with `createSdkClient()` after the telemetry service. `onChange` broadcasts `{type: "daemon.update"}`. It starts beside `telemetry.start()`, is stopped in shutdown after telemetry, and is registered in the startup-undo cleanups.
- Tests `TA-01`..`TA-05` in `packages/daemon/test/copilot-account.test.ts` pass with a fake client, fake timers and the manual clock from `test/support/deps.ts`. TA-01 validates a `daemon.update` built with `daemonInfo()` against `validateWsServerMessage`.

## What does not

- Nothing in the spec is left undone. The D-57 CR (the `copilot` stub in `test/support/deps.ts`) is applied, as the orchestrator accepted.
- Full daemon suite: `pnpm vitest run packages/daemon` gives 118/118 passing across 17 files.

## Deviations and notes

- `start()` returns void and `stop()` returns a Promise, as `docs/contracts/internal.md` section 2 says. The task text does not name the return types.
- `entitlementRequests` of -1 (unlimited) maps to `entitlement: null`. The contract says `minimum: 0`, so -1 would fail the schema.
- `planTier` is read from a `planTier` key on the quota result. The SDK's `AccountGetQuotaResult` has no such field, so `planTier` is null in practice.
- The forecast is not clamped. A `used` drop inside the window (after a reset) gives a negative rate, as the spec's literal formula does.
- `error` is redacted and then cut, so a token cannot survive the cut.

## Surprises

- The SDK's `AccountGetQuotaResult` has no plan field, and `getStatus()` gives `version` and `protocolVersion`, not `runtimeVersion`. Both mappings are in `copilot-sdk-client.ts`.
- `models.listTokenPriceUnits` (below) reports `ai_credits` for every model, so nano-AIU conversion may not be needed for prices. `aiCreditsToday` stays null, as D-56 item 4 says, until someone decides how to use this.
