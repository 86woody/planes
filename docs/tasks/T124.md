# T124: `mc uninstall --all [--purge]`; the untested uninstalls get tests (D-59)

Milestone M5 · Wave 11 · Depends on: T118 · Runs on: any OS

## Goal

One command removes everything mission-control added to the machine, so that after it
`npm rm -g mission-control-desktop` leaves nothing behind. `uri-handler` and `autostart`
uninstall, untested so far, get tests.

## Steps

1. `uninstall.ts` keeps `mc uninstall <target>` exactly as it is. New forms: `mc uninstall --all` and
   `mc uninstall --all --purge` (flags in either order). Anything else with `--all` or `--purge`
   (an extra word, `--purge` alone, `--all` with a target) prints the usage and exits 2. The usage
   becomes `usage: mc uninstall <claude-code|codex|copilot|shell|uri-handler|autostart|vscode> | --all [--purge]`.
2. `--all`, in order:
   1. Stop the daemon: `stopDaemon(resolveCliPaths(io.env), io)`. Print `daemon: stopped` or
      `daemon: not running`. If it fails, print `daemon: could not stop` and exit 1 before touching
      anything else.
   2. Read the manifest. The targets to run are, in this fixed order, `vscode`, `autostart`,
      `uri-handler`, `shell`, `codex`, `copilot`, `claude-code`: every one that has a manifest
      entry, plus `claude-code`, `copilot`, `codex` and `shell` always (their uninstall finds our
      entries in the files even without a manifest entry, and changes nothing when there are none).
      A manifest that cannot be read: print `manifest: <message>`, run only those four, and treat the
      run as failed.
   3. Run each target's existing handler with the same `ctx`. Catch per target: a thrown error or a
      non-zero exit prints `<target>: failed: <message or "exit N">` and the run continues with the
      next target. Success prints `<target>: removed`.
   4. Without `--purge`: print `left in place: <configDir>` and `left in place: <stateDir>` (each only
      if it exists) and `mc uninstall --all --purge also deletes them`.
   5. With `--purge` and every target succeeded: delete `ctx.stateDir` and `ctx.configDir`
      (`rmSync` recursive, force) and print `deleted <dir>` for each. Guard first: refuse (print
      `purge: refusing to delete <dir>`, exit 1) unless the directory's basename is `mission-control`,
      or, when `MC_HOME` is set, it is exactly `<MC_HOME>/state` or `<MC_HOME>/config`. With `--purge`
      and any failure: delete nothing, print `purge skipped: fix the failures above and run again`.
   6. Exit 0 when the daemon step and every target succeeded (and the purge, when asked), else 1.
   7. Last line on success: `mission-control removed. Now run: npm rm -g mission-control-desktop`.
3. `main.ts`: the `uninstall` line of `USAGE` reads `uninstall <what>|--all  remove what install added`.

## Tests

`packages/cli/test/uninstall-all.test.ts` (temp `MC_HOME`, temp home, injected fake `run`; no real
registry, editor, shell profile or window; reuse the helpers of `install-other.test.ts`):

- `UA-01` with claude-code, copilot, codex, shell, uri-handler (win32), autostart (win32) and vscode
  installed through the real install commands with the fake `run`: `--all` exits 0; the seeded
  Claude settings, Copilot hooks dir, Codex config and shell profile are byte-for-byte their seeded
  content (or absent if they did not exist); the fake `run` saw the uri-handler unregister commands,
  `reg.exe delete` of the autostart Run value and `code --uninstall-extension`; the manifest has no
  entries; output has `<target>: removed` for each.
- `UA-02` `mc uninstall uri-handler`: win32 runs the unregister commands and removes `restore.vbs`;
  linux removes the desktop file and runs `update-desktop-database`; the manifest entry is gone; not
  installed -> exit 0 and no `run` calls.
- `UA-03` `mc uninstall autostart`: win32 (`reg.exe delete`, vbs removed), linux systemd (unit
  removed), linux xdg (desktop file removed), darwin (plist removed); each manifest entry is gone.
- `UA-04` a fake `run` that fails `code --uninstall-extension`: the other targets still run and are
  removed, `vscode: failed:` is printed, exit 1; with `--purge` both directories still exist and
  `purge skipped` is printed.
- `UA-05` `--all --purge` after success deletes `<MC_HOME>/config` and `<MC_HOME>/state`, and a file
  next to them in `MC_HOME` survives; `--all` alone keeps both and prints both `left in place:` lines.
- `UA-06` a daemon started in `MC_HOME` (as `cli.test.ts` starts one) is stopped by `--all` before the
  targets run: `daemon: stopped` comes first and `daemon.json` is gone.
- `UA-07` usage: `--purge` alone, `--all copilot`, `--all --purge extra` exit 2 with the usage line;
  `mc uninstall copilot` still works as before.

`packaging-test/install.test.mjs`:

- `SK-08` in the SK prefix and `MC_HOME`: `mc install claude-code` and `mc install copilot` (with
  `COPILOT_HOME` set to a temp dir), then `mc uninstall --all --purge` exits 0, then
  `npm rm -g mission-control-desktop --prefix <prefix>` exits 0. After it: no `mc` shim and no
  `mission-control-desktop` folder under the prefix; `<MC_HOME>/config` and `<MC_HOME>/state` do not
  exist; the seeded Claude settings file equals its seeded content; the Copilot hooks dir has no
  `mission-control.json`. Run it last in the file (after SK-07), on its own prefix if SK-05/06 need
  theirs.
