# T095: RW-08 passes whether or not the UI has been built

Milestone M5 · Wave 8h · Depends on: T082 · Runs on: any OS

## Goal

RW-08 (`packages/daemon/test/layout-wiring.test.ts`) GETs `/` from an in-process daemon and
expects 200. The gate's `daemon` stage (m1) runs before `ui-build` (m2), so on a fresh clone
`packages/ui/dist` does not exist yet and the daemon correctly answers 503 "UI not built".
That failed the Linux gate on 2026-11-15. After this task, RW-08 still proves that the
daemon takes `uiDir` from `layout()`, in both states.

## Codes against

`docs/PACKAGING.md` 3 (`layout().uiDir`), `docs/DECISIONS.md` D-40.

## Files

`packages/daemon/test/layout-wiring.test.ts`, `docs/checkpoints/T095.md`.

## Do not touch

Product code. Every other test in the file. Keep RW-08's title and its source-text
expects.

## Steps

1. In RW-08, compute `const built = existsSync(path.join(layout().uiDir, "index.html"))`
   before starting the daemon.
2. If `built`, keep today's expects: status 200, the body matches `/<html/i`, and it does
   not contain "UI not built". Otherwise expect status 503 and a body containing
   "UI not built". Both branches must expect on the HTTP status and body the daemon
   produced.
3. Prove both branches by running the acceptance command twice: once as written (the UI is
   built first), and once after `rm -rf packages/ui/dist` with only
   `pnpm --filter "@mc/daemon..." build && pnpm vitest run packages/daemon/test/layout-wiring.test.ts`
   (no UI build). Record both outputs in the checkpoint, then rebuild.
