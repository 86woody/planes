# T115: `mc doctor copilot` proves the Copilot SDK runtime on one PC (D-56)

Milestone M5 · Wave 9a · Depends on: T050 · Runs on: any OS

## Goal

One command that says if the Copilot SDK runtime works on this PC: `mc doctor copilot [--live]`.
It prints one line per check and exits 1 when a check fails.

## Codes against

`docs/DECISIONS.md` D-56 (items 2 and 5); `docs/research/telemetry-metrics.md` section 11 (checks
D1-D10); the SDK's own types in `node_modules/@github/copilot-sdk/dist/*.d.ts` and its `README.md`.

## Files

`packages/cli/src/commands/doctor.ts` (the `copilot` subcommand only),
`packages/cli/src/lib/doctor-copilot.ts`, `packages/cli/package.json` (dependency
`@github/copilot-sdk` `1.0.34`, exact), `pnpm-lock.yaml`, `packages/cli/test/doctor-copilot.test.ts`,
`docs/checkpoints/T115.md`.

## Steps

1. `pnpm --filter @mc/cli add @github/copilot-sdk@1.0.34 --save-exact`.
2. `mc doctor` with no arguments is unchanged. `mc doctor copilot` runs D1-D9; `--live` adds D10;
   any other argument prints `usage: mc doctor [copilot [--live]]` and exits 2.
3. Output, one line per check: `PASS|FAIL|WARN|SKIP D<n> <label>  [<detail>]`; then
   `DOCTOR COPILOT PASS <passed>/<run>` or `DOCTOR COPILOT FAIL <passed>/<run>` (SKIP not counted
   in `<run>`). Exit 1 if any FAIL, else 0.
4. Checks, in order (research note 11): D1 Node version >= 22.12; D2 `@github/copilot-sdk` resolves
   and its platform runtime package for `process.platform`/`process.arch` is present (read
   `package.json` `optionalDependencies` of the SDK to find the name); D3 `new CopilotClient()` then
   `start()` and `getStatus()` give a version (detail: `runtime <v> protocol <p>`); D4 runtime version
   equals `copilot --version` (WARN when different or when `copilot` is not on PATH); D5 signed in
   (use the SDK's auth status call; not signed in = SKIP with detail `not signed in`); D6 `listSessions()`
   ids equal the folder names in `<COPILOT_HOME or ~/.copilot>/session-state` (WARN when they differ,
   detail = the two counts); D7 `client.rpc.account.getQuota({})` gives a result and `listModels()`
   (or `rpc.models.list`) gives at least one model (SKIP when D5 skipped); D8 the newest
   `events.jsonl` parses line by line (detail: lines, bad lines; never print a line); D9 pick the
   newest session folder whose `events.jsonl` has a `session.shutdown` line, record size and SHA-256,
   `resumeSession(id, {suppressResumeEvent: true, allowTranscriptRecovery: false, enableSessionTelemetry: false})`,
   `getEvents()`, disconnect, and PASS only when size and hash are unchanged (SKIP when no ended
   session); D10 (only `--live`) spawn `copilot -p "Reply with the single word ok"` in a new temp folder
   with `COPILOT_OTEL_FILE_EXPORTER_PATH=<temp>/otel.jsonl` set on that child only, timeout 120 s; PASS
   when the file has at least one `span` record and one `metric` record whose
   `gen_ai.conversation.id` (spans) matches a new session folder.
5. Load the SDK with a dynamic `import()` inside `doctor-copilot.ts`, so other `mc` commands never load
   it. Always `stop()` the client in a `finally`. Never print a token, a config value or a line of any
   events file. Never pass `gitHubToken`.
6. Make the SDK client and the `copilot` spawn injectable (`runCopilotDoctor(io, deps)`), so tests use fakes.

## Tests (`packages/cli/test/doctor-copilot.test.ts`, fakes only; no real runtime, no prompt)

- `DC-01` all fakes healthy: every check PASS (D10 not run), last line `DOCTOR COPILOT PASS 9/9`, exit 0.
- `DC-02` `start()` throws: D3 FAIL with the message, later SDK checks SKIP, exit 1.
- `DC-03` not signed in: D5 and D7 SKIP, exit 0.
- `DC-04` D9: a fake attach that appends to the temp `events.jsonl` makes D9 FAIL; one that does not makes it PASS.
- `DC-05` usage: `mc doctor copilot --bogus` exits 2 with the usage line; `mc doctor` output is unchanged.

Tests set `COPILOT_HOME` and `MC_HOME` to temp folders.
