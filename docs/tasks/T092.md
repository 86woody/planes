# T092: `mc init` and `mc launch`

Milestone M5 · Wave 8f · Depends on: T085, T086 · Runs on: any OS

## Goal

After `npm i -g ./mission-control-desktop-<v>.tgz`, `mc init` asks which agents to connect
and installs them (plus the support installers that apply), and `mc launch` starts the
daemon if needed and opens the page. Both only sequence existing commands.

## Codes against

`docs/DECISIONS.md` D-46, D-41 items 4 and 6, `docs/PACKAGING.md` 5. Existing code you call:
`commands/install.ts` (`INSTALL_TARGETS`), `installers/manifest.ts` (`makeCtx`, `CtxInput`
with its injectable `onPath`, `readManifest`), `installers/{copilot,claude,codex}.ts`
(`installCopilot`, `installClaude`, `installCodex`), `installers/uri.ts` (`installUri`),
`installers/vscode.ts` (`installVscode`, T086), `commands/start.ts` (`run`, with T085's
`healLaunchers`) and `commands/open.ts` (`run`).

## Files

`packages/cli/src/commands/{init,launch}.ts`, `packages/cli/test/init-launch.test.ts`, in
`packages/cli/src/main.ts` only the two `import` lines, the two `COMMANDS` entries and the
two `USAGE` lines for `init` and `launch`, and `docs/checkpoints/T092.md`.

## Do not touch

`commands/{install,start,open}.ts`, `installers/**`, `lib/**`, every other line of

## Steps

1. `commands/init.ts`. Export:
   - `export const AGENTS = [{ key: "copilot", label: "GitHub Copilot CLI", manifestKey: "copilot-cli" }, { key: "claude-code", label: "Claude Code", manifestKey: "claude-code" }, { key: "codex", label: "Codex", manifestKey: "codex" }] as const;`
     The order is the menu order, and `DEFAULT_AGENTS = ["copilot"]` is the pre-selection.
   - `export function parseInitArgs(argv: string[]): { agents: string[] | null } | string`: accepts only `--agents <list>` or `--agents=<list>`. The list is split on `,`, trimmed,
     lower-cased and de-duplicated, and every entry must be an `AGENTS` key. Otherwise the error is `usage: mc init [--agents copilot,claude-code,codex]` (also for an unknown flag, a missing value or an empty list).
   - `export interface InitDeps { stdin: NodeJS.ReadableStream; stdout: NodeJS.WritableStream; isTTY: boolean }`, defaulting to `process.stdin`, `process.stdout` and `process.stdin.isTTY === true`.
   - `export async function promptAgents(deps: Pick<InitDeps, "stdin" | "stdout">): Promise<string[] | null>`: uses `readline.createInterface({ input, output, terminal: false })` and writes
     ```
     Connect which agents? Type numbers separated by commas; Enter accepts [1].
       1) GitHub Copilot CLI  (default)
       2) Claude Code
       3) Codex
     >
     ```
     (the `(default)` marker comes from `DEFAULT_AGENTS`; the last line is the prompt `> `). It reads one line and returns the keys. Empty or whitespace-only input returns `DEFAULT_AGENTS`; `"2,3"` returns
     `["claude-code","codex"]` in menu order; numbers may be separated by commas and/or spaces, and duplicates collapse. An input with a number outside `1..3` or a non-number writes
     `not a choice: <input>` and asks again, at most three times, then returns `null`. End of input before any line returns `null`. The interface is always closed.
   - `export async function run(argv: string[], io: Io, input: Partial<CtxInput> & Partial<InitDeps> = {}): Promise<number>`:
     1. `parseInitArgs`; on a string, `io.err(msg)` and return 2.
     2. No `--agents` and `!(input.isTTY ?? process.stdin.isTTY === true)`: `io.err("usage: mc init [--agents copilot,claude-code,codex] (no terminal to ask on)")`, return 2. No installer ran.
     3. No `--agents` with a TTY: `promptAgents`; `null` gives the same usage line and return 2.
     4. Selected agents run in menu order (not input order), then the support steps. Each target gets its own `makeCtx(captured, { ...input, dryRun: false })`, where `captured.out` and `captured.err` collect into strings
        (the installers' own lines are not echoed; `io` supplies `env` and `cwd`). Status per target, with `had = readManifest(ctx)[manifestKey] !== undefined` read before the call:
        - exit code 0: `installed` when `!had`, else `repaired` (an installer run on an already-current file changes nothing, D-41.4);
        - non-zero exit or a thrown error: `failed (<first non-empty stderr line, or the error message>)`.
        Agents call `installCopilot`, `installClaude` and `installCodex`, with the manifest keys above.
     5. Support steps run after the agents whatever their result. `uri-handler` only when `ctx.platform` is `win32` or `linux`: when `ctx.env.MC_HOME` is set the status is `skipped (MC_HOME set)` and `installUri` is not called; else
        `installUri(ctx, false)` with the same installed/repaired/failed mapping (manifest key `uri-handler`). `vscode`: when none of `code`, `code-insiders`, `cursor` satisfies `await ctx.onPath(name)` (asked in that order), the status is
        `skipped (no editor on PATH)`; else `installVscode(ctx)` (manifest key `vscode`). On macOS `uri-handler` is not listed at all. A failed support step is printed as `failed (...)` but never changes the exit code.
        Claude Code's own automatic uri-handler step (claude.ts:121, skipped under `MC_HOME` by T084) is left alone; init's explicit step then reports `repaired`.
     6. Output: exactly one line per target, `io.out(target.padEnd(12) + " " + status)`, in this order: the selected agents, `uri-handler`, `vscode`. Target names are `copilot`, `claude-code`, `codex`, `uri-handler`, `vscode`.
        Then a final line `next: mc launch` when no agent failed.
     7. Return 1 if any selected agent failed, else 0.
2. `commands/launch.ts`: `export async function run(argv: string[], io: Io): Promise<number>`. The flags are open's: only `--print` and `--no-pair`; anything else gives `io.err("usage: mc launch [--print] [--no-pair]")` and return 2.
   Then `const code = await startRun([], quiet)`, where `quiet` is `io` with an `out` that drops a line starting `already running ` (everything else, including `started pid=` and `launchers updated`, passes through). A non-zero `code` is returned
   and open does not run. Then `return openRun(argv, io)`. The exit code is start's when start fails, else open's. (`open` also calls `ensureRunning`, so the second check is harmless; start runs first so that T085's launcher self-heal happens.)
3. `main.ts`: `import { run as init } from "./commands/init.js"; import { run as launch } from "./commands/launch.js";`, add `init,` and `launch,` to `COMMANDS`, and add to `USAGE` before the `start` line:
   ```
     init [--agents <list>]  connect agents; prompts when omitted (copilot, claude-code, codex)
     launch                start the daemon if needed, then open the page
   ```
   Keep every other help line as it is; `start`, `open` and `install` stay listed.

   `PassThrough`s (`stdin.end("2,3\n")`, `stdout` collected into a string); `isTTY: true` unless noted. Launch tests copy `package-cli.test.ts` PC-13's setup (`MC_HOME` temp, `MC_PORT: "0"`, `MC_PLATFORM: "fake"`, `MC_TEST: "1"`, its `afterEach` that runs `main(["stop"])`, timeout 30000).

   - `IN-06 init exits 1 when a selected agent fails and still reports the other targets`

   Bodies:

   - IN-04: `--agents` absent, `isTTY: false`: returns 2, `err` is `usage: mc init [--agents copilot,claude-code,codex] (no terminal to ask on)`, and the manifest file does not exist.
   - IN-05: first run `--agents copilot`: the `copilot` line ends `installed`; second run: ends `repaired`; the hooks file content is byte-identical between the runs. Every target line matches `/^(copilot|claude-code|codex|uri-handler|vscode) +(installed|repaired|skipped \(.+\)|failed \(.+\))$/`, and `next: mc launch` is last.
