# T114: the daemon's Copilot account service over the SDK (D-56)

Milestone M5 · Wave 9c · Depends on: T113, T115 · Runs on: any OS

## Goal

The daemon asks the Copilot SDK for account data (runtime version, plan, quota) every 5 minutes
and puts it in `DaemonInfo.copilot`, with today's nano-AIU total and a month-end forecast.

## Codes against

`docs/DECISIONS.md` D-56 (items 2 and 4); `docs/contracts/api.schema.json` (`DaemonInfo.copilot`,
`$defs/CopilotAccount`); `docs/contracts/internal.md` (the `copilot-account.ts` row); the SDK's types
in `node_modules/@github/copilot-sdk/dist/*.d.ts` and its `README.md`.

## Steps

1. `pnpm --filter @mc/daemon add @github/copilot-sdk@1.0.34 --save-exact`.
2. `copilot-sdk-client.ts`: `createSdkClient(): CopilotAccountClient` over the real SDK, loaded with
   a dynamic `import()`. `CopilotAccountClient` = `{ start(): Promise<void>; status(): Promise<{runtimeVersion: string | null}>; quota(): Promise<unknown>; stop(): Promise<void> }`
   (`quota()` calls `client.rpc.account.getQuota({})`). Never passes `gitHubToken`; never creates,
   resumes or lists sessions.
3. `copilot-account.ts`: `createCopilotAccount(deps, {client, refreshMs = 300000, onChange})`.
   `start()` starts the client and refreshes now and every `refreshMs` (`unref()`). A refresh builds
   `CopilotAccount`:
   - `runtimeVersion` from `status()`; `planTier` from the quota result when it has one, else null.
   - `quota` from the quota snapshot that has a numeric entitlement (prefer a key containing
     `premium` or `credit`): `entitlement = entitlementRequests`, `used = usedRequests`,
     `remainingPct = remainingPercentage`, `resetDate`, `unlimited = isUnlimitedEntitlement`; null when none.
   - `nanoAiuToday` = sum of `telemetry.credits.nanoAiu` of sessions whose `updatedAt` is today in
     local time; `aiCreditsToday` = null (D-56 4).
   - `forecastPct`: keep in memory one `(time, used)` sample per refresh for 7 days; with two samples at
     least 1 hour apart and a `resetDate` and an entitlement > 0:
     `100 * (used + rate * msUntilReset) / entitlement` where `rate` = used change per ms over the kept
     samples; else null.
   - `error`: null on success; on failure the message cut to 200 characters with anything matching
     `/(gh[opsu]_|github_pat_)[A-Za-z0-9_]+/` replaced by `<redacted>`; the other fields keep their last values.
   Call `onChange()` only when the result differs from the previous one. `stop()` stops the timer
   and the client. `current()` returns the last result, or null before the first.
4. `main.ts`: when `env.MC_TEST === "1"` or `env.MC_COPILOT_SDK === "0"`, `deps.copilot.current()`
   always returns null and no client is made. Otherwise create it with `createSdkClient()` after the
   telemetry service; `onChange` broadcasts `daemon.update`.
5. `routes/api.ts`: `DaemonInfo.copilot = deps.copilot.current()`.
6. In the checkpoint, report what `models.listTokenPriceUnits` returns as its `unit` on dev-pc
   (one manual call; field names and the unit string only) for D-56 item 4.

## Tests (`packages/daemon/test/copilot-account.test.ts`; fake client, fake timers)

- `TA-01` a healthy fake: `current()` has `runtimeVersion`, `quota` mapped, `error: null`, and passes the
  `DaemonInfo` part of the API schema (validate a `daemon.update` WsServerMessage with it).
- `TA-02` `nanoAiuToday` sums only sessions updated today.
- `TA-03` forecast: null with one sample; a number after two samples 2 h apart.
- `TA-04` a failing `quota()` sets `error`, redacts `gho_abc123`, keeps the last quota.
- `TA-05` `onChange` fires once for a change and not for an equal refresh; `stop()` stops the client.
