# T043 checkpoint: macOS discovery and focus

Builder: task branch `task/T043-mac-focus`, worktree `task-T043-mac-focus`, host `dev-pc` (Windows 11).
Run on Windows, so only the `any` IDs were checked. The macOS rows are unverified.

## What works

- `macos/scripts/`: terminal-find, terminal-focus, iterm-find, iterm-focus (AppleScript, JSON-escaped output with a `jsonEscape` handler); screen-frame, frontmost, ax-focus, ax-list, ax-trusted (JXA). All run as `osascript [-l JavaScript] <script> <argv...>`. Arguments are only ever argv elements, never spliced into source.
- `macos/discover.ts`: `parseOsascriptError` (-1743 automation, -25211 / "assistive access" accessibility), `resolveTarget` for Terminal.app and iTerm2 by tty (only when the app is running, via `pgrep -x`), tmux (inner pane, outer client tty from `tmux list-clients`), WezTerm and kitty by env, VS Code and other apps by PID through ax-list, `foregroundWindow` via frontmost.js, `listWindows` via ax-list.js (empty without Accessibility), `windowExists`.
- `macos/focus.ts`: macos.md 3.1 to 3.4. Terminal/iTerm2 maximize uses screen bounds; AX targets go through ax-focus.js; tmux inner selection with `-S socket`; verification polls the frontmost PID for 500 ms, then retries via ax-focus, then `partial/flashed`; an AXMain title mismatch gives `partial/focused_window_only`. Automation or Accessibility denial gives `failed/permission_denied` with detail `macos_automation_denied` or `macos_accessibility_denied`.
- `macos/index.ts`: `create(env)` composes discover and focus. `capabilities()` adds `macos_accessibility_denied` (ax-trusted false) and `macos_automation_denied` (last Terminal/iTerm2 osascript call refused by -1743). Every method is guarded, so none throws (PA-01).
- Tests: `test/macos-focus.test.ts` (MU-01..MU-08, all pass). `test/os/macos-focus.os.test.ts` (MO-01, MO-02, MO-03, MO-04, MO-06, skipped unless darwin and MC_OS_TESTS=1). Recorded osascript outputs and stderr samples in `test/fixtures/macos/`.

## What does not work yet, or is unverified

- Nothing has run against real Terminal.app, iTerm2, VS Code or System Events. All AppleScript and JXA is unexecuted on this host. The MO and M rows are unverified.
- `notify.ts` is still the T044 stub, which throws. `index.ts` guards every call, so notifications report `notify: false` until T044 merges.
- kitty focus runs `kitty @ focus-window --match id:<id>` without `--to <KITTY_LISTEN_ON>`, and WezTerm runs `wezterm cli activate-pane` without `WEZTERM_UNIX_SOCKET`. The inner selector has no field for either, so these depend on the daemon's inherited environment.
- `resolveTarget`'s 1500 ms budget is not enforced. Each osascript call has the 3 s exec timeout, so a cold call can exceed it.

## Deviations from the task text (all small, all disclosed here)

1. `screen-frame.js` returns the raw main-screen `visibleFrame` plus `primaryHeight` as JSON. The top-left conversion (macos.md 3.2) happens in `focus.ts` (`topLeftBounds`), so MU-04 tests the code that runs. The formula is unchanged.
2. `terminal-find` and `iterm-find` also output `minimized` (and iTerm2 outputs `session`), so `if-minimized` (PA-06) can be honoured. `ax-focus.js` takes `<pid> <title> <mode> l t r b` and reads AXMinimized itself, so the mode decision happens before restore.
3. `.js` scripts run as `osascript -l JavaScript <file>`. Without `-l`, osascript does not run them as JXA.
4. The tmux socket is taken from `env.TMUX` at resolution and kept in a per-pane map in `discover.ts`, because `InnerSelector` has no socket field. After a daemon restart, focus falls back to the default tmux socket.
5. The iTerm2 unique-id fallback (ITERM_SESSION_ID after the colon) applies at resolution only. Focus re-finds the tab by tty.
6. `windowExists` checks only that the owner PID is alive. The window-level check is left to focus, which returns `not_found`.
7. The JXA scripts carry `/* global */` and `eslint-disable @typescript-eslint/no-unused-vars` headers. The root eslint config is frozen and has no JXA globals, and `run()` is an entry point that eslint sees as unused.
8. Reads outside the three-file read list: the stub files I own, `process/index.ts`, `exec.ts`, `types.ts`, `windows/index.ts` (stub only), the generated `@mc/contracts` shapes (Capabilities, Host, FocusResult, Origin, ProcessInfo, RestoreReason), the T043 entries in `scripts/test-ids.json`, and `scripts/task-check.mjs`. I needed these to compile and to match the test IDs. No frozen file was changed. No CR was needed.

## Surprises

- The windows stub (T040) is still a stub on this branch, so I did not depend on it.
- A shell `printf` mangled the backslashes in the `terminal-find` fixture, so MU-02 and MU-05 failed on invalid JSON. Fixed by rewriting the fixture with the file writer.
- The MU-07 path check had to accept both separators, because `scriptPath` gives backslashes on Windows.
