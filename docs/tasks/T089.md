# T089: Package-install smoke: install the tarball into a temp prefix and run `mc`

Milestone M5 · Wave 8g · Depends on: T087 · Runs on: Windows and Linux

## Goal

Prove the packaged tarball works with no clone: `npm i -g` it into a temp prefix, then
run the installed `mc`, the launcher, the hook and the packaged daemon against temp
dirs. This is the `package` gate stage (first in m5) and the SK ids.

**Needs npm registry access.** The tarball lists koffi, fastify, ws, ajv and the other
external dependencies, and `npm i -g` downloads them using the real npm cache (see step 5), so a warm cache avoids re-downloading. On a
machine with no registry access this task fails by design; say so in the checkpoint
rather than working around it. macOS is not run (PACKAGING.md 6).

## Codes against

`docs/PACKAGING.md` 2 (layout), 4 (launcher format), 5 (install flow), 6 (verified
where); `docs/DECISIONS.md` D-39, D-41, D-44; `docs/contracts/config.md` 1 (`MC_HOME` ->
`$MC_HOME/state`) and its environment overrides (`MC_PORT=0` writes the real port to
`daemon.json`); `docs/contracts/claude-hooks.md` 1-2; PRD AC-11 (hook exits 0 within
1500 ms); `docs/TEST-PLAN.md` 2.1, 2.3, 3.

## Files

`packaging-test/install.test.mjs`, `scripts/gates.json` (stage `package`),
`docs/checkpoints/T089.md`.

## Do not touch

Everything else, including `scripts/package.mjs` (T087) and `scripts/test-ids.json` (the
orchestrator writes it). If the tarball is wrong, write `CR:` in your checkpoint and
stop. The test never reads or writes the real `~/.claude`, the real config and state
dirs, or port 47800 (a daemon may be running there; leave it alone).

## Steps

1. `vitest.workspace.ts` is not yours: T080 already created the `packaging` project
   (`packaging-test/**/*.test.mjs`, testTimeout 600000). Do not edit it. The `beforeAll`
   and `afterAll` hooks in step 5 get their own 300000 ms timeout argument.
2. `scripts/gates.json`: add one stage after `budget` and before `audit`:
   `{ "name": "package", "kind": "vitest", "pre": ["pnpm -r build", "pnpm package"], "cmd": "vitest run --project packaging", "first": "m5" }`.
   That project also holds T087's PK and T088's RN tests, so the stage reports them too.
   The runner adds the JSON reporter for `kind: "vitest"`, so the SK titles land in
   `.gate/reports/package.json` (`scripts/lib/run.mjs` `stageCommands`), and
   `scripts/check-test-ids.mjs` counts them (`ID_TITLE = /^([A-Z]+-\d{2})\s/`). The audit
   fails on any skipped test, so SK tests must never use `skip`, `todo` or `runIf`.
3. `packaging-test/install.test.mjs`: plain ESM, one file, one `describe("package install", ...)`
   whose six `it` blocks run in order and share state from a `beforeAll`.
   ESLint note: `eslint.config.js` declares only these globals for `.mjs`: `process`,
   `console`, `Buffer`, `URL`, `setTimeout`, `clearTimeout`. Do not use `fetch`,
   `performance`, `AbortSignal` or `setInterval` bare; use `node:http` `get`, `Date.now()`
   and `setTimeout`. Import `describe, it, expect, beforeAll, afterAll` from `vitest`.
4. Helpers inside the file (keep them small):
   - `rootVersion`: `JSON.parse(readFileSync(<repo root>/package.json, "utf8")).version`.
     Repo root is `fileURLToPath(new URL("..", import.meta.url))`.
   - `tarball`: `<root>/release/mission-control-desktop-<rootVersion>.tgz`. If it does not
     exist, `throw new Error("run pnpm package first")` in `beforeAll`.
   - `sh(cmd, args, opts)`: `spawnSync` returning `{code, stdout, stderr}`. For `npm` on
     Windows use `shell: true` and double-quote every argument (npm is `npm.cmd`); on other
     OSes call `npm` directly. Never run `mc` through `.cmd` shims: call `process.execPath`
     with `<pkgDir>/dist/mc.js`. Also assert that the shim npm created exists
     (`<prefix>/mc.cmd` on Windows, `<prefix>/bin/mc` elsewhere), so the `bin` field is
     checked.
   - `install(prefix)`: `npm i -g --prefix <prefix> --cache <realCache> --no-audit --no-fund --loglevel=error <tarball>`,
     timeout 240000 ms, must exit 0 (put stderr in the assertion message).
   - `pkgDir(prefix)`: Windows `<prefix>/node_modules/mission-control-desktop`; other OSes
     `<prefix>/lib/node_modules/mission-control-desktop`.
   - `mc(prefix, args)`: `sh(process.execPath, [<pkgDir>/dist/mc.js, ...args], {env})`.
   - `waitFor(fn, ms)`: poll `fn` every 100 ms until truthy or `ms` elapses. This is the
     only waiting allowed, always with an explicit deadline of at most 15000 ms.
   - `httpGet(port, path)`: `node:http` `get` to `127.0.0.1`, resolves `{status, body}`.
   - `real(p)`: `realpathSync.native(p)`; compare paths after `real()` and, on Windows,
     after converting `\` to `/` and lower-casing (settings.json holds forward slashes).
5. `beforeAll` (timeout 300000): make one temp root with `mkdtempSync(join(tmpdir(), "mc-pkg-"))`
   and under it `prefix1/`, `prefix2/`, `home/`, `mchome/`, `claude/`. Env for every child
   (spread `process.env` first, then override): `MC_HOME=<mchome>`, `HOME=<home>`,
   `USERPROFILE=<home>`, `APPDATA=<home>/AppData/Roaming`, `LOCALAPPDATA=<home>/AppData/Local`,
   `XDG_CONFIG_HOME=<home>/.config`, `XDG_STATE_HOME=<home>/.local/state`,
   `XDG_DATA_HOME=<home>/.local/share`, `CLAUDE_CONFIG_DIR=<claude>`, `MC_PORT=0`.
   Delete `MC_PLATFORM` and `MC_TEST` from that env: the smoke runs the real platform on
   purpose, so koffi (Windows) and dbus-next (Linux) load from the installed
   `node_modules`. Write a seed `<claude>/settings.json` (`JSON.stringify(seed, null, 2) + "\n"`)
   with one unrelated key (`"theme": "dark"`) and one unrelated `Stop` hook group
   (`{ "matcher": "", "hooks": [{ "type": "command", "command": "echo", "args": ["x"] }] }`),
   and keep the parsed `seed` object. Before overriding the env, read the real npm cache
   once: `realCache = sh(npm, ["config", "get", "cache"]).stdout.trim()` with the untouched
   `process.env` (the temp USERPROFILE/APPDATA/LOCALAPPDATA would otherwise give an empty
   cache); `install()` passes it as `--cache`. Then `install(prefix1)`.

   `afterAll` (timeout 300000): `mc stop` with the prefix2 install, then the prefix1 install
   (ignore errors; either may be gone); if `<mchome>/state/daemon.json` still exists, read
   its `pid` and `process.kill(pid)` inside a `try`;
   `rmSync(tempRoot, {recursive: true, force: true})`.
6. The six tests. Titles must be exactly:
   - `SK-01 mc --version of the installed package prints the root package.json version`:
     run `mc(prefix1, ["--version"])`; code 0; `stdout.trim() === rootVersion`; the npm
     shim exists.
   - `SK-02 mc install claude-code writes hooks that point at the launcher in MC_HOME/state/bin, and the launcher targets the installed package`:
     run `mc(prefix1, ["install", "claude-code"])`, code 0 (print stderr on failure), and its stdout contains the line
     `uri-handler skipped (MC_HOME set)` (D-41.6: with `MC_HOME` set the installer never
     writes the real HKCU keys, so no registry export or restore is needed).
     Parse `<claude>/settings.json`; collect every hook object under `hooks.*[*].hooks[*]`
     whose `args` has length 2 and `args[1] === "claude-code"`; expect at least 9 (one per
     event, claude-hooks.md 1); each has `args[0]` equal (normalised as in `real()`) to
     `<mchome>/state/bin/mc-hook.js`. Read that launcher's first line; it must match
     `/^\/\/ mission-control launcher\. target: (.+)\. version: (.+)$/`; the target must
     `real()`-start with `real(prefix1)`, end with `dist/mc-hook.js` and exist; the version
     equals `rootVersion`.
   - `SK-03 the launcher run with a fixture Claude payload exits 0 within 1500 ms and leaves a spool file`:
     no daemon is running here. Read the payload text from
     `<repo root>/packages/contracts/fixtures/ingest/raw/cc-session-start.json`. Spawn
     `process.execPath [<mchome>/state/bin/mc-hook.js, "claude-code"]` with that text as
     `input`, same env, timeout 5000. Measure with `Date.now()` around the call. Expect
     code 0, elapsed `< 1500`, empty stdout, and at least one `*.json` file in
     `<mchome>/state/spool/`. If nothing was spooled because the hook reached some other
     daemon, write a `CR:` line instead of loosening the test.
   - `SK-04 mc start runs the packaged daemon: /healthz reports the root version and GET / serves the UI index, then mc stop`:
     `mc(prefix1, ["start"])` code 0. `waitFor` (15000) until `<mchome>/state/daemon.json`
     exists and parses; port = its `port` (a number > 0, since `MC_PORT=0`).
     `httpGet(port, "/healthz")`: status 200, JSON `ok === true` and
     `version === rootVersion`. `httpGet(port, "/")`: status 200 (not 503) and body
     contains `<html`. Then `mc(prefix1, ["stop"])` code 0, and `waitFor` (15000) that
     `daemon.json` is gone. Put the stop in a `finally` so a failed assertion still stops it.
   - `SK-05 reinstalling into a second prefix then mc start rewrites the launcher target`:
     `rmSync(prefix1, {recursive: true, force: true})` (the old install is gone),
     `install(prefix2)`, `mc(prefix2, ["start"])` code 0 (the manifest still holds the
     claude-code entry from SK-02, which is what lets `mc start` heal the launchers), then
     read the first line of `<mchome>/state/bin/mc-hook.js` and `<mchome>/state/bin/mc.js`:
     both targets `real()`-start with `real(prefix2)` and exist (`dist/mc-hook.js` and
     `dist/mc.js` respectively). Put `mc(prefix2, ["stop"])` in a `finally`.
   - `SK-06 mc uninstall claude-code from the second prefix restores the settings file to its seeded content`:
     `mc(prefix2, ["uninstall", "claude-code"])` code 0; `JSON.parse` of
     `<claude>/settings.json` deep-equals `seed`. This must run last, because uninstall
     empties the manifest.
7. Run `pnpm -r build && pnpm package` once (outside the test), then the acceptance command. Typecheck and
   lint must stay green: `pnpm exec eslint packaging-test --max-warnings 0`.

## Stop if

a root script `package` is missing (T080 owns it), or `release/mission-control-desktop-<v>.tgz` is not
produced, or `mc --version` does not exist (T085), or the install prints no `uri-handler skipped (MC_HOME set)`
line (T084). Write `CR:` in the checkpoint and stop. Do not edit root `package.json`
or `vitest.workspace.ts` yourself.
