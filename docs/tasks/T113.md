# T113: the daemon reads Copilot session logs and OTel files into `Session.telemetry` (D-56)

Milestone M5 · Wave 9b · Depends on: T112, T021, T027 · Runs on: any OS

## Goal

For every `copilot-cli` session, the daemon reads new lines of the session's `events.jsonl` and
the OTel files under `<stateDir>/otel/`, folds them with T112's `createCopilotFold`, and sets
`Session.telemetry`. It never writes to the Copilot folder.

## Steps

1. `SessionService.setTelemetry(id, t)`: like `setGit`: no-op for an unknown id; store
   `{...session, telemetry: t}`; emit an upsert only when the value changed (use the file's `same`
   deep compare); `save()`.
2. `createTelemetry(deps, {copilotHome, tickMs = 2000})`. Each tick (and `tickNow()`):
   - For each session with `adapter === "copilot-cli"` that is live, or ended less than 60 s ago:
     the file is `<copilotHome>/session-state/<nativeId>/events.jsonl`. Keep per session
     `{fold, offset, rest}`. Open read-only, read from `offset` to the end, prepend `rest`, feed each
     complete line (`\n`, strip `\r`) to `fold.addEventLine`, keep the last partial line in `rest`.
     If the file is now smaller than `offset`, start a new fold at offset 0. A missing file is not an
     error. Read at most 8 MiB per file per tick.
   - For each `*.jsonl` in `<stateDir>/otel/` (missing folder = nothing): the same offset and rest
     logic; parse each line; a `span` record's `gen_ai.conversation.id` attribute (object or OTLP list
     form, as T112 reads it) names session `copilot-cli:<id>`; when that session exists, give the record
     to its fold (`addOtelRecord`). Other records are ignored.
   - For each session with a fold: `sessions.setTelemetry(id, fold.snapshot(clock.now()))`.
   - Forget the state of sessions that no longer exist.
   - An OTel file whose last change is more than 7 days old and which is fully read is deleted.
     Nothing else is ever deleted or written outside `<stateDir>`.
   - A read error is logged once per file (`log.warn`), never thrown.
3. `main.ts`: `copilotHome = env.COPILOT_HOME ?? path.join(os.homedir(), ".copilot")`; create the
   service after the session service; `start()` after the notifier and liveness start; `stop()` on
   shutdown before the final flush. `adapters["copilot-cli"].enabled === false` in the config: do not start it.
4. Timers use `setInterval(...).unref()`.

## Tests (`packages/daemon/test/telemetry.test.ts`; temp `COPILOT_HOME` and `MC_HOME`; call `tickNow()`, no sleeps)

- `TD-01` a session's `events.jsonl` with usage lines sets `telemetry` (tokens, `sources: ["events"]`);
  appended lines update it on the next tick; a partial last line is held until its newline arrives.
- `TD-02` a `claude-code` session gets no telemetry; a missing file gives none; the SHA-256 of every
  file under the temp `COPILOT_HOME` is the same before and after ticks.
- `TD-03` an OTel file with a compaction `chat` span for that session id adds `"otel"` to `sources`
  and compaction tokens; a span for an unknown id changes nothing.
- `TD-04` a file replaced by a shorter one restarts the fold (tokens drop to the new file's sum).
- `TD-05` `setTelemetry` emits one upsert for a new value and none for an equal value; unknown id is a no-op.
