## What does not work

  Vitest then reports `Timeout calling "onTaskUpdate"` (the blocked spawnSync starves the
  worker RPC), and all six tests are skipped.
- Observed on dev-pc (Windows 11), npm 11.12.1, Node 24.15.0. npm's debug log shows
  `usocket@0.3.0` placed for `dbus-next@0.10.2` (its `optionalDependencies`). `usocket`
  declares `"install": "node-gyp rebuild"` and `gypfile: true`, and `node-gyp@^7` is pulled in
  with it. `node-gyp rebuild` ran for more than 4 minutes with no result. `nodejs.org` answers
  HTTP 200, so network access is not the obvious cause. I did not isolate the exact node-gyp
  failure mode (toolchain or header fetch).
- Cleanup: the smoke test's npm, node-gyp and vitest child processes were killed by PID after
  the run. The temp dirs were removed by `afterAll`. No daemon was started by a passing test.
  The real `~/.claude`, the real config and state dirs and port 47800 were never touched.

## Surprises

- `PACKAGING.md` 7 says `usocket` "stays unbuilt". The tarball does not stop npm from running
  its install script, so the claim does not hold on a plain `npm i -g`.
- The spec's `spawnSync` calls block the vitest worker for the whole install. A slow install
  shows up as `Timeout calling "onTaskUpdate"` rather than as a clean assertion failure. This
  is a test-design note, not the blocker.

## CR

CR: scripts/package.mjs (T087, owned by another task) the tarball's dependency set must not
let `npm i -g` run `usocket@0.3.0`'s `node-gyp rebuild` install script. `usocket` is an
optional dependency of `dbus-next@0.10.2`, which `PACKAGING.md` 7 says stays unbuilt. Options
for the owner: drop `usocket` from the installed tree (for example an `overrides` or
`bundleDependencies` choice made in `scripts/package.mjs`, or a `dbus-next` version without
the optional native dep), or declare the install as one that never runs external build
scripts. The T089 test cannot pass until a plain `npm i -g <tarball>` finishes on this machine.
Re-run `pnpm task:check T089` after T087 changes the tarball.

Not done because of the stop: `TASK T089 PASS 6/6` is not reached. The SK tests have not been
run to completion, so SK-02..SK-06 behaviour is unverified.
