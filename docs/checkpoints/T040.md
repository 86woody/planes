# T040 checkpoint: Windows discovery, win32 bindings, adapter assembly

Host: dev-pc (Windows 11 Pro 10.0.26300). Branch `task/T040-win-discover`.

## What works

- `windows/win32.ts`: lazy koffi bindings (koffi imported on first use), `hwndToHex`,
  `hexToHwnd`, `windowInfo(h)`, `enumerateWindows()` (one EnumWindows pass, visible windows only),
  `foregroundHwnd()`. Process facts (exe basename, elevation) are cached per pass.
- `windows/discover.ts`: pure `chooseWindow({origin, host, windows, byHwnd})` implementing
  windows.md 2 steps 1-4 and 2.1, the WSL row of windows.md 1, and the remote row of
  platform-adapter.md 4. `createDiscover({exec, env})` gathers windows and the hook HWNDs
  (console, owner, root owner), then calls `chooseWindow`. Implements `resolveTarget`,
  `windowExists`, `foregroundWindow`, `listWindows`.
- `windows/index.ts`: `create(env)` composes discover, focus and notify, plus
  `processAlive` from `process/index.ts`. Every method is wrapped so nothing throws (PA-01).
- Unit tests `packages/platform/test/windows-discover.test.ts`: WU-01..WU-06 (7 tests with the
  edge case), fixtures in `packages/platform/test/fixtures/windows/` (conhost, wt-owner,
  wt-pseudoconsole, wt-two-windows, unknown-host, elevated-wt, wsl-wt). All pass on any OS.
- OS tests `packages/platform/test/os/windows-discover.os.test.ts` (skipped unless
  `MC_OS_TESTS=1` on win32): WO-01, WO-05, WO-08 all pass on dev-pc.
- `pnpm task:check T040` prints `TASK T040 PASS 9/9`, exit 0. `pnpm -w run typecheck` and
  `pnpm -w run lint` exit 0.

## What does not work yet

- `create(env)` throws `not implemented: T041` / `T042` until focus.ts and notify.ts
  merge, because it calls `createFocus` and `createNotify` at construction. The discover
  half works standalone.
- Elevation detection is not exercised: no elevated window exists on this box. The
  `OpenProcessToken`/`GetTokenInformation` path is written from the Win32 docs and only
  covered by the pure fixture (`elevated-wt.json`). Manual W-10 is the real check.
- `ResolvedTarget` has no `detail` field, so the detail strings in the task
  (`target window is elevated`, `ambiguous: 2 windows`) cannot be returned. Only the
  `reason` is set. Focus-time detail belongs to T041.

## Deviations from the contract text (for the reviewer)

1. `WindowInfo` carries `hwnd`, `rootOwner` and `elevated` in addition to the
   `{pid, exe, className, title, visible, owner}` listed in the task. `elevated` is needed
   so `chooseWindow` can stay pure and test the elevated rule with fixtures. `rootOwner` is
   needed for step 3, and it lets the impure part pre-fetch the root owner so `byHwnd` stays
   synchronous.
2. Step 4 ambiguity: several candidate windows in one ancestor process returns
   `none/no_window_found` for every host kind, not only Windows Terminal (windows.md 2.1
   is written for WT; applying it generally is the conservative choice).
3. A ConsoleWindowClass window found through the ancestry scan gets capability `full`
   (`targetFor`), not only one found by step 2. WO-01 depends on this.
4. Step 1 with a VS Code owner returns capability `window`, inner null (the bridge
   handles VS Code, windows.md 1).

## Surprises

- Windows 11 default terminal: a conhost started by Node `spawn` was delegated to
  Windows Terminal, so no ConsoleWindowClass window appeared. Starting it with
  `Start-Process conhost.exe` from PowerShell gives a classic console window. WO-01 now
  launches through PowerShell for that reason.
- The window with the marker title is owned by the `cmd.exe` that conhost hosts, not by
  `conhost.exe`. The hook's ancestry therefore reaches the window through the cmd PID.
- `"0x".toUpperCase()` produces `"0X"`. That broke the HWND lookup at first. Normalisation
  is now `normHex` (uppercase the digits only). Anything else that normalises origin HWNDs
  must use it.
- koffi `IKoffiRegisteredCallback` is the type needed for the EnumWindows callback
  registration; `unknown` does not typecheck.
