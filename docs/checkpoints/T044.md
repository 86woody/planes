## What works

- `packages/platform/src/macos/notify.ts`: `createNotify` with backend detection at
  creation (alerter, then terminal-notifier, then osascript), exposed as `backend`.
- Pure builders `alerterArgs`, `terminalNotifierArgs`, `osascriptArgs`, with
  `-execute` paths single-quoted and `'` escaped as `'\''`.
- alerter: spawned (not exec), stdout JSON parsed on exit; `contentsClicked` and
  `actionClicked` call `onClick(sessionId)`; a timeout does not. At most 10 live,
  oldest killed beyond that.
- terminal-notifier and osascript: run through the injected `exec` with a 1500 ms
  timeout, so `notify` returns well inside PA-07.
- `withdraw`: alerter kill plus `alerter -remove <tag>`; terminal-notifier
  `-remove <tag>`; osascript no-op.
- `probe()`: `notify: true`; `notifyClick: backend !== "osascript"`; the
  `macos_notify_no_click` info issue for osascript only.
- `scripts/notify-osascript.applescript`: `display notification` with title and body
  from argv and `sound name "Glass"`.

## Decisions and assumptions

- `createNotify` is synchronous per internal.md section 6, so backend detection uses a
  local `spawnSync` `which` instead of the async `which` from `exec.ts`.
- alerter processes are spawned with `child_process.spawn` directly, because `exec`
  waits for close and times out after 3 s. Unit tests mock `node:child_process`.
- `terminalNotifierArgs` always passes `-sound default`. `OsNotification` has no
  silent flag, so there is nothing to condition it on.
- When `sessionId` is null, `terminalNotifierArgs` omits `-execute` entirely, since
  there is no session to restore. macos.md does not say what to do here.
- The osascript script path is resolved from `import.meta.url`
  (`src/macos/scripts/`). A build that does not copy the `.applescript` file to dist
  would break this backend.
- `createNotify` returns an extra `backend` field beyond the frozen signature, as the
  task asks.

## Surprises

- The unit test's fake stdout needed `setEncoding`, as a real ChildProcess has it.
  Without it `notify` caught the TypeError and returned null.
