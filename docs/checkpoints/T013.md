# T013 checkpoint: process utilities

Builder: task/T013-process, worktree task-T013-process, host dev-pc (Windows 11).

## What works

- `parse.ts`: `parseLinuxStat` (comm between first `(` and last `)`, ppid field 4,
  starttime field 22), `parsePsLstart` (24-char lstart, name = basename),
  `walkAncestry` (max 16, stops at pid 0/1, system/launchd/systemd/init, unknown pid,
  cycles), `normName` (lower-case, `.exe` stripped).
- `windows.ts`: koffi bindings local to the file (toolhelp snapshot, OpenProcess,
  GetProcessTimes, GetExitCodeProcess, CloseHandle, GetLastError). Ancestry uses one
  snapshot per call; start time is fetched lazily per chain entry. `alive` treats access
  denied as alive. `ttyOf` returns null. `commandLine` uses the PowerShell CIM path.
- `posix.ts`: Linux via `/proc`; macOS via one `ps -A -o pid=,ppid=,lstart=,comm=` per
  call with `LC_ALL=C`. `alive` = kill(pid, 0) (EPERM counts as alive) plus start-time
  comparison. `ttyOf` uses `ps -o tty=`.
- `index.ts`: dynamic import of `./windows.js` or `./posix.js` on first use, so koffi
  is not loaded on macOS or Linux. Exports `ancestry`, `processAlive`,
  `processStartTime`, `commandLine`, `ttyOf` with the frozen signatures.
- Tests: PR-01..PR-08 in `packages/platform/test/process.test.ts`, all passing live on
  Windows (PR-04 through PR-07 spawn real `node` children).
- `pnpm -w run typecheck` and `pnpm -w run lint` exit 0.

## What does not work or is not verified

- Only Windows was exercised. The Linux and macOS branches of `posix.ts` compile and
  pass typecheck but have not run. PR-04 through PR-07 are the checks that would
  exercise them on those hosts.
- Windows `commandLine` (PowerShell CIM) and `ttyOf` are not covered by any test. The
  PR list does not require them.
- Linux zombie processes: `/proc/<pid>/stat` still exists until the parent reaps the
  child, so `processAlive` reports true for a zombie. The spec does not cover this and
  I did not add a state check (parseLinuxStat returns only the fields the spec lists).
- `walkAncestry` does not stop on the `System` pid 4 by number; it stops by name (the
  Windows System process is named `System`), which matches the contract.

## Surprises

- `ProcessInfo.name` keeps the image basename with `.exe` (contracts doc example:
  `node.exe`). PR-04 therefore compares `normName(name) === "node"` rather than the raw
  string. The contract's agent rules already strip `.exe`, so no conversion was done in
  the process layer.
- koffi needs the `FILETIME` struct registered by name before the GetProcessTimes
  prototype is parsed. The registration is kept as a bare call, not a `const`, so
  lint does not flag it as unused.
- `exactOptionalPropertyTypes` makes `startTime` a conditional property: `walkAncestry`
  and `ancestry` only set it when a value exists.
- `ps` lstart is locale-dependent, so the macOS call forces `LC_ALL=C`. This is untested
  on a Mac.
