# T004 checkpoint

## What works
- `scripts/gates.json`: the TEST-PLAN 2.1 rows in order, audit last. Commands with `<gate>` and `<reports>` placeholders are filled in by the runner.
- `scripts/lib/run.mjs`: `runStage`, leading `NAME=value` moved into env, `pnpm exec` prefix (skipped when a command already starts with `pnpm `), reporter flags for vitest and playwright, `pre` commands, tail of 30 lines.
- `scripts/gate.mjs <mN>`: TEST-PLAN 2.2 output, stops early only on `toolchain`, `GATE <mN> PASS n/n` or `FAIL k/n`, exit 0 iff all passed. Extra options `--gates <file>` and `--reports <dir>` (tests use them so a nested run never clears the real `.gate/reports`).
- `scripts/check-test-ids.mjs --gate <mN>`: TEST-PLAN 2.3 audit, `ids f/r (os=..), skipped k`, `missing:` and `unknown:` lines.
- `scripts/task-check.mjs T0xx`: TEST-PLAN 2.4. Unknown task is detected from a row in `docs/TASKS.md`, so T060 (no IDs yet) prints `PASS 0/0`, not UNKNOWN.
- `scripts/test-ids.json`: 382 IDs from TEST-PLAN section 4 (51 rows). Milestone comes from the TASKS.md M column; BG-01 is m5.
- `scripts/test/gate.test.mjs`: GT-01..GT-06, titles exactly as specified. The audit tests use `scripts/test/fixtures/reports/m0-pass.json` and derive variants in temp dirs.
- `.gitea/workflows/gate.yml`: as specified.

## What does not
- The Playwright path is not exercised by any test or gate run (no e2e tests exist yet). I checked the Playwright JSON parser once by hand with a synthetic report (passed, skipped, timedOut mapped correctly). A real Playwright run is still unverified.
- The forge workflow has not run on a Gitea runner.

## What surprised me
- `node -e 1` evaluates the expression and exits 0. The stage fixtures use `node -e "process.exit(1)"`.
- The audit's `missing:` list covers all 16 missing m0 IDs, not just CT-01. Acceptance only requires the line to contain `missing: CT-01`, which it does.
- Gate stage summaries: a passing stage shows its last output line only when it starts with `ids ` or `node v` (the audit and toolchain lines). This is my rule, not the spec's; the spec only says "optional summary text".
- `docs/TEST-PLAN.md` section 4 was expanded by a one-off generator script kept outside the repo (scratchpad), not written by hand. The output was checked for counts per task and spot-checked (SM-29 absent, WO rows windows-only, BG-01 m5).
- The workflow runs `sudo apt-get update` before the install line. The spec's install line alone would likely fail on a fresh runner.
