## Deviations and decisions

- Bar, banner and empty-state class names have no CSS file in this task's Files list, so their rules sit in `global.css`. Move them to a component CSS file if a later task owns one.
- The announcer maps attention reason to its word (`GO/NO-GO`, `HOLD`, `ANOMALY`, `NOMINAL`) with a local table in `App.tsx` rather than importing `stateLabel` from `format.ts`. `format.ts` is T031's and still a stub here, so importing it would make App throw in tests. The duplication is small; consolidate when T031 merges if preferred.
- LINK lamp is always lit: `go` when the link is open, `nogo` otherwise (including `connecting`). The spec gives only go/nogo.
- NOTIFY and FOCUS lamps are unlit (colour `los`) while `capabilities` is null. CFG is unlit while `daemon` is null.
- The `Capabilities`, `DaemonInfo`, `StateResponse` and `Session` field names used in `Bar`, `Banner` and `App` were checked by reading `packages/contracts/src/generated/api.ts`. That file is outside the "Codes against" list. It was a type lookup only, and typecheck confirms the names.
- Tests mock `Lamp`, `PollStrip`, `Counts`, `Board` and `store`, as the task specifies. `window.matchMedia` is guarded in `App` because jsdom does not provide it.

## What surprised me

- jsdom has no `window.matchMedia`, so the motion effect in `App` needed a guard.
- With fake timers, the LOS effect in `Banner` must be driven with `act(() => vi.advanceTimersByTime(...))` or the state change is not flushed.
