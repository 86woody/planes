# T026: HTTP app: routes, WebSocket, test routes

Milestone M1 · Wave 3 · Depends on: T014, T015, T021-T025 · Runs on: any OS

## Goal

Assemble the Fastify app: every route of the API contract with its auth realm, the
browser WebSocket, the bridge WebSocket mount, the UI static files, the test-only fake
platform routes, and the glue that resolves targets and reads git info after ingest.

## Codes against

`docs/contracts/api.md` (all, normative), `api.schema.json`, `vscode-bridge.md` 1,
`internal.md` (`DaemonDeps`, `buildApp`, `registerSecurity` route config),
`ARCHITECTURE.md` sections 4-5, D-19.

## Files

`packages/daemon/src/app.ts`, `packages/daemon/src/ws.ts`,
`packages/daemon/src/routes/{ingest,api,pair,static,bridge,test}.ts`,
`packages/daemon/test/{api,ws}.test.ts`, `packages/daemon/test/support/**`,
`docs/checkpoints/T026.md`.

## Do not touch

All other daemon modules (you only call them through `DaemonDeps`), `main.ts` (T027).

## Steps

1. `buildApp(deps, opts)`: `Fastify({logger: false, bodyLimit: 16384})`, register
   `@fastify/cookie`, `@fastify/websocket`, then `registerSecurity(app, {port: () => <bound port>, auth: deps.auth, testMode: opts.testMode})`.
   The bound port is read from `app.server.address()` at request time.
2. Routes with `config: {realm, rateLimit?, allowedOrigins?, bodyLimit?}` exactly per
   api.md section 3 and section 4. Bodies validated with the `@mc/contracts` validators
   (`validateEnvelope` for ingest -> 400 `invalid_envelope` with the first error).
3. `routes/ingest.ts`: after `deps.sessions.ingest(env, deps.clock.now())`, if the
   record is new or its previous origin differs (`JSON.stringify` compare), call
   `deps.focus.resolve(id)` (not awaited; catch and log); if `payload.cwd` is new for the
   session, `readGit(cwd)` then `deps.sessions.setGit`. Reply `202`.
4. `routes/api.ts`: `GET /api/state` -> `{seq: <the WS hub's current wire seq, see step 6 and D-27>, sessions: sessions.list(), daemon, capabilities}`
   with `daemon = {pid: process.pid, version, startedAt, port, configOk: config.error() === null, configError: config.error(), bridges: bridges.windows().length}`.
   `GET /api/csrf` (realm `browser`) -> `{csrf: auth.csrfFor(cookie)}`;
   `restore`, `ack` (`apply({kind: "ack"})`), `DELETE` (409 unless ended/lost),
   `notify/test`, `pair-code`.
5. `routes/pair.ts`: `POST /api/pair` sets cookie `mc_session` with the attributes of
   api.md 2 and returns `{csrf}`.
6. `ws.ts` `/api/ws` (D-27): the hub owns the **wire seq**, one counter for all sockets
   and message types, starting at 0. `SessionChange.seq` from `sessions.onChange` is the
   service's internal change order and is never put on the wire. On open send `hello`
   (seq = the current wire seq); subscribe to `sessions.onChange` and `deps.broadcast`
   events; coalesce upserts per session to one per 100 ms (latest wins); a message takes
   `++wireSeq` only at the moment it is actually sent, so a coalesced-away upsert uses no
   number and every client sees previous + 1. `notify`, `highlight`, `daemon.update`,
   `session.remove` (flush any pending upsert for that id first, or drop it) take the
   next wire seq the same way. Export a reader (e.g. `wireSeq()`) for step 4; protocol ping every
   20 s, terminate if no pong in 10 s; any client message other than `{"type":"ping"}`
   closes with 1008.
   Broadcast wiring (exact): `ws.ts` exports `export const wsHub = new EventEmitter()`.
   Whoever builds `DaemonDeps` (your `test/support/deps.ts`, and T027's `main.ts`) sets
   `broadcast: (m) => wsHub.emit("msg", m)`. `ws.ts` listens on `wsHub` `"msg"` and
   forwards to every open browser socket.
7. `routes/bridge.ts`: `GET /bridge/v1` websocket, realm bearer, allowedOrigins
   `["vscode-file://vscode-app"]` -> `deps.bridges.attach(socket)`. Also
   `deps.bridges.onChange(() => resolve every vscode session; broadcast daemon.update)`.
8. `routes/static.ts`: if `opts.uiDir`, serve it with `@fastify/static`; `GET /` returns
   `index.html` with `<meta name="mc-host" content="<os.hostname() HTML-escaped>">`
   inserted before `</head>` (read once, cached). No `uiDir` -> `GET /` returns a plain
   text `UI not built` with 503.
9. `routes/test.ts`: only when `opts.testMode` and `process.env.MC_PLATFORM === "fake"`;
   `GET /api/test/fake-platform` -> `{calls}` from the FakePlatform (`deps.platform` cast);
   `POST /api/test/fake-platform/foreground {sessionId}` -> set the fake's
   `foregroundSessionWindow` to that session's `target.window.handle` (or null).
10. `test/support/deps.ts`: builds a full `DaemonDeps` from the real modules with a
    temp `MC_HOME`, `FakePlatform`, fake clock option; used by your tests and by T027.
11. Tests use `app.inject()` for HTTP and a real listen on port 0 for WebSockets
    (`ws` client). Titles exactly:
    - `API-01 GET /healthz returns ok, pid and version without auth`
    - `API-02 POST /ingest/v1/events with a valid fixture returns 202 and the session appears in /api/state`
    - `API-03 ingest with an invalid envelope returns 400 invalid_envelope`
    - `API-04 GET /api/state with bearer and no Origin works; with a foreign Origin 403`
    - `API-05 pair-code then pair sets an HttpOnly SameSite=Strict cookie and returns csrf`
    - `API-06 browser POST restore with cookie and csrf returns RestoreResponse`
    - `API-07 restore of an unknown id is 404`
    - `API-08 ack sets attention.acknowledged`
    - `API-09 DELETE of a live session is 409; of an ended session 204`
    - `API-10 GET / injects meta mc-host and the CSP header`
    - `API-11 test routes are 404 unless MC_TEST=1 and MC_PLATFORM=fake`
    - `API-12 ingest triggers focus.resolve and setGit for a new cwd`
    - `API-13 GET /api/csrf with the paired cookie returns the csrf pair returned; without a cookie 401`
    - `WS-01 hello carries the full state and its seq`
    - `WS-02 an ingest produces session.upsert with seq hello+1`
    - `WS-03 two upserts for one session within 100 ms are coalesced into one`
    - `WS-04 a client message other than ping closes the socket with 1008`
    - `WS-05 upgrade without the cookie or with a foreign Origin is refused`
    - `WS-06 broadcast notify and highlight reach connected clients with contiguous seqs`
