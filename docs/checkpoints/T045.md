# T045 checkpoint: Linux discovery and focus

Host: dev-pc (Windows 11). Built on `task/T045-linux-focus` per D-33. No WSL, no
real window commands were run on this machine; all external output is injected or
recorded.

## What works

- `backends/select.ts`: `selectBackend(config, displayEnv, host)` follows the linux.md 1
  table with the config override first. `LinuxWindow`, `LinuxBackend`, `focusResult`,
  `pollUntil` shared here.
- `backends/x11.ts`: `parseWmctrl`, stacking order from `_NET_CLIENT_LIST_STACKING`,
  focus per linux.md 3.1 (un-minimize, raise, maximize per policy, verify, xdotool
  fallback, then `flashed`).
- `backends/sway.ts`: `parseSwayTree` walks `nodes` and `floating_nodes`; focus by
  `[con_id=N] focus`; maximize skipped with detail `tiling: maximize skipped`.
- `backends/hyprland.ts`: `parseHyprClients`, `activewindow -j` for active; focus by
  `focuswindow address:`; `fullscreen 1` only when the window reports `fullscreen 0`.
- `backends/kwin.ts`: `kwinScript(params)` builds the script from `JSON.stringify`
  values only; the runner writes the script, loadScript/run, waits 1 s for Report,
  unloads and deletes the file. The runner is injectable (`runScript`).
- `backends/gnome.ts`: `parseWindowCalls`; Unminimize, Activate, Maximize over
  `org.gnome.Shell.Extensions.Windows`; `flashed` when not focused after 500 ms.
- `tmux.ts`: `-S <socket>` on every command; most recent client by `client_activity`;
  switch-client, select-window, select-pane.
- `discover.ts`: candidate pids nearest first; X11 `WINDOWID` first; linux.md 2.1
  multi-window rule via `chooseWindow`; tmux outer window from the client tty's
  ancestry; kitty and WezTerm inner selectors from env; `none` backend gives
  `wayland_unsupported_compositor`; GNOME without the extension gives
  `gnome_extension_missing`; `remote` gives `remote_session`.
- `focus.ts`: PA-02 guard; re-resolve once by pid and title (linux.md 8); backend focus,
  then inner selector (failure gives `focused_window_only`), then foreground verify
  (PA-03).
- `index.ts`: composes discover and focus; every method is wrapped so none rejects
  (PA-01); `capabilities()` reports `focus` by `which` checks with the linux.md 7 fix
  text; `processAlive` reads `/proc/<pid>/stat` and compares start time.

## Surprises and findings for the orchestrator

1. **tmux socket has no slot in `InnerSelector`.** The contract carries only
   `tmuxPane`, but `-S <socket>` needs the socket from `$TMUX`. `tmux.ts` remembers the
   socket per pane in process memory when `resolveTarget` runs, and `focus` reads it
   back. Works within one daemon process; lost on restart, which then gives
   `focused_window_only`. A contract field (for example `tmuxSocket`) would be cleaner.
2. **`KITTY_LISTEN_ON` is not in the `displayEnv()` overlay list in linux.md 1.** The
   kitty inner focus reads it from `displayEnv()` as linux.md 4.2 implies, but the
   overlay list does not name it. Without it kitty gives `focused_window_only`.
3. **`resolveTarget(origin, host)` has no session `project`.** linux.md 2.1 says to pick
   the window whose title contains the project. `chooseWindow` supports the hint
   (LU-07 tests it), but `resolveTarget` passes none, so multi-window processes fall
   back to topmost. Needs the project on the origin or in the call.
4. **`/proc` ancestry is parsed locally** (`parseProcStat`, `readAncestry` in
   `discover.ts`). I did not read `src/process/**` (T013) so as not to touch it; this
   may duplicate its parser. Worth a merge-time look.
5. **`index.ts` calls `createNotify` from `notify.ts`**, which is still the T046 stub.
   Until T046 merges, `create()` throws `not implemented: T046`. Nothing in T045's tests
   calls `create()`.
6. **The LU-10 title appears on two tests** (sway/Hyprland, and an x11/KWin constructor
   check). The registry only requires the ID prefix to pass, so this is harmless.
