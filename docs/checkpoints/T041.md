# T041 checkpoint: Windows focus, foreground, WT tabs

## What works

- `focus(target, opts)` in `packages/platform/src/windows/focus.ts`, split into a pure
  `planFocus` (windows.md 3 steps, with the ShowWindow constants) and an impure
  `runFocus`. Verify polls `GetForegroundWindow` every 25 ms for 300 ms; the attach
  retry runs once; a failed second verify flashes and returns `partial/flashed`.
- Alt-key foreground trick (lone VK_MENU key-up through `SendInput`, 40-byte INPUT
  struct), skipped for `plain`.
- Elevation check (`OpenProcessToken`/`TokenElevation`) for target and daemon: an elevated
  target returns `failed/permission_denied` with `target window is elevated`.
- HWND reuse check: owning PID differs from `NativeWindow.pid` -> `not_found`.
- `chooseTab` (rules a and b of windows.md 4.2) and `focusResultFor` (WU-12 mapping) are pure.
- `ps/wt-tabs.ps1` (UIA TabItem list as JSON) and `ps/wt-select-tab.ps1` (SelectionItem
  Select, `{"ok":true}`). Both set UTF-8 console output so glyphs like U+2733 survive.
- Tests: WU-07..WU-12 in `packages/platform/test/windows-focus.test.ts` (6 tests, any OS).
  WO-02, WO-03, WO-04, WO-07 in `packages/platform/test/os/windows-focus.os.test.ts`.
  Each acts only on windows the test spawned (MC-TEST-<rand> titles).
- Acceptance: `pnpm task:check T041` -> `TASK T041 PASS 10/10`, exit 0.
  `pnpm -w run typecheck` and `pnpm -w run lint` exit 0.
- WO-07 ran the real Windows Terminal path (`wt.exe` is on PATH here, test took about

- After the run no MC-TEST windows remained (checked via UIA).

## What does not work, or is not covered

- `focus` does not re-resolve a closed window from the stored origin (windows.md 8 row
  "Window closed since resolve"). `focus` has no origin, so a missing window is `not_found`
  straight away.
- A target with `capability: "window"` and no `inner` returns `ok/focused`, not
  `focused_window_only`. Only a failed tab selection yields `focused_window_only`.
- Virtual desktop switching (W-09), the manual Windows checks (W-01..W-10) and the
  `mc restore` side of `AllowSetForegroundWindow` are not in this task. `focus` also calls
  `AllowSetForegroundWindow(ASFW_ANY)` itself when `fromActivation` is set; windows.md 3
  puts that call in the CLI, so this is a small deviation.
- Latency: each PowerShell helper has its own 3000 ms timeout (PA-05). `focus` runs two
  helpers for a WT tab (list, then select), so a cold start could push the total past the
  PA `focus` budget of 3000 ms. Not measured.
- `PlatformEnv.repoRoot` is used to find the `ps/` scripts, because `tsc -b` does not copy
  `.ps1` files to `dist`. This assumes `repoRoot` is the repo root.

## Surprises

- `conhost.exe cmd.exe /k ...` launched directly from node (`spawn`, with stdio ignore or
  inherit) exits with code 0 at once in this environment and leaves no window. The same
  command started with `Start-Process ... -PassThru` from PowerShell keeps a live window.
  WO tests therefore spawn conhost through PowerShell and track the PID.
- `Get-Process(...).MainWindowHandle` is 0 for a conhost window. UI Automation
  (`NativeWindowHandle`, `ProcessId`) reports the window and its owning conhost PID. The
  test finds windows by UIA title, and reads the owner PID with `GetWindowThreadProcessId`.
- koffi's `koffi.struct` accepts an unnamed definition, so no global type-name clash
  arises when modules are reloaded.
