# T022: VS Code bridge registry (daemon side)

Milestone M1 · Wave 2 · Depends on: T003 · Runs on: any OS

## Goal

Accept VS Code bridge WebSocket connections, track each window's workspace and
terminals, bind windows to native windows on focus, match sessions to windows, and
send focus requests with timeouts.

## Codes against

`docs/contracts/vscode-bridge.md` (normative, sections 1, 2, 3, 5), D-08,
`internal.md` (`BridgeRegistry`, `BridgeWindow`, `createBridgeRegistry`),
`ingest.md` section 5 (`VSCODE_NAMES`; import the constant from `@mc/core`),
`@mc/contracts` `validateBridgeClientMessage`.

## Files

`packages/daemon/src/bridge.ts`, `packages/daemon/test/bridge.test.ts`,
`docs/checkpoints/T022.md`.

`routes/**`, `app.ts` (T026 mounts `/bridge/v1` and calls `attach(socket)`).

## Steps

1. `attach(socket)`: start a 5 s timer for `hello`; on each message parse JSON,
   validate; invalid -> close 1008. `hello` -> create/replace the window entry by
   `windowId`, reply `welcome`; `terminals` -> replace the list; `windowState` -> update
   focused; `result` -> resolve the pending request. On close: remove the window, reject
   its pending requests with `{ok: false, detail: "disconnected"}`.
2. Binding: on `hello` with `focused: true` and on `windowState {focused: true}`: after
   150 ms (`setTimeout`), `platform.foregroundWindow()`; if its `app` (lower-cased,
   `.exe` stripped) is in `VSCODE_NAMES`, set `nativeWindow` and clear the same handle
   from every other window.
3. `findForSession(origin, kind)`: `vscode-terminal` -> the window having a terminal
   whose `shellPid` is in `origin.ancestry` pids (return that `terminalId`);
   `vscode-extension` -> the window whose `extHostPid` is in the ancestry
   (`terminalId: null`). Ancestry pids nearest first; first hit wins.
4. `request(windowId, msg)`: requestId `r-<n>`, send, resolve on `result` or after 2000 ms
   with `{ok: false, detail: "timeout"}`. Unknown window -> `{ok: false, detail: "no_window"}`.
5. `onChange` fires on hello, terminals, close, and binding changes.
6. Tests use a fake socket (an `EventEmitter` with `send` and `close` spies) and a
   `FakePlatform`. Titles exactly:
   - `BR-01 hello registers the window and replies welcome`
   - `BR-02 no hello within 5 s closes with 1008` (fake timers)
   - `BR-03 invalid message closes with 1008`
   - `BR-04 focused windowState binds the foreground Code.exe window and unbinds it elsewhere`
   - `BR-05 foreground window of another app does not bind`
   - `BR-06 findForSession matches a terminal shellPid in the ancestry`
   - `BR-07 findForSession matches extHostPid for vscode-extension`
   - `BR-08 request resolves on result and times out after 2000 ms`
