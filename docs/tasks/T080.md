# T080: Manifests and version source

Milestone M5 · Wave 8a · Depends on: nothing · Runs on: any OS

## Goal

The vitest aliases that make `@mc/platform/layout` resolve and a `packaging` test project,
one version source (root `package.json`, `1.0.0`) with a script that sets and checks it
across all nine manifests, the platform package exporting `@mc/platform/layout` and
copying the macOS scripts into `dist/`, and the VS Code bridge renamed `vscode-bridge`
with a `package` script that writes a `.vsix`. Nothing here changes product behaviour.

## Codes against

`docs/PACKAGING.md` sections 3 (the `./layout` export, the `macosScriptsDir` row) and 8,
`docs/DECISIONS.md` D-43 and D-44.

## Files

`package.json` (root), `packages/*/package.json` (all 8), `scripts/version.mjs`,
`scripts/copy-platform-assets.mjs`, `scripts/test/version.test.mjs`, `packaging-test/version-build.test.mjs`, `vitest.workspace.ts`
(only the alias and the `packaging` project, step 9), `docs/checkpoints/T080.md`.

## Do not touch

Every other file. In particular:

- `packages/cli/src/installers/vscode.ts` still has `const BRIDGE = "@mc/vscode-bridge"`
  (line 6) and runs `pnpm --filter @mc/vscode-bridge build` (lines 20-21). After your rename
  that real command fails (pnpm finds no such package) until T086 rewrites it. This is a
  known transient break. Its tests (IX-08) still pass because they use an injected runner.
  Do not edit that file.
- `pnpm-lock.yaml` is written only by `pnpm add` (step 3). Never edit it by hand.
- `packages/platform/src/layout.ts` does not exist yet (T081). Do not create it. The
  `./layout` export you add points at `dist/layout.*`, which T081 produces.
- `scripts/test-ids.json`, `scripts/gates.json`, and every part of `vitest.workspace.ts` other than what step 9 names.

## Steps

0. Where the tests live. `scripts/test/**` runs in the gate stage `gate-self` (m0) before any build,
   so VR-01..VR-10, VR-12, VR-15 and VR-16 (no build output, no pnpm/vsce run) go in
   `scripts/test/version.test.mjs`. VR-11, VR-13 and VR-14 need built output or run a build, so they go in
   `packaging-test/version-build.test.mjs` (the vitest project `packaging`, which runs after
   `pnpm -r build && pnpm package` in the stage `package`). Same title format, same helpers
   (copy `ROOT` and the `pnpm` spawn helper into that file; `import { test, expect } from "vitest"`).
   The acceptance command builds first, so `task:check` finds the build output.
1. Root `package.json`: add `"version": "1.0.0",` as the line right after `"name": "mission-control",`.
   Add to `scripts` (keep every existing script):
   - `"package": "node scripts/package.mjs"`
   - `"release": "node scripts/release.mjs"`
   - `"version:check": "node scripts/version.mjs check"`

   (`package.mjs` and `release.mjs` are written by T087 and T088. Do not create them.)
2. Set `"version": "1.0.0"` in each of the 8 `packages/{cli,contracts,core,daemon,hook,platform,ui,vscode-bridge}/package.json`
   (they hold `0.1.0` on line 3). Edit only that value. Keep every file's formatting
   (two-space indent, and whether it ends with a newline).
3. Add esbuild at the root: run `pnpm add -Dw esbuild@^0.25.0` (the bridge already uses
   `^0.25.0`, so it is in the pnpm store). Then confirm
   `node -e "require.resolve('esbuild')"` prints no error from the repo root. This changes

4. `packages/platform/package.json`:
   - add to `exports`, after `"."`: `"./layout": { "types": "./dist/layout.d.ts", "default": "./dist/layout.js" }`
   - set `"build": "tsc -b && node ../../scripts/copy-platform-assets.mjs"` (keep `typecheck` as is).
5. `packages/vscode-bridge/package.json`:
   - `"name": "vscode-bridge"` (was `@mc/vscode-bridge`; `publisher` stays `woody`, so the extension id stays `woody.vscode-bridge`)
   - `"main": "./dist/extension.cjs"`

     (`-o` naming a directory makes vsce write `<name>-<version>.vsix` into it, so the file
     is `dist/vscode-bridge-<v>.vsix`). Leave `private`, `type`, `exports`, `engines` alone.
6. `scripts/copy-platform-assets.mjs` (plain Node ESM, built-ins only). It takes an optional
   `argv[2]` platform package directory (default: `<this script's dir>/../packages/platform`,
   resolved from `import.meta.url`, never from the cwd). It deletes `<dir>/dist/macos/scripts`
   if present, then copies every file of `<dir>/src/macos/scripts/` into
   `<dir>/dist/macos/scripts/` (creating directories). On success it prints
   `copied <n> files to <dest>` and exits 0. If `<dir>/src/macos/scripts` does not exist it
   prints `copy-platform-assets: missing <that path>` to stderr and exits 1.
7. `scripts/version.mjs` (plain Node ESM, built-ins only). The repo root is
   `MC_VERSION_ROOT` if set, else the parent of the script's directory. Manifests are the
   root `package.json` plus `<root>/packages/<dir>/package.json` for every directory under
   `<root>/packages` that has one (sorted by path). Paths in messages use `/`.
   - `node scripts/version.mjs check`: reads the root version; if every manifest has the same
     `version`, prints `version <v> ok (<n> manifests)` and exits 0. Otherwise prints one
     line per differing manifest to stderr, `version mismatch: <relative path> has <x>, root has <v>`,
     and exits 1. A manifest with no `version` counts as a mismatch with `<x>` = `none`.
   - `node scripts/version.mjs set <v>`: `<v>` must match `^\d+\.\d+\.\d+(-[0-9A-Za-z.]+)?$`.
     Rewrites the first `"version": "..."` in every manifest by text replacement (so no other
     byte of any file changes), prints `version set to <v> (<n> manifests)`, exits 0.
   - Any other arguments, or an invalid `<v>`: prints
     `usage: node scripts/version.mjs set <x.y.z> | check` to stderr, exits 2, writes nothing.
8. Tests in `scripts/test/version.test.mjs` (vitest project `scripts`; `import { test, expect } from "vitest"`).
   Spawn scripts with `spawnSync(process.execPath, [script, ...args], { encoding: "utf8", env: { ...process.env, MC_VERSION_ROOT: tmp } })`.
   A helper builds a temp tree (`fs.mkdtempSync(path.join(os.tmpdir(), "mc-ver-"))`) with a root
   `package.json` plus `packages/a`, `packages/b`, `packages/c` stub manifests, all at `1.0.0`,
   each written as `JSON.stringify({ name, version: "1.0.0", private: true }, null, 2)` (no trailing newline
   for `a`, a trailing newline for the others). Tests that run `pnpm` use
   `spawnSync("pnpm", [...], { cwd: ROOT, shell: true, encoding: "utf8" })` with a test timeout of 120000.
   `ROOT` is the repo root, derived from `import.meta.url`. Titles exactly:
   - `VR-01 the root and all 8 packages/*/package.json carry version 1.0.0`
   - `VR-02 version.mjs check exits 0 on the repo and prints "version 1.0.0 ok (9 manifests)"`
   - `VR-03 version.mjs check on a tree with one different version exits 1 and names that manifest`
   - `VR-04 version.mjs set 1.2.3 rewrites every manifest, check then passes, and no other byte changes`
   - `VR-05 version.mjs set with an invalid version exits 2 and leaves every file unchanged`
   - `VR-06 the root package.json has scripts package, release and version:check with the exact commands`
   - `VR-07 esbuild is a root devDependency and resolves from the repo root`
   - `VR-08 platform package.json exports ./layout (types and default under dist) and its build runs copy-platform-assets.mjs`
   - `VR-09 copy-platform-assets.mjs copies src/macos/scripts/* to dist/macos/scripts and prints the count`
   - `VR-10 copy-platform-assets.mjs exits 1 naming the path when src/macos/scripts is missing`
   - `VR-11 after a build packages/platform/dist/macos/scripts holds every file of src/macos/scripts`
   - `VR-12 the bridge manifest is named vscode-bridge, main is ./dist/extension.cjs, build writes dist/extension.cjs, and package passes the D-43 vsce flags`
   - `VR-13 pnpm --filter vscode-bridge run build writes packages/vscode-bridge/dist/extension.cjs`
   - `VR-14 pnpm --filter vscode-bridge run package writes packages/vscode-bridge/dist/vscode-bridge-1.0.0.vsix, a zip that lists extension/dist/extension.cjs`
   - `VR-15 in every vitest project @mc/platform/layout resolves through the alias to packages/platform/src/layout.ts while @mc/platform still resolves to src/index.ts`
   - `VR-16 vitest.workspace.ts defines a packaging project over packaging-test/**/*.test.mjs with testTimeout 600000, and no other project allows an empty file set`

   How to assert, where it is not obvious:
   - VR-04: snapshot every file's text, run `set 1.2.3`, then expect each new text to equal
     the old text with `"version": "1.0.0"` replaced by `"version": "1.2.3"` (`String.replace`), then run `check` and expect exit 0.
   - VR-07: `createRequire(path.join(ROOT, "package.json")).resolve("esbuild")` does not throw,
     and `devDependencies.esbuild` in the root manifest is a string.
   - VR-09: temp dir with `src/macos/scripts/a.js` and `src/macos/scripts/b.applescript`, run the
     script with that dir as `argv[2]`, expect both under `dist/macos/scripts/` with equal content, and stdout containing `copied 2 files to`.
   - VR-11: `readdirSync(src/macos/scripts).sort()` equals `readdirSync(dist/macos/scripts).sort()` and is non-empty.
   - VR-13: run through `pnpm`, then `existsSync` of the output.
   - VR-15, VR-16: `const projects = (await import("../../vitest.workspace.ts")).default` (vitest loads TypeScript;

     Write a helper `resolveAlias(alias, spec)` that returns the `replacement` of the first entry whose
     `find` matches: for a RegExp `find.test(spec)`, for a string `spec === find || spec.startsWith(find + "/")`.

     to equal `path.join(ROOT, "packages", "platform", "src", "index.ts")`

     VR-16: the project whose `test.name` is `packaging` has `test.include` equal to
     `["packaging-test/**/*.test.mjs"]`, `test.testTimeout` 600000 and `test.passWithNoTests` true;
