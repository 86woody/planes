# T002 checkpoint: `@mc/contracts`

Branch `task/T002-contracts`, built on `integration`. Host `dev-pc`.

## What works

- `schemas/session|ingest|api|config.schema.json` are byte-identical copies of `docs/contracts/` (CT-02).
- `schemas/bridge.schema.json` transcribed from `vscode-bridge.md` sections 2-3: `$defs.BridgeClientMessage` (oneOf hello/terminals/windowState/result), `$defs.BridgeServerMessage` (oneOf welcome/focusTerminal/focusAgentPanel), every object `additionalProperties: false`, every field required.
- `scripts/generate.mjs` (`pnpm --filter @mc/contracts run generate`, or `node scripts/generate.mjs [outDir]`) emits `src/generated/{session,ingest,api,config,bridge}.ts` via `json-schema-to-typescript`. Sibling refs are served by a custom `$refOptions.resolve.file` plugin from `schemas/`.
- `src/index.ts` re-exports the README names. `Config` is `DeepRequired<ConfigFile>`, written in `index.ts`. `ConfigFile` is the generated type as is.
- `src/validate.ts`: one shared `Ajv2020` (`allErrors`, `strict: false`, ajv-formats, all five schemas) and a second instance with `useDefaults` for `validateConfig`. The config path works on a structured copy so the caller's object is not mutated. Errors are `"<instancePath> <message>"`.
- Fixtures: 12 valid ingest envelopes, 3 invalid (`invalid-extra-env`, `invalid-tool-input`, `invalid-version`, derived from `cc-post-tool`), 4 raw Claude Code hook inputs in `fixtures/ingest/raw/`, 8 session fixtures in `fixtures/sessions/<state>.json`.
- `contracts.lock.json` holds the SHA-256 of the five schema files.
- `test/contracts.test.ts` has CT-01 to CT-08 with the exact titles from the task.
- `pnpm task:check T002` prints `TASK T002 PASS 8/8`. `pnpm -w run typecheck` and `pnpm -w run lint` exit 0.

## Which generator path was needed

Plain path for every schema. The plain compile of `api.schema.json` and `bridge.schema.json` emitted every `$defs` type, so the anyOf-root fallback was not used. Those two plain outputs also carry a root alias (`export interface DaemonApi` / `DaemonBridge` with `[k: string]: unknown`). It is harmless and not re-exported by `index.ts`. The fallback is still in `generate.mjs` for a future schema that loses its `$defs`.

## What does not work / not done

- The `raw/cc-*.json` hook inputs were written from the hook field list in `ingest.md` section 4, not copied from `code.claude.com/docs/en/hooks`. The task said "copied from the examples", but this builder had no docs access under its read list. The four files cover SessionStart, UserPromptSubmit, Notification (permission_prompt) and PermissionRequest with `tool_input` added. Nothing in the tests depends on their exact wording.
- `docs/contracts/api.schema.json` refers to `RestoreResponse` and `StateResponse`, which copy `Session` and `FocusResult` into `api.ts`. Those duplicates are not re-exported, so no name collision.

## Surprises

- Under `module: NodeNext`, the default import of `ajv/dist/2020.js` types as a namespace. The fix is the named import `{ Ajv2020 }`. For `ajv-formats` the default import is the namespace too, so the code takes `.default`. Both work at runtime.
- `structuredClone` is not a known global for the `.mjs` lint config. `generate.mjs` uses a JSON round-trip instead.
- Root errors from Ajv have an empty `instancePath`, so their error string starts with a space (`" must NOT have additional properties"`). That follows the spec's literal format. Nested errors read `"/ui must NOT ..."`, which CT-07 checks.
- `test/contracts.test.ts` imports `generate.mjs` with a `@ts-expect-error` because the file has no type declarations. The tests are not in the typecheck include set.
