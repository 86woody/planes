## What works

- `e2e/support/daemon.ts`: builds once per Playwright process (`pnpm -r build`), starts the
  daemon per test with a fresh temp `MC_HOME`, `MC_PORT=0`, `MC_PLATFORM=fake`, `MC_TEST=1`;
  reads port and token; kills it in teardown. `restart()` reuses the port (CARD-04).
- `e2e/support/events.ts`: `Mc.send()` posts a Claude Code `IngestEnvelope` with bearer auth.
  The agent pid is the runner's own pid with its real start time (FILETIME via PowerShell on
  Windows), so the liveness sweeper keeps sessions alive (D-29). `fakeCalls()`,
  `countCalls()`, `setForeground()`, `pairCode()`, `seedBoard()` (one session per DESIGN.md 4
  row; the lost row is 13 h old on the real clock), and the temp project repo.
- `e2e/support/page.ts`: `openPaired()`, `cardFor()`, `showSplashdown()`.
- Playwright Chromium was missing; `pnpm exec playwright install chromium` ran (no deps).

## Surprises

- Ended and lost cards sit in the collapsed SPLASHDOWN section, so they are not in the DOM
  until it is expanded (`showSplashdown`).
- The daemon prunes non-live sessions whose `updatedAt` is older than 24 h, and marks an
  agentless session lost after 12 h. The lost row is therefore seeded 13 h before the real
  clock. Seeding it from the frozen 2026-11-08 date made it vanish (pruned).
- Chromium reports `linear` as the keyframe easing for `steps(1)` CSS animations. DS-04 reads
  `getComputedStyle(target).animationTimingFunction` instead.
- DS-01 compares canonical token values (leading zero added, seconds to ms). tokens.css
  spells `.08em`, `.12em`, `.12s`, `.2s`; equal values pass, but the strings are not verbatim
  with DESIGN.md 1.
- DS-08 pins event times to the frozen clock (`sentAt`), so elapsed and HOLD times are fixed.
