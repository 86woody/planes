## Interpretation choices (spec was silent or ambiguous)
- Usage fields are read from `d.usage` for `session.usage_record` and from `d` for `assistant.usage`. `model`, `initiator` and `maxPromptTokens` fall back to the event `data` when absent from the usage object.
- `model` keeps the previous value when a call has no model. `model.call_failure` does not change `calls.total` or the top-level `model`.
- `rate_limit` is matched by the exact type `rate_limit`, as written in the spec.
- `totalNanoAiu` and `currentTokens` are read from `d` directly.
- `tokenRate` keeps every call's (time, tokens) pair, so calls dropped from `recentCalls` still count. The list grows with the session's call count.
- `tools` is capped at 50 by most recent use, then sorted by runs desc and name. The spec's "newest 50" was ambiguous; this is my reading.
- A line with a missing or invalid `timestamp` uses the newest timestamp seen (or 0). It does not change `updatedAt`.
- `updatedAt` uses event timestamps only. OTel times are not parsed, since their format is not in the spec.
- `permission.requested` and `user_input.requested` with no `requestId` still count as requested. They cannot be matched on completion, so they stay pending.
- Event-line sources are recorded only for lines that parse and have a string `type`. Known-ignored events still count as events.

## Surprises
- The generated `Telemetry` type uses fixed-length tuple types for `maxItems` arrays (`subagents`, `tools`, `recentCalls`). Dynamic arrays need a cast at the snapshot boundary.
- `@mc/core` lint bans `node:*` imports everywhere under `packages/core/**`, tests included.
- `packages/core/tsconfig.json` includes only `src`, so `tsc` does not typecheck the test file. Vitest and ESLint do.
