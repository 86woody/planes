# T013: Process utilities (ancestry, liveness, tty)

Milestone M1 · Wave 1 · Depends on: M0 · Runs on: any OS (tests run everywhere with fixtures; the live test runs on the current OS)

## Goal

Cross-platform process inspection used by the hook (fingerprint) and the platform
adapters (liveness): parent chain with names and start times, alive-with-start-time,
command line, controlling tty.

## Codes against

`docs/contracts/ingest.md` section 3, `docs/platforms/windows.md` 2.3,
`docs/platforms/macos.md` 2 (last bullet), `docs/platforms/linux.md` 2.3,
`internal.md` section 4 (`process/index.ts` exports).

## Files

`packages/platform/src/process/{index,windows,posix,parse}.ts`,
`packages/platform/test/process.test.ts`, `packages/platform/test/fixtures/process/**`,
`docs/checkpoints/T013.md`.

Everything else in `packages/platform` (`windows/win32.ts` belongs to T040: declare the

## Steps

1. `parse.ts` (pure, testable everywhere): `parseLinuxStat(text) -> {pid, ppid, startTime, comm}`
   (comm is between the first `(` and the **last** `)`; fields after that are space
   separated, ppid is field 4, starttime field 22, both counted from 1 over the whole
   line); `parsePsLstart(output) -> Map<pid, {ppid, startTime, name}>` for
   `ps -A -o pid=,ppid=,lstart=,comm=` (lstart = 24 chars after the ppid column and one
   space; name = basename of the rest, trimmed).
2. `windows.ts`: koffi bindings `CreateToolhelp32Snapshot`, `Process32FirstW`,
   `Process32NextW` (`PROCESSENTRY32W` struct: dwSize, cntUsage, th32ProcessID,
   th32DefaultHeapID (uintptr), th32ModuleID, cntThreads, th32ParentProcessID,
   pcPriClassBase, dwFlags, szExeFile[260] wchar), `OpenProcess`, `GetProcessTimes`,
   `GetExitCodeProcess`, `CloseHandle`. Command line on Windows: run
   `powershell.exe -NoProfile -Command "(Get-CimInstance Win32_Process -Filter 'ProcessId=<pid>').CommandLine"`
   (slow path, 0.5-1.5 s; the hook never calls it since ingest.md 3 reads no command
   lines; it stays for `mc doctor` and future adapters). `ttyOf` returns null.
3. `posix.ts`: Linux via `/proc`; macOS via `ps` (one call per `ancestry`); `commandLine`
   via `/proc/<pid>/cmdline` (NUL to space) or `ps -o command= -p <pid>`; `ttyOf` via
   `ps -o tty= -p <pid>` -> `/dev/<tty>`, `??` or `?` -> null.
4. `index.ts`: dispatch by `process.platform`, loading `./windows.js` or `./posix.js` with a
   dynamic `import()` on first use (so koffi is never loaded on macOS or Linux). `ancestry(fromPid)` returns
   `[info(fromPid), info(parent), ...]` (the hook calls `ancestry(process.ppid)`). Implement the stop rules of ingest.md 3
   (max 16, stop at pid 0/1 and names `system`, `launchd`, `systemd`, `init`).
5. Tests, titles exactly:
   - `PR-01 parseLinuxStat handles a comm containing ") ("`
   - `PR-02 parseLinuxStat extracts ppid and starttime`
   - `PR-03 parsePsLstart parses the recorded fixture` (`fixtures/process/ps-lstart.txt`, write it from a real macOS format sample: `  501     1 Sun Nov  8 20:15:03 2026     /usr/libexec/foo`)
   - `PR-04 ancestry of a spawned child starts with the child then this process` (live,
     current OS: spawn `node -e "setTimeout(()=>{},3000)"`, call `ancestry(child.pid)`:
     entry 0 is the child's pid with name `node`, entry 1 is `process.pid`; kill the child)
   - `PR-05 processAlive is true for process.pid with its own start time`
   - `PR-06 processAlive is false with a wrong start time`
   - `PR-07 processAlive is false after a child exits`
   - `PR-08 ancestry stops at 16 entries` (unit, with an injected fake process table)

   For PR-08 export `walkAncestry(start: number, lookup: (pid) => ProcessInfo & {ppid: number} | undefined): ProcessInfo[]`
   from `parse.ts` and use it in both OS implementations.
