# T097: `mc init --agents` accepts the list as separate words (PowerShell)

Milestone M5 · Wave 8h · Depends on: T092 · Runs on: any OS

## Goal

In PowerShell, an unquoted `claude-code,copilot` is an array literal, so
`mc init --agents claude-code,copilot` reaches node as `--agents claude-code copilot`.
`parseInitArgs` accepts only exactly two arguments, so it prints the usage line and exits 2.
The fresh-machine run in Windows Sandbox (FM-06, 2026-11-15) hit this. After this task, every
argument after `--agents` up to the next one starting with `--` is part of the list, and
each may itself contain commas.

## Steps

1. In `parseInitArgs`, accept these forms (unknown agents and empty lists stay errors, as
   today):
   - `--agents a,b`;
   - `--agents a b`, any number of words;
   - `--agents a, b`, a comma attached to the end of a word;
   - `--agents=a,b`.

   Collect every argument after `--agents` up to the next argument that starts with `--`,
   or the end. Split each on commas, trim, drop empty pieces, and de-duplicate, keeping
   menu order as today. Any other argument is still a usage error, exit 2. Keep the USAGE
   text.
2. Add the test `IN-13 --agents accepts the list as separate words, the way PowerShell passes a,b`.
   It calls `parseInitArgs` with `["--agents", "claude-code", "copilot"]`,
   `["--agents", "claude-code,", "copilot"]` and `["--agents", "copilot,claude-code"]`, and
   expects each to select the same agents. It also runs `init` through the same
   sandbox/injected path IN-03 uses with `["--agents", "claude-code", "copilot"]`, and
   expects exit 0 and a `claude-code` entry in the manifest. Finally it expects
   `["--agents", "claude-code", "--bogus"]` to return the usage error.
