# T091: Packaging docs: user guide, PRD non-goal, fresh-machine record, handoff

Milestone M5 · Wave 8i · Depends on: T090 · Runs on: any OS (orchestrator, not a builder)

## Goal

The docs describe the packaged install as the primary path and the clone as the
developer path. The fresh-machine proof is recorded. HANDOFF.md blocker 5 is closed or
names exactly what is still open. Builders cannot do this task: everything it touches is
under `docs/` or is `HANDOFF.md`, which only the orchestrator writes.

## Codes against

`docs/PACKAGING.md` 5 and 6, `docs/DECISIONS.md` D-39..D-46, `RELEASE-NOTES.md` (T088),
the FM-01..FM-08 checklist in `docs/TEST-PLAN.md` 6.

## Files

`docs/USER-GUIDE.md`, `docs/PRD.md`, `docs/validation/fresh-machine-windows-<date>.md`,
`HANDOFF.md`, `docs/checkpoints/T091.md`.

## Do not touch

Product code, tests, `scripts/**`, other docs.

## Steps

1. `docs/USER-GUIDE.md` section 2: make the three-command flow from PACKAGING.md 5
   (`npm i -g ./mission-control-desktop-<v>.tgz`, `mc init`, `mc launch`; D-46) the first
   install path ("Install the package"). Describe the `mc init` prompt (Copilot
   pre-selected, Enter accepts, `--agents copilot,claude-code,codex` skips it, rerun to
   repair) and what it also installs (uri-handler, vscode). Put `mc start`, `mc open` and
   `mc install <target>` (including `shell`, `autostart`, and the per-agent targets) in a
   "Reference: individual commands" subsection, not in the first-run flow. Move the clone flow (`pnpm install`,
   `pnpm build`, `pnpm mc ...`) under a "From a clone (developers)" subsection. In the
   requirements, pnpm becomes "clone only". Replace `pnpm mc` with `mc` in every
   user-facing line (`grep -n "pnpm mc" docs/USER-GUIDE.md`; today in sections 2, 4, 6 and 9). Add
   "Upgrade" with the PACKAGING.md 5 upgrade (`mc launch`) and Node-switch text.
2. `docs/USER-GUIDE.md` section 9: add the full uninstall sequence from PACKAGING.md 5,
   including `mc uninstall` for each optional target and `npm rm -g mission-control-desktop`.
   Add `stateDir/bin/` to the file-locations table.
3. `docs/PRD.md` section 5: replace the packaging bullet with "SEA single binaries,
   signing and notarization, auto-update and package-manager listings (D-45). v1 ships
   an npm tarball, `mission-control-desktop` (D-39)."
4. Woody runs T090's manual checklist in Windows Sandbox. Record
   `docs/validation/fresh-machine-windows-<YYYY-MM-DD>.md` with one `ID | PASS/FAIL | note`
   row per FM-01..FM-08, the tarball file name, its version and the sandbox's Windows
   build.
5. `HANDOFF.md` blocker 5: replace the "Scope to settle" text with
   "Plan: D-39..D-46, docs/PACKAGING.md, T080-T092 (wave 8)". When T080-T090 are merged,
   the `package` stage passes on Windows and Linux, and every FM row passes, mark it DONE
   with the validation file name.
