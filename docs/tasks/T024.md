# T024: FocusService and target resolution

Milestone M1 · Wave 2 · Depends on: T003, T012 · Runs on: any OS

## Goal

Decide, for each session, which window (and tab or VS Code terminal) RESTORE should act
on and what capability the card shows; then perform the restore through the platform
adapter and the VS Code bridge, and record the result.

## Steps

1. `resolve(id)`:
   - No record or no origin -> nothing.
   - Session ended or lost -> `setRestore(id, host, {capability: "none", reason: "process_ended", lastResult}, null)`.
   - `host = classifyHost(origin)` (from `@mc/core`).
   - `vscode-terminal` / `vscode-extension`: `bridges.findForSession(origin, host.kind)`.
     a. Found and `window.nativeWindow` set -> target `{window: nativeWindow, inner: null, capability: "full", reason: null}`.
     b. Found, unbound: title fallback (step 3) with `workspaceName`; unique match -> bind it
        (`bridges.rebind(windowId, w)`) and use (a); else capability `none`, reason `vscode_window_unbound`.
     c. Not found: title fallback with the session's `project`; unique -> capability `window`,
        reason `vscode_bridge_missing`; else `none`, `vscode_bridge_missing`.
     Keep `{bridgeWindowId, terminalId}` alongside the target in a private
     `Map<SessionId, {windowId: string; terminalId: string | null}>`.
   - Anything else: `platform.resolveTarget(origin, host)`.
   - Write with `sessions.setRestore(id, host, {capability, reason, lastResult: <unchanged>}, target)`.
2. `restore(id, source)`: never throws.
   - Unknown id -> `{failed, not_found, "unknown session"}` (no apply).
   - No target yet -> `resolve(id)` first.
   - Capability `none` -> `{failed, unsupported, detail: <reason>}`.
   - `opts = {maximize: config.restore.maximize, foregroundStrategy: config.restore.windowsForegroundStrategy, fromActivation: source === "notification"}`.
   - VS Code target: `platform.focus(target, opts)`, then if a bridge entry exists,
     `bridges.request(windowId, terminalId ? {type: "focusTerminal", terminalId, maximizePanel: false} : {type: "focusAgentPanel", adapter: session.adapter})`.
     Combine per vscode-bridge.md 5: OS `focused` + bridge ok -> `ok/focused`; OS
     `focused` + bridge failed -> `partial/focused_window_only` with the bridge detail;
     OS `flashed` -> `partial/flashed`; OS `not_found` -> unbind (`rebind(windowId, null)`),
     `resolve`, retry once.
   - Other targets: `platform.focus(target, opts)`; on `not_found`, `resolve` and retry once.
   - Finally `sessions.apply({kind: "restore_result", sessionId: id, result, ackOnRestore: config.restore.ackOnRestore})`.
3. Title fallback: `platform.listWindows(VSCODE_NAMES)`; matches = windows whose title
   contains ` - <name> - ` or ends with ` - <name>` or equals `<name>`; unique match only.
4. Serialize per session: a second `restore(id)` while one is running awaits the first
   and returns its result.
5. Tests, titles exactly:
   - `FO-01 a windows-terminal session resolves through platform.resolveTarget and writes capability full`
   - `FO-02 vscode-terminal with a bound bridge window resolves full and remembers the terminalId`
   - `FO-03 vscode-terminal with an unbound bridge and a unique title match binds the window`
   - `FO-04 vscode-terminal without a bridge and a unique title match is window/vscode_bridge_missing`
   - `FO-05 ended session resolves to none/process_ended`
   - `FO-06 restore of a full target calls platform.focus with the config options and applies restore_result`
   - `FO-07 VS Code restore sends focusTerminal after the OS focus; bridge failure yields focused_window_only`
   - `FO-08 not_found triggers one re-resolve and one retry`
   - `FO-09 capability none returns failed/unsupported without calling platform.focus`
   - `FO-10 concurrent restores of one session run platform.focus once`
