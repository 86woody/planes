# T023: Notifier

Milestone M1 · Wave 2 · Depends on: T011, T003 · Runs on: any OS

## Goal

Turn session changes into OS notifications through the policy: per-session last-sent
memory, foreground suppression, coalescing, renotify ticks, withdrawal when attention
clears, click handling, and the WebSocket mirror.

## Codes against

`attention.md` section 6 (`decide`, `decideRenotify`, `Coalescer`), `internal.md`
(`Notifier`, `createNotifier`, `DaemonDeps.broadcast`), `platform-adapter.md`
(`notify`, `withdraw`, `foregroundWindow`), `api.md` section 5 (`notify` message).

## Files

`packages/daemon/src/notifier.ts`, `packages/daemon/test/notifier.test.ts`,
`docs/checkpoints/T023.md`.

## Do not touch

Everything else. Tests use a minimal in-memory `SessionService` double (only
`onChange`, `get`, `list`), a `FakePlatform`, and a fake `FocusService`.

## Steps

1. `start()`: subscribe to `sessions.onChange`. For each `upsert`:
   - `isForeground`: `platform.foregroundWindow()` compared with the record's
     `target.window.handle` (false when either is null).
   - `localMinutes` from `new Date(clock.now())` local hours*60+minutes.
   - `decide(prev, next, ctx)`; on `send`, pass through the `Coalescer`; for each
     notification it releases: `platform.notify(n, onClick)`, remember
     `{handle, reason, at}` per session, `broadcast({type: "notify", notification: n})`,
     and, when `handle` is not null and `n.sessionId` is not null,
     `sessions.apply({kind: "notified", sessionId, at: clock.now()})` (attention.md SM-38
     increments `stats.notifications`). Ignore the upsert this causes (prev and next have
     the same attention, so `decide` returns `no_change` anyway).
   - If `next.attention.active` is false and a handle exists for the session:
     `platform.withdraw(handle)` and forget it.
2. `onClick(sessionId)`: `null` -> nothing (summary); else `focus.restore(sessionId, "notification")`;
   if the result is `failed`, `broadcast({type: "highlight", sessionId})`.
3. Renotify: every 30 s (`setInterval`), for each session with active attention,
   `decideRenotify`; send as above (not through the coalescer).
4. Coalescer flush: a 1 s interval calling `flush(now)` and sending what it returns.
5. `test()`: send `{sessionId: null, title: "MISSION CONTROL · COMMS CHECK", body: "Notifications are GO", urgency: "normal", tag: "test"}`
   directly; return `{sent: handle !== null, backend: (await platform.capabilities()).notify ? "os" : "none"}`.
6. `stop()`: clear intervals, unsubscribe.
7. Tests, titles exactly:
   - `NT-01 attention entry sends one platform.notify, one broadcast notify and one notified apply`
   - `NT-02 the same attention updated again sends nothing`
   - `NT-03 foreground session window suppresses the notification`
   - `NT-04 attention clearing withdraws the shown notification`
   - `NT-05 click calls focus.restore with source notification; failed result broadcasts highlight`
   - `NT-06 renotify after renotifyMinutes for unacknowledged attention` (fake timers)
   - `NT-07 a burst of 5 attentions sends 3 then one summary after 5 s` (fake timers)
   - `NT-08 test() sends the COMMS CHECK notification`
