# T086: `mc install vscode` from the shipped .vsix

Milestone M5 · Wave 8d · Depends on: T080, T081, T083 · Runs on: any OS

## Goal

In package mode (no clone, no pnpm) `mc install vscode` installs the `.vsix` that ships in
the npm package into every editor CLI on PATH. Clone mode keeps today's build flow. The
`.vsix` holds exactly three files.

## Codes against

`docs/PACKAGING.md` 1, 3 (the `Layout` interface, `vsixPath`) and 8, `docs/DECISIONS.md`
D-30 and D-43, `docs/tasks/T051.md` step 6 (the clone flow that stays), PRD AC-15.

## Files

`packages/cli/src/installers/vscode.ts`, `packages/vscode-bridge/.vscodeignore`,
`packages/cli/test/install-vscode-package.test.ts`, `docs/checkpoints/T086.md`. One extra
edit (PACKAGING.md 8, after T083 merged): only the two `"@mc/vscode-bridge"` strings inside test
`IX-08` of `packages/cli/test/install-other.test.ts` (step 8).

## Do not touch

Every other file. In particular `packages/cli/src/installers/manifest.ts` and the rest of
`packages/cli/test/install-other.test.ts` belong to T083, `packages/vscode-bridge/package.json`
belongs to T080 (it is already renamed to `vscode-bridge` with `main` `./dist/extension.cjs`
when you start). If the `ctx.layout` field described in step 1 does not exist in
`manifest.ts`, or `packages/vscode-bridge/package.json` still says `@mc/vscode-bridge`, stop
and write `CR:` in your checkpoint.

## Steps

1. Assumption you rely on (T083 owns `manifest.ts` and adds it): `CtxInput` and `Ctx` carry
   `layout: Layout`, where `Layout` is `import type { Layout } from "@mc/platform/layout"`
   (PACKAGING.md 3). `makeCtx` defaults it to `layout()` and a test injects it through the
   `input` argument (`{ ...sb.input, layout }`). In `vscode.ts` use a type-only import and
   read `ctx.layout`; never import the `layout()` function there.
2. In `packages/cli/src/installers/vscode.ts`:
   - change `const BRIDGE = "@mc/vscode-bridge";` to `const BRIDGE = "vscode-bridge";`;
   - add `const EXTENSION_ID = "woody.vscode-bridge";`;
   - `bridgeExtensionId(ctx)`: when `ctx.layout.mode === "package"` return `EXTENSION_ID`
     without reading any file (a package install has no `packages/vscode-bridge/`); otherwise
     keep today's code (it already strips a scope, so it returns `woody.vscode-bridge`).
3. In `installVscode(ctx)`, before the existing code add the package branch, taken when
   `ctx.layout.vsixPath !== null`:
   - `const vsix = ctx.layout.vsixPath;`
   - if `!existsSync(vsix)`: `ctx.err(\`vscode: packaged extension missing: ${vsix}\n\`)` and
     `return 1`. Run nothing.
   - write the manifest entry `{ vsix, installedWith: [], extensionId: EXTENSION_ID, shipped: true }`
     under `vscode` (same read/save helpers as today);
   - loop `EDITORS` (`code`, `code-insiders`, `cursor`, in that order): skip when
     `!(await ctx.onPath(editor))`, else `ctx.run(editor, ["--install-extension", vsix], LONG)`.
     Reuse the existing per-editor handling unchanged (record each success at once into
     `installedWith`, report a failure, exit 1 if any failed). Best done by moving that loop
     into a local helper `installInto(ctx, vsix)` used by both branches;
   - success text: `vscode: installed into <list>\n`, or
     `vscode: no editor CLI on PATH; <vsix> is the extension file\n` when none, exit 0.
   - no `pnpm`, no `vsce`, no build in this branch.
4. Clone mode (`ctx.layout.vsixPath === null`): the existing flow unchanged except that the
   filter constant is now `vscode-bridge`. The manifest entry there stays without `shipped`.
5. `uninstallVscode`: keep as is, except `rmSync(entry.vsix)` runs only when
   `entry.shipped !== true` (the shipped file lives inside the npm package and must survive).
6. Create `packages/vscode-bridge/.vscodeignore` with exactly these four lines (D-43):
   ```
   **
   !dist/extension.cjs
   !package.json
   !README.md
   ```
7. Tests in `packages/cli/test/install-vscode-package.test.ts` (vitest; import `sandbox`, `REPO`
   from `./fixtures/install-sandbox.js`, `run as install` from `../src/commands/install.js`,
   `run as uninstall` from `../src/commands/uninstall.js`). Use temp dirs; the runner records
   calls and never executes. Import `layoutFor` from `@mc/platform/layout`
   (the vitest alias exists since T080) and build the layouts with it:
   - `pkgLayout(root)`: `layoutFor("package", root, "1.0.0")` (its `vsixPath` is `<root>/vscode-bridge.vsix`, so use `layout.vsixPath` rather than recomputing it);
   - `cloneLayout()`: `layoutFor("clone", REPO, "1.0.0")` (its `vsixPath` is `null`).
   - package-mode tests `mkdtempSync` a package dir and write a small `vscode-bridge.vsix`
     file (any bytes) into it, then call `install(["vscode"], sb.io, { ...sb.input, layout })`.
   Titles exactly:
   - `VX-01 package mode installs the shipped vsix with code only: no pnpm, no vsce, no build`
   - `VX-02 package mode installs into code, code-insiders and cursor in that order, only those on PATH`
   - `VX-03 package mode with the vsix file missing exits 1 and runs nothing`
   - `VX-04 package mode with no editor on PATH exits 0 and runs nothing`
   - `VX-05 package mode uninstall removes the extension from each editor and keeps the shipped vsix file`
   - `VX-06 clone mode still builds with the vscode-bridge filter and never uses the @mc/ scope`
   - `VX-07 vsce ls lists exactly dist/extension.cjs, package.json and README.md`
   - `VX-08 the bridge manifest is named vscode-bridge and main is dist/extension.cjs`

   Assertions:
   - VX-01: `sb.calls` equals `[["code", "--install-extension", vsix]]` with `onPath: ["code"]`
     and `platform: "win32"`; exit 0; the manifest (`<sb.stateDir>/install-manifest.json`)
     `.vscode` has `installedWith` `["code"]`, `extensionId` `"woody.vscode-bridge"`, `shipped` `true`.
   - VX-02: `onPath: ["cursor","code","code-insiders"]` gives calls in the order code,
     code-insiders, cursor; with `onPath: ["code-insiders"]` only that one.
   - VX-03: no vsix file written: exit 1, `sb.calls` equals `[]`, `sb.errs.join("")` contains
     `vscode: packaged extension missing`.
   - VX-04: `onPath: []`: exit 0, `sb.calls` equals `[]`, `sb.out.join("")` contains `no editor CLI on PATH`.
   - VX-05: install then `uninstall(["vscode"], sb.io, { ...sb.input, layout })`: calls include
     `["code", "--uninstall-extension", "woody.vscode-bridge"]`, `existsSync(vsix)` is `true`, and the
     manifest has no `vscode` key.
   - VX-06: `{ ...sb.input, layout: cloneLayout() }`, `onPath: ["code"]`: `sb.calls[0]` equals
     `["pnpm", "--dir", REPO, "--filter", "vscode-bridge", "build"]`, and no call contains `@mc/vscode-bridge`.
   - VX-07: first run `pnpm --filter vscode-bridge build` from `REPO` with `spawnSync` (so
     `dist/extension.cjs` exists), then `pnpm exec vsce ls --no-dependencies` with
     `cwd: <REPO>/packages/vscode-bridge`, `encoding: "utf8"`, `shell: process.platform === "win32"`,
     `input: ""`. Take stdout lines, trim, drop empty ones, turn `\` into `/`, sort. Expect exactly
     `["README.md", "dist/extension.cjs", "package.json"]`. If `vsce ls` prints any additional
     path, do not widen the list: write `CR:` in your checkpoint (D-43 says three files).
     Pass `60_000` as the third argument of `it(...)` (build plus vsce).
   - VX-08: read `<REPO>/packages/vscode-bridge/package.json`; `name` is `"vscode-bridge"`, `main`
     is `"./dist/extension.cjs"`.
   Use `afterEach` to call `cleanup()` of every sandbox and `rmSync` every temp package dir.

8. In `packages/cli/test/install-other.test.ts`, test `IX-08`, change the two occurrences of
