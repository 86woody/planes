# T081: Layout module

Milestone M5 · Wave 8b · Depends on: T080 · Runs on: any OS

## Goal

`packages/platform/src/layout.ts`: the one module that knows where every shipped file
lives, in a clone and in an installed package, exactly as frozen in `docs/PACKAGING.md`
section 3. Nothing calls it yet (T082 and T083 do).

## Codes against

`docs/PACKAGING.md` section 3 (interface and both columns of the table), `docs/DECISIONS.md` D-40.

## Files

`packages/platform/src/layout.ts`, `packages/platform/test/layout.test.ts`,
`docs/checkpoints/T081.md`.

## Do not touch

Every other file. In particular `packages/platform/src/index.ts` (do not re-export layout
from it; consumers use the subpath `@mc/platform/layout`, which T080 added to
`packages/platform/package.json`), `packages/platform/src/types.ts`, and every platform
adapter file (T082 rewires them).

## Steps

1. Create `packages/platform/src/layout.ts`. It imports only `node:` builtins
   (`node:fs` `readFileSync`, `node:path`, `node:url`), no relative imports. It exports exactly
   the interface of PACKAGING.md 3: `LayoutMode`, `Layout`, `layoutFor`, `layout`. Declare
   `declare const __MC_PACKAGE__: { version: string } | undefined;` at the top.
2. `layoutFor(mode, root, version)` is pure (no fs, no globals). It sets `root` to
   `path.resolve(root)` and builds every other field with `path.join(root, ...segments)`
   using the table below (`/` here only separates the segments you pass to `join`).
   `vsixPath` is `null` in clone mode.

   | Field | clone | package |
   |---|---|---|
   | `mcJs` | `packages/cli/dist/mc.js` | `dist/mc.js` |
   | `daemonJs` | `packages/daemon/dist/bin.js` | `dist/daemon.js` |
   | `hookJs` | `packages/hook/dist/mc-hook.js` | `dist/mc-hook.js` |
   | `uiDir` | `packages/ui/dist` | `ui` |
   | `psDir` | `packages/platform/src/windows/ps` | `ps` |
   | `macosScriptsDir` | `packages/platform/dist/macos/scripts` | `macos-scripts` |
   | `iconPath` | `packages/platform/assets/icon-256.png` | `assets/icon-256.png` |
   | `shellAssetsDir` | `packages/cli/assets/shell` | `shell` |
   | `schemasDir` | `packages/contracts/schemas` | `schemas` |
   | `vsixPath` | `null` | `vscode-bridge.vsix` |

3. `layout()` is memoised (a module-level variable; the second call returns the same object).
   `typeof __MC_PACKAGE__ !== "undefined"` selects package mode:
   - package: `root = path.resolve(fileURLToPath(new URL("..", import.meta.url)))` and
     `version = __MC_PACKAGE__.version`.
   - clone: `root = path.resolve(fileURLToPath(new URL("../../..", import.meta.url)))` (from
     `packages/platform/dist/layout.js`, and also from `packages/platform/src/layout.ts`, this
     is the repo root) and `version` = the `version` string of `<root>/package.json`, read with
     `readFileSync` on the first call.

   `fileURLToPath` of a directory URL ends with a separator, so the `path.resolve` is required.
4. Tests in `packages/platform/test/layout.test.ts` (vitest project `platform`). Import
   `layoutFor` and `layout` from `../src/layout.js`. Use
   `ROOT = path.resolve(path.dirname(fileURLToPath(import.meta.url)), "../../..")` for the repo
   root and `R = path.resolve(os.tmpdir(), "mc-layout-root")` as the fake root for `layoutFor`.
   For the table tests, write the expected segments as arrays in the test and compare with
   `path.join(R, ...segments)`. Titles exactly:
   - `LY-01 layoutFor clone returns every row of the clone column and vsixPath null`
   - `LY-02 layoutFor package returns every row of the package column and vsixPath under root`
   - `LY-03 layoutFor echoes mode and version and stores root resolved`
   - `LY-04 every path field of both modes is absolute and starts with root`
   - `LY-05 layout() in the test run is clone mode with root equal to the repo root`
   - `LY-06 layout().version equals the version in the root package.json`
   - `LY-07 layout() is memoised: two calls return the same object`
   - `LY-08 clone-mode source files exist: the three ps1 files, the icon, the three shell snippets, a schema and a macOS script`
   - `LY-09 clone-mode built files exist: mc.js, bin.js, mc-hook.js and the UI index.html`
   - `LY-10 with __MC_PACKAGE__ stubbed, a fresh layout() is package mode rooted at the module parent with that version`
   - `LY-11 layout.ts imports only node: builtins`
   - `LY-12 the build emits dist/layout.js and dist/layout.d.ts`

   How to assert, where it is not obvious:
   - LY-01/LY-02: call `layoutFor("clone", R, "9.9.9")`, expect each listed field `toBe` its joined path, `vsixPath` `toBeNull()` (clone) or `path.join(R, "vscode-bridge.vsix")` (package). Cover all ten path fields (`mcJs, daemonJs, hookJs, uiDir, psDir, macosScriptsDir, iconPath, shellAssetsDir, schemasDir, vsixPath`) and `root`.
   - LY-08: `psDir` + `toast-host.ps1`, `wt-tabs.ps1`, `wt-select-tab.ps1`; `iconPath`; `shellAssetsDir` + `mc.ps1`, `mc.bash`, `mc.zsh`; `schemasDir` + `api.schema.json`; `macosScriptsDir` + `notify-osascript.applescript` (this one exists only after `pnpm -r build`, which the acceptance command runs; T080 copies it).
   - LY-09: also exists only after the build.
   - LY-10: `vi.stubGlobal("__MC_PACKAGE__", { version: "7.7.7" })`, `vi.resetModules()`, `const m = await import("../src/layout.js")`, then `m.layout()` has `mode` `"package"`, `version` `"7.7.7"`, `root` equal to `path.resolve(path.dirname(fileURLToPath(import.meta.url)), "..")` (the `packages/platform` directory), and `mcJs` equal to `path.join(root, "dist", "mc.js")`. Finish with `vi.unstubAllGlobals()` in `afterEach`.
   - LY-11: read `src/layout.ts`, collect every `from "<spec>"` and every `import("<spec>")`, expect all specs to start with `node:`.
   - LY-12: `existsSync` of `packages/platform/dist/layout.js` and `layout.d.ts`.
5. Run the acceptance command. Also run `pnpm -w run typecheck` and `pnpm -w run lint`.
